## 1. Alerts and Incidents

### Alert

An **Alert** is a single detection generated when suspicious or malicious activity is identified.

Examples:

1. Suspicious PowerShell execution
2. Impossible travel login
3. Malware detected on an endpoint

### Incident

An **Incident** is a collection of related alerts that together tell the story of an attack. Microsoft Defender XDR automatically correlates alerts from different security products into a single incident.

**Example**

Instead of four separate alerts (phishing email received, user clicked malicious link, malware executed, credential theft detected), Defender XDR groups them into one incident, for example:

> Incident: Multistage attack involving phishing and malware

> **Exam Tip:** Alert equals a single event. Incident equals a collection of related alerts that Defender XDR correlates automatically.

### SC 200 Exam Tips

* Know the exact distinction: Alert = individual detection, Incident = correlated group of alerts.
* Correlation across products (Endpoint, Office 365, Identity, Cloud Apps) is done automatically by Defender XDR, not manually by the analyst.

## 2. Why Defender XDR Groups Alerts into Incidents

Attackers rarely perform a single action. A typical attack chain may involve:

1. Initial Access
2. Execution
3. Persistence
4. Credential Access
5. Lateral Movement
6. Data Exfiltration

```text
Initial Access
     │
     ▼
Execution
     │
     ▼
Persistence
     │
     ▼
Credential Access
     │
     ▼
Lateral Movement
     │
     ▼
Data Exfiltration
```

Defender XDR combines all related activities into one incident so analysts can understand:

* Where the attack started
* The attack path
* Affected users
* Affected devices
* Mailboxes impacted
* Severity
* Scope of compromise

This gives analysts the **full attack story** instead of investigating alerts one by one.

### SC 200 Exam Tips

* Remember the attack chain stages above; incident correlation exists because a single attacker action rarely stands alone.
* An incident view should always be treated as the full story, not a single event.

## 3. The Incident Queue

The **Incident Queue** is the primary place where SOC analysts work. By default it displays incidents from the last 30 days.

Analysts use it to:

1. Review incidents
2. Prioritize work
3. Assign ownership
4. Investigate attacks
5. Resolve incidents

> **Exam Tip:** Incident Queue = the main dashboard for incident management.

### SC 200 Exam Tips

* Default retention shown in the queue: 30 days.
* Core queue actions to remember: review, prioritize, assign, investigate, resolve.

## 4. The Action Center

Use the memory trick **P H U S** to recall the four core areas of the Action Center:

| Letter | Meaning |
|---|---|
| P | Pending, actions waiting for approval |
| H | History, completed actions |
| U | Undo, reverse a remediation action |
| S | Submissions, send Email, URL, or File to Microsoft for analysis |

### SC 200 Exam Tips

* If a question mentions reversing an automated remediation, the answer involves the Undo function in the Action Center.
* Submissions is the correct answer for sending a suspicious email, URL, or file to Microsoft for review.

## 5. Advanced Hunting

**Advanced Hunting** is a query based (KQL) threat hunting tool in Microsoft Defender XDR.

It allows SOC analysts to:

1. Search raw security data
2. Investigate suspicious activity
3. Hunt for threats proactively
4. Build custom detection rules
5. Generate alerts automatically

> Think of it as KQL powered threat hunting across Microsoft Defender data.

### Why SOC Analysts Use It

Normal alerts only show what Defender already detected. Advanced Hunting helps analysts find:

| Use Case | Example |
|---|---|
| Known Threats | Find all devices infected with a named malware family such as Emotet |
| Unknown Threats | Search for PowerShell launching encoded commands |
| Threat Hunting | Find users logging in from unusual locations |
| Incident Investigation | Trace a phishing email from delivery to execution |

### Data Sources Searched

Advanced Hunting searches data across all Microsoft Defender XDR products:

| Product | Data Covered |
|---|---|
| Microsoft Defender for Endpoint | Process, file, registry, and network events on endpoints |
| Microsoft Defender for Office 365 | Email delivery, attachments, URLs |
| Microsoft Defender for Cloud Apps | Office 365 and other SaaS application activity |
| Microsoft Defender for Identity | Active Directory logons, domain controller activity, user authentication |

> **Exam Question:** Which Microsoft solutions provide data for Advanced Hunting? Answer: Defender for Endpoint, Defender for Office 365, Defender for Cloud Apps, and Defender for Identity, all four together.

### SC 200 Exam Tips

* Advanced Hunting is built on KQL and spans all four Defender XDR workloads.
* Distinguish "known threat" queries from "unknown threat" hunting queries; the exam may present a scenario and ask which hunting category it represents.

## 6. Key Advanced Hunting Tables

Memorize these tables and what each one contains.

| Table Name | Purpose / Info |
|---|---|
| AlertInfo | High level information about alerts, including severity, category, and detection source |
| AlertEvidence | Details about entities (files, processes, IPs, users, devices) associated with an alert |
| DeviceProcessEvents | Process creation and execution on devices |
| DeviceFileEvents | File creation, modification, and deletion |
| DeviceRegistryEvents | Registry entries created, modified, or deleted on endpoints |
| DeviceNetworkEvents | Network connections originating from devices |
| DeviceLogonEvents | Local and network sign ins and authentication events on devices |
| EmailEvents | Inbound and outbound email information including sender, recipient, and delivery status |
| EmailAttachmentInfo | Email attachments, used to find malicious attachments |
| EmailUrlInfo | URLs found in emails, used to hunt phishing URLs |
| IdentityLogonEvents | Active Directory and Microsoft Online authentication activity |

### Example Query

```kql
DeviceProcessEvents
| where FileName == "powershell.exe"
```

### Exam Shortcut

| Concept | Table |
|---|---|
| Process | DeviceProcessEvents |
| File | DeviceFileEvents |
| Registry | DeviceRegistryEvents |
| Network | DeviceNetworkEvents |
| Logon | DeviceLogonEvents |

> **Exam Tip:** Memorizing these five Device tables alone will help answer a large percentage of SC 200 Advanced Hunting questions.

### SC 200 Exam Tips

* Table names are case sensitive in the schema and always start with the entity type they describe (Device, Email, Identity, Alert).
* If a scenario mentions phishing, think EmailEvents, EmailAttachmentInfo, and EmailUrlInfo together.
* If a scenario mentions persistence or C2 style behavior, think DeviceRegistryEvents and DeviceNetworkEvents.

## 7. Advanced Hunting Memorization Sheet

| Concept | Value |
|---|---|
| Advanced Hunting | Query based threat hunting |
| Retention | 30 days |
| Time Zone | UTC |
| Required Custom Detection Columns | Timestamp, DeviceId, ReportId |
| Fastest Rule Frequency | Continuous, also called Near Real Time (NRT) |
| Alert Limit | 100 alerts per run |

> **Exam Tip:** Custom detection rules must return the columns Timestamp, DeviceId, and ReportId or the rule will fail to create alerts correctly. NRT is the fastest available detection frequency.

### SC 200 Exam Tips

* All Advanced Hunting timestamps are in UTC, regardless of the analyst's local time zone.
* Data retention for hunting queries is 30 days by default; this is a common exam trap versus longer Sentinel retention periods.

## 8. The Hunting Graph

The **Hunting Graph** is a visual investigation tool in Microsoft Defender XDR Advanced Hunting that shows relationships between entities involved in an attack, instead of plain table rows.

```text
User
  │
  ▼
Device
  │
  ▼
Process
  │
  ▼
File
  │
  ▼
IP Address
```

### Why It Exists

A KQL query such as the one below can return thousands of rows that are hard to read as a flat table:

```kql
DeviceProcessEvents
| where FileName == "powershell.exe"
```

The Hunting Graph turns those rows into connected nodes automatically.

### What the Graph Can Display

The graph can visualize these entity types:

1. Devices, for example WIN10 01, SERVER01
2. Users, for example Administrator, John Smith
3. Files, for example malware.exe, invoice.pdf
4. Processes, for example powershell.exe, cmd.exe
5. URLs, for example evil.com
6. IP Addresses, for example 185.220.x.x
7. Emails, for example phishing emails

### Example: Phishing Attack Investigation

```text
Email
  │
  ▼
User Clicked Link
  │
  ▼
Downloaded malware.exe
  │
  ▼
powershell.exe Launched
  │
  ▼
Connected to C2 IP
```

### SC 200 Exam Tips

* The Hunting Graph is a visualization layer on top of Advanced Hunting results, not a separate data source.
* Expect scenario questions asking which tool best shows the relationship between a user, a device, and a malicious process; the answer is the Hunting Graph.

## 9. Sign in Logs and Identity Investigation

Sign in logs record every authentication attempt against Microsoft Entra ID.

```text
User Attempts Sign In
        │
        ▼
Entra Evaluates Authentication
        │
        ▼
Conditional Access Evaluated
        │
        ▼
Result Recorded in Sign In Logs
```

Every login attempt creates an event, and sign in logs provide:

1. Date and time
2. User
3. Application
4. Status
5. Conditional Access policy applied

These are typically the first things an analyst checks during an identity related investigation.

### Investigation Scenario

Alert: Impossible Travel Detected.

> John logs in from Bangladesh, then ten minutes later logs in from Germany.

What to check in the sign in logs:

1. User
2. IP address
3. Country
4. Device
5. Authentication result
6. Conditional Access result

This helps determine whether the activity is malicious or explainable, for example by a VPN.

### Where to Query Sign In Data

| Location | Table / Schema Name |
|---|---|
| Defender XDR Advanced Hunting | AADSignInEventsBeta |
| Microsoft Entra ID Log Analytics | SigninLogs |

### SC 200 Exam Tips

* Know both schema names above; the exam may ask which table to query from Advanced Hunting versus from Log Analytics for sign in data.
* Impossible travel scenarios are a classic exam pattern testing whether you know to check sign in logs first.

## 10. Microsoft Secure Score

**Microsoft Secure Score** is a measurement of an organization's overall security posture.

```text
Security Configuration
        +
Security Controls
        +
Recommended Actions
        =
Secure Score
```

The higher the score, the more recommended security actions have been implemented.

Secure Score answers the question: "How secure is our Microsoft environment?" Instead of manually checking hundreds of settings, Microsoft calculates a score and provides prioritized recommendations.

### SC 200 Exam Tips

* Secure Score is a posture and configuration metric, not an incident detection tool.
* Improving Secure Score generally means implementing the recommended actions Microsoft surfaces for identity, devices, apps, and data.

## 11. Threat Analytics

**Threat Analytics** is a Microsoft Defender XDR feature that helps security teams understand:

1. Current threats
2. Active campaigns
3. Vulnerabilities
4. Threat actors
5. Business impact
6. Exposure in your environment

```text
Threat Intelligence
        +
Your Organization's Exposure
        =
Threat Analytics
```

Instead of only saying "a new vulnerability exists," Threat Analytics tells you, for example, "a new vulnerability exists and 57 of your devices are exposed."

### SC 200 Exam Tips

* Threat Analytics combines Microsoft's threat intelligence with your tenant specific exposure data.
* It is human curated by Microsoft security researchers, which distinguishes it from AI generated summaries (see the Briefing Agent below).

## 12. Security Copilot: Threat Intelligence Briefing Agent

The **Threat Intelligence Briefing Agent** is a Security Copilot agent that automatically creates threat briefings using:

1. Threat intelligence
2. Recent threat actor activity
3. Vulnerability information
4. Your organization's exposure data

This reduces the need for analysts to manually gather information from many sources.

### Who Uses It

1. CISOs
2. Security Managers
3. Security Analysts

### What the Briefing Includes

| Section | Description |
|---|---|
| Executive Summary | High level overview for management |
| Vulnerabilities in the News | New CVEs and actively exploited vulnerabilities |
| Threat Activity | Current campaigns affecting organizations |
| Business Impact | Potential impact on the organization |
| Exposure Information | Which threats matter most to your specific environment |

### Threat Analytics vs Threat Intelligence Briefing Agent

| Feature | Purpose |
|---|---|
| Threat Analytics | Microsoft threat intelligence and exposure analysis, the source data |
| Threat Intelligence Briefing Agent | AI generated summary of Threat Analytics data |
| Security Copilot | The AI platform that powers the Briefing Agent |

> **Exam Tip:** Threat Analytics is the source, human curated reporting. The Briefing Agent is the AI tool, powered by Security Copilot, that synthesizes that data into a fast, readable summary for analysts.

### SC 200 Exam Tips

* Do not confuse Threat Analytics (data source) with the Briefing Agent (AI summarizer). The exam frequently tests this exact distinction.
* Security Copilot is the underlying AI platform; the Briefing Agent is one specific agent built on it.

## 14. Thinking Like a SOC Analyst

Each tool in Defender XDR answers a different question during incident response.

```text
Incident Queue
      │
      ▼
"What happened?"
      │
      ▼
Advanced Hunting
      │
      ▼
"How did it happen?"
      │
      ▼
Reports
      │
      ▼
"How often is this happening? Are we improving? Where are we exposed?"
```

| Tool | Question It Answers |
|---|---|
| Incident Queue | What happened |
| Advanced Hunting | How did it happen |
| Reports | How often is this happening, are we improving, where are we exposed |

### SC 200 Exam Tips

* This three tool distinction is a favorite exam pattern: given a scenario, identify which tool is the correct one to answer the analyst's specific question.

## 15. Incident Page Tabs

Incident pages in Microsoft Defender XDR commonly include these tabs:

1. Overview
2. Alerts
3. Assets
4. Evidence and Response
5. Investigation Graph

> **Exam Tip:** Know what each tab is for. Overview summarizes the incident, Alerts lists correlated alerts, Assets lists impacted users and devices, Evidence and Response lists entities and remediation actions, and Investigation Graph visualizes relationships similar to the Hunting Graph.

### SC 200 Exam Tips

* If a question asks where to find impacted devices or users for an incident, the answer is the Assets tab.
* If a question asks where to see remediation actions taken, the answer is Evidence and Response.

## 16. SC 200 Last Minute Revision

### Core Definitions to Memorize

| Term | One Line Definition |
|---|---|
| Alert | A single detection of suspicious or malicious activity |
| Incident | A correlated group of related alerts telling the story of one attack |
| Advanced Hunting | KQL based proactive threat hunting across Defender XDR data |
| Hunting Graph | Visual, node based view of Advanced Hunting results |
| Secure Score | Numeric measurement of security posture and configuration |
| Threat Analytics | Microsoft curated threat intelligence plus your tenant exposure |
| Threat Intelligence Briefing Agent | Security Copilot agent that AI summarizes Threat Analytics |
| Sign in Logs | Record of every Entra ID authentication attempt |

### Frequently Confused Concepts

| Concept A | Concept B | Key Difference |
|---|---|---|
| Alert | Incident | Alert is one event, Incident is a correlated group of alerts |
| Threat Analytics | Threat Intelligence Briefing Agent | Threat Analytics is the human curated source data, the Briefing Agent is the AI generated summary |
| Incident Queue | Advanced Hunting | Incident Queue shows what happened, Advanced Hunting lets you investigate how it happened |
| AADSignInEventsBeta | SigninLogs | First is queried from Defender XDR Advanced Hunting, second is queried from Microsoft Entra ID Log Analytics |
| Advanced Hunting retention | Standard Sentinel retention | Advanced Hunting data is retained 30 days by default, a shorter window than typical Sentinel workspace retention |

### Quick Comparison: Where Data Lives

| Defender Product | Primary Data Domain |
|---|---|
| Defender for Endpoint | Devices, processes, files, registry, network |
| Defender for Office 365 | Email delivery, attachments, URLs |
| Defender for Cloud Apps | SaaS and Office 365 cloud activity |
| Defender for Identity | Active Directory and identity authentication |

### Essential KQL Syntax to Remember

```kql
// Basic filter pattern used constantly in SC 200 scenarios
TableName
| where ColumnName == "value"
```

```kql
// Example: find PowerShell process execution
DeviceProcessEvents
| where FileName == "powershell.exe"
```

Required columns for a valid custom detection rule output: Timestamp, DeviceId, ReportId.

### Key Workflow: Incident Correlation

```text
Alert 1: Phishing Email Received
Alert 2: User Clicked Malicious Link
Alert 3: Malware Executed
Alert 4: Credential Theft Detected
        │
        ▼
Defender XDR Correlation Engine
        │
        ▼
Single Incident: "Multistage Attack Involving Phishing and Malware"
```

### Key Workflow: Analyst Triage Order

```text
1. Incident Queue: identify and prioritize the incident
        │
        ▼
2. Overview and Assets tabs: understand scope, users, devices
        │
        ▼
3. Advanced Hunting: confirm scope and hunt related activity
        │
        ▼
4. Hunting Graph / Investigation Graph: visualize entity relationships
        │
        ▼
5. Evidence and Response tab / Action Center: remediate and track actions
        │
        ▼
6. Reports: monitor trend and confirm improvement over time
```
