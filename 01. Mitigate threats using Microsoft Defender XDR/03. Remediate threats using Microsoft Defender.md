## 1. AIR: Automated Investigation and Response

**AIR (Automated Investigation and Response)** is a Microsoft Defender for Office 365 capability that automatically investigates alerts and then recommends, or directly performs, remediation actions. It reduces the manual workload of a SOC analyst reviewing every single alert.

```text
Alert
  │
  ▼
Automated Investigation
  │
  ▼
Evidence Analysis
  │
  ▼
Recommended Actions
  │
  ▼
Remediation
```

### Why AIR Exists

| Without AIR | With AIR |
|---|---|
| Analyst manually investigates the alert | Defender automatically investigates the alert |
| Analyst manually collects evidence | Defender automatically correlates evidence |
| Analyst manually decides on a response | Defender suggests a response for the analyst to approve |
| Process can take hours | Process is largely automated and much faster |

### AIR Workflow (Must Memorize)

| Phase | Name | What Happens |
|---|---|---|
| 1 | Alert Triggered | A security event occurs, for example a malicious URL is clicked, malware is detected, or a suspicious email is delivered. A security playbook starts automatically. |
| 2 | Automated Investigation Begins | Defender launches an automated investigation. It can start automatically from an alert, or be started manually by an analyst. |
| 3 | Investigation Scope Expands | As related alerts appear, the investigation grows to include them, adding related evidence automatically. |
| 4 | Results Generated | AIR produces findings, evidence, recommended actions, and investigation logs for analysts to review. |
| 5 | Analyst Reviews and Approves | The SOC team reviews the results, recommendations, and remediation actions, then approves remediation. |

```text
Email Alert
    │
    ▼
User Found
    │
    ▼
Device Found
    │
    ▼
More Alerts Found
```
*(This is how the investigation scope in Phase 3 expands.)*

> **Exam question:** Can automated investigations be started manually?
> **Answer:** Yes. This is a frequently tested detail, AIR is not purely automatic in how it starts.

> **Exam tip:** In Microsoft Defender for Office 365, many remediation actions require analyst approval. AIR recommends, it does not always act unilaterally.

### Automatic Remediation Actions

| Action | Purpose |
|---|---|
| Block URL | Prevents future clicks on a malicious link |
| Delete Emails | Removes malicious messages from mailboxes |
| Password Reset | Protects a compromised user account |
| Enforce MFA (multifactor authentication) | Requires stronger authentication for a risky account |

### Pending Actions Tab

One of the highest yield exam topics in this module.

The **Pending Actions** tab contains remediation actions that are awaiting analyst approval, for example "Pending Approval: Soft Delete Emails." The analyst reviews the pending item and approves it before Defender carries it out.

### AIR + Microsoft Entra

```text
Compromised User
        │
        ▼
Password Reset
        │
        ▼
MFA Enforcement
```

AIR can trigger identity related remediation because Defender products integrate directly with Microsoft Entra ID.

### AIR vs Action Center

A commonly confused pair.

| AIR | Action Center |
|---|---|
| Investigates threats | Manages remediation actions |
| Finds, analyzes, and recommends | Approves, rejects, tracks, and undoes actions |

> **Memory trick:** AIR discovers the problem. Action Center manages the fix.

### AIR vs Advanced Hunting

| AIR | Advanced Hunting |
|---|---|
| Automated | Manual |
| Flow: Alert then Investigation then Response | Flow: Analyst then KQL query then Investigation |

> **Exam shortcut:** Need automated investigation, think AIR. Need manual threat hunting, think Advanced Hunting.

### SC-200 Exam Tips (Section 1)

1. AIR stands for Automated Investigation and Response, and it lives inside Microsoft Defender for Office 365 (and more broadly, Microsoft Defender XDR).
2. Investigations can start automatically from an alert **or** be started manually by an analyst, remember both are correct.
3. Many remediation actions require explicit analyst approval through the Pending Actions tab, AIR is not fully autonomous by default.
4. Know the distinction: AIR investigates and recommends, Action Center approves and executes, Advanced Hunting is the manual, KQL driven alternative to AIR.
5. Identity actions like password reset and MFA enforcement show the tie between AIR and Microsoft Entra ID.

## 2. Configure, Protect, and Detect

### 2.1 Safe Attachments

**Safe Attachments** protects users from unknown malware, previously unseen (zero day) malware, and malicious file attachments. Rather than trusting file signatures alone, Microsoft detonates suspicious files inside an isolated sandbox and analyzes their behavior.

**Example:** A user receives `Invoice_2026.docm` containing a malicious macro. Traditional antivirus might miss it because the malware is new. Safe Attachments instead:

1. Receives the email
2. Detonates the attachment in a sandbox
3. Observes its behavior
4. Determines whether it is malicious
5. Allows or blocks delivery accordingly

#### Safe Attachments Policy Actions

| Action | Behavior | Notes |
|---|---|---|
| Off | No scanning occurs, email goes straight to the inbox | Troubleshooting only, not recommended |
| Monitor | Malware is detected and logged, but delivery continues | Useful for testing a policy before enforcing it |
| Block | Blocks malicious attachments outright | The most secure option |
| Replace | Removes the malicious attachment but still delivers the email body | Useful when business communication must continue |
| Dynamic Delivery | Delivers the message body immediately while the attachment is scanned separately | A favorite SC-200 exam topic, see diagram below |
| Redirect Attachment on Detection | Sends a copy of detected malware to the security team instead of the user | Useful for malware analysis, threat hunting, and incident response |

**Dynamic Delivery workflow:**

```text
Email Arrives
     │
     ▼
Message Body Delivered Immediately
     │
     ▼
Attachment Scanned in Sandbox
```

| Scan Result | Outcome |
|---|---|
| Safe | Attachment is reattached to the message |
| Malicious | Attachment is blocked |

> The user gets the message quickly without waiting for scanning to finish, only the attachment is held back.

**Redirect Attachment on Detection workflow:**

```text
Malware Detected
      │
      ▼
User Does Not Receive Attachment
      │
      ▼
Security Team Receives a Copy
      │
      ▼
Analyst Investigates
```

### 2.2 Safe Links

**Safe Links** protects users from malicious URLs. Instead of checking a URL only when the email arrives, Safe Links checks it again at the moment the user clicks it.

**Why this matters, delayed weaponization:** Attackers sometimes point a link at a harmless page when the email is first sent, then later swap the destination to a phishing page. A URL that looked safe at 9 AM can redirect to a phishing page by 3 PM. Filtering that only scans at delivery time misses this. Safe Links protects at click time instead.

**Workflow:**

```text
User Receives Email
        │
        ▼
URL Rewritten by Microsoft
        │
        ▼
User Clicks Link
        │
        ▼
Microsoft Checks Reputation
```

| Reputation Result | Outcome |
|---|---|
| Safe | Access allowed |
| Malicious | Access blocked |

#### Applications Protected by Safe Links

| Category | Coverage |
|---|---|
| Email | Outlook messages |
| Office applications | Word, Excel, PowerPoint, Visio |
| Office on the web | Word Online, Excel Online, PowerPoint Online |
| Microsoft Teams | Chat messages and channel messages |
| Mobile Office apps | iOS and Android |

#### Safe Links Policy Settings

| Setting | What It Does | Recommendation |
|---|---|---|
| Scan URLs | Checks unknown URLs at the moment they are clicked | Enabled |
| Use Safe Attachments to scan downloadable content | Extends sandbox scanning to files a link points to, for example `Email → URL → PDF download`. If the file at `https://contoso.com/maliciousfile.pdf` is malicious, the user sees a warning page instead of the file | Enabled, this is an important integration point between Safe Links and Safe Attachments |
| "Do not track when users click safe links" | Controls whether click data (who clicked, when, and which URL) is stored | Leave **unselected**; unselecting this setting is what keeps click tracking **enabled**, a classic double negative exam trap |
| Block Access to Original URL | If a URL is malicious, the user sees a warning page and access is blocked | Most secure option |
| URL Exclusions | Lets you exclude trusted URLs from scanning | Use sparingly, too many exclusions create blind spots |
| Apply Safe Links to messages sent within the organization | Protects internal email too, useful when an employee account is compromised and used to send malicious links to colleagues | Recommended |

> **Exam tip:** Click tracking data (who clicked, when, and which URL) is valuable during investigations, for example confirming a user clicked a phishing URL at a specific time to help determine exposure.

> **SC-200 exam question:** Which feature checks URLs at the time the user clicks them?
> **Answer:** Safe Links (not Safe Attachments, and not Anti-phishing policies).

### 2.3 Anti-phishing Policies

**Anti-phishing** policies in Microsoft Defender for Office 365 check incoming messages for indicators that a message might be a phishing attempt, using machine learning, reputation analysis, sender validation, and impersonation detection.

**Common phishing example:** An attacker sends a message from `microsoft-support@gmail.com` with the subject "Your password expires today," hoping the user clicks the link and enters their credentials. Anti-phishing tries to stop this before the message is even delivered.

#### Impersonation Protection

**User impersonation:** A real executive uses `ceo@contoso.com`. An attacker registers `ce0@contoso.com`, swapping the letter O for the digit 0. The two addresses look nearly identical. Anti-phishing is designed to catch this kind of lookalike sender.

**Domain impersonation:** The legitimate domain is `contoso.com`. Malicious lookalikes might be `cóntoso.com` (using an accented character) or `cont0so.com` (swapping O for 0). Anti-phishing can identify these lookalike domains and flag or block messages from them.

### SC-200 Exam Tips (Section 2)

1. Safe Attachments protects against malicious **files**, Safe Links protects against malicious **URLs**, Anti-phishing protects against **impersonation and spoofing**, keep these three roles distinct.
2. Dynamic Delivery is the Safe Attachments option that delivers the email body immediately and reattaches the file only after it is confirmed safe.
3. Redirect Attachment on Detection sends malware to the security team rather than the user, useful for investigation.
4. Safe Links rechecks a URL at click time, this is what defeats delayed weaponization attacks.
5. The "do not track" Safe Links setting is a double negative, leaving it unselected means tracking stays on.
6. Know both impersonation types: user impersonation targets a specific person's address, domain impersonation targets the whole domain.

## 3. Microsoft Security Copilot: Phishing Triage Agent

The **Phishing Triage Agent** is an AI powered Microsoft Security Copilot agent that automatically analyzes user reported phishing emails and classifies each one as:

1. **True Positive**, meaning it is real phishing
2. **False Positive**, meaning it is not malicious

Instead of requiring an analyst to manually inspect every reported email, the agent performs the initial investigation and provides its reasoning, acting like an AI analyst assisting the SOC team.

**Where it works:** Inside Microsoft Defender, integrating with:

| Integration | Role |
|---|---|
| Microsoft Defender XDR | Central platform the agent operates within |
| Microsoft Defender for Office 365 | Source of the reported email and its metadata |
| Microsoft Threat Intelligence | Provides reputation and campaign context |
| Microsoft Security Copilot | Provides the underlying AI reasoning engine |

### How It Works

**Example scenario:** An employee receives an email with subject "Payroll Update" and attachment `Salary_Update.docm`, suspects it is malicious, and selects Report Phishing.

```text
Employee Reports Email
        │
        ▼
Microsoft Defender Creates an Alert
        │
        ▼
Phishing Triage Agent Starts Automatically
        │
        ▼
Collects Evidence
        │
        ▼
Uses AI Reasoning
        │
        ▼
Classifies the Email
        │
        ▼
Updates the Alert
        │
        ▼
SOC Analyst Reviews the Result
```

The analyst only needs to verify the AI's conclusion instead of starting the investigation from scratch.

### What the Agent Analyzes

| Source | What It Checks | Example |
|---|---|---|
| 1. Email content | Subject, sender, body, attachments | A lookalike sender such as `support@micros0ft.com` raises suspicion |
| 2. Files and URLs | Attachments and embedded links, detonated or analyzed if needed | `Invoice.docm` behavior analysis shows it attempts to download malware, classified malicious |
| 3. Screenshots | Visual inspection of emails or linked pages, where supported | Recognizing a fake Microsoft login page that visually mimics the real one |
| 4. Threat Intelligence | Sender history, known malicious URLs, malicious file hashes, prior campaigns seen by other organizations | Richer context for the final classification |
| 5. Advanced Hunting | Correlates data across the organization's Microsoft security data | Same sender emailed 200 employees, 5 clicked, 1 device got infected, high confidence phishing campaign |

### AI Reasoning

Unlike a traditional rule based system that simply checks a single condition (for example, "if URL is bad then block"), the agent weighs multiple signals together: sender reputation, domain age, email wording, threat intelligence, user behavior, and organizational context. This produces a more accurate verdict and reduces false positives.

### Learning from Feedback

If an analyst disagrees with the AI's classification, for example the AI says False Positive but the analyst determines it is actually phishing, the analyst updates the classification and submits feedback. The system uses this feedback to improve future decisions for that organization's environment.

### Real SOC Scenario

Imagine an organization receiving 10,000 user reported emails each week.

| Without the Agent | With the Agent |
|---|---|
| Analysts manually review every report | The AI performs the initial investigation |
| Genuine attacks may be delayed | Safe emails are automatically identified |
| | Malicious emails are prioritized |
| | Analysts focus on confirmed threats and response, not repetitive triage |

### SC-200 Exam Notes (Section 3)

1. **Purpose:** Automates triage of user reported phishing emails.
2. **Runs in:** Microsoft Defender together with Microsoft Security Copilot.
3. **Evidence used:** Email analysis, file and URL analysis, screenshots, Microsoft Threat Intelligence, and advanced hunting correlation.
4. **Classification output:** True Positive or False Positive.
5. **Benefits:** Reduces analyst workload, speeds up incident response, and provides transparent, explainable reasoning.
6. **Feedback loop:** Analysts can correct the AI's decisions, and the system improves over time for that tenant.

## 4. Simulate Attacks

### 4.1 Threat Trackers

**Threat Trackers** show the latest cybersecurity threats Microsoft is observing globally, essentially a live threat intelligence feed. They include:

1. Noteworthy Trackers
2. Trending Trackers
3. Tracked Queries
4. Saved Queries

**Example:** Microsoft discovers a new ransomware campaign. Threat Tracker immediately surfaces the malware name, affected industries, indicators of compromise, and recommendations, allowing SOC analysts to prepare defensively before their own organization is targeted.

### 4.2 Threat Explorer (Very Important)

**Threat Explorer** is one of the most important Defender for Office 365 investigation tools, used to investigate email based threats in real time.

**Example:** A phishing campaign with subject "Payroll Update" hits 500 users. Instead of checking every mailbox manually, an analyst opens Threat Explorer and instantly sees sender, recipients, subject, URLs, attachments, malware family, and delivery status.

**Top Targeted Users:** identifies who was attacked most and which department is being targeted.

| Department | Phishing Emails Received |
|---|---|
| Finance | 120 |
| HR | 8 |
| IT | 5 |

This tells the analyst that attackers are specifically targeting Finance.

**Delivery Action** (an exam favorite), shows whether an email was:

1. Delivered
2. Blocked
3. Quarantined
4. Delivered as Spam

```text
Email
  │
  ▼
Blocked
  │
  ▼
User Never Received It
```

```text
Email
  │
  ▼
Delivered
  │
  ▼
User Opened It
  │
  ▼
Investigate the Device
```

### 4.3 Attack Simulator

**Attack Simulator** lets you safely simulate real attacks against your own organization to identify weaknesses. Supported simulation types include:

1. Spear phishing
2. Credential harvesting
3. Attachment based malware
4. Password spray
5. Brute force password attacks

**Example, credential harvesting:**

```text
User Receives Email
        │
        ▼
Clicks Link
        │
        ▼
Fake Login Page
        │
        ▼
Enters Password
        │
        ▼
Simulation Records the Event
```

No real credentials are stolen, but administrators learn which users are susceptible to phishing so they can target training.

### Feature Purpose Comparison

| Feature | Purpose |
|---|---|
| Threat Trackers | View Microsoft's latest threat intelligence and trending campaigns |
| Threat Explorer | Investigate email threats, attachments, URLs, senders, recipients, delivery actions, and targeted users in real time |
| Attack Simulator | Run controlled phishing and password attack simulations to assess user awareness and organizational security |

### SC-200 Exam Tips (Section 4)

1. Threat Trackers are informational, they describe threats Microsoft sees globally, they do not investigate your own tenant's mail.
2. Threat Explorer is the go to tool for investigating what actually happened to email in your own organization.
3. Delivery Action values to memorize: Delivered, Blocked, Quarantined, Delivered as Spam.
4. Attack Simulator tests your own users under controlled, safe conditions, no real credentials or malware are involved.
5. Do not confuse Attack Simulator (proactive testing) with the Phishing Triage Agent (reactive triage of real reports).

## 5. SC-200 Last Minute Revision (Cheat Sheet)

### Most Important Facts to Memorize

1. AIR automatically investigates alerts and recommends or performs remediation, but many actions still need analyst approval through Pending Actions.
2. Automated investigations can be started automatically **or** manually.
3. Action Center is where actions get approved, rejected, tracked, and undone, AIR is where they get discovered.
4. Safe Attachments defends against malicious **files** using sandbox detonation.
5. Safe Links defends against malicious **URLs** by rechecking reputation at click time, defeating delayed weaponization.
6. Dynamic Delivery delivers the email body instantly while the attachment is scanned separately in the background.
7. Anti-phishing policies catch user impersonation (lookalike addresses) and domain impersonation (lookalike domains).
8. The Phishing Triage Agent classifies user reported emails as True Positive or False Positive using AI reasoning across five evidence sources.
9. Threat Explorer investigates real email threats in your tenant, Threat Trackers show global intelligence, Attack Simulator tests your own users proactively.

### Frequently Confused Concepts

| Concept A | Concept B | Key Difference |
|---|---|---|
| AIR | Advanced Hunting | AIR is automated; Advanced Hunting is manual, analyst driven KQL querying |
| AIR | Action Center | AIR investigates and recommends; Action Center approves, rejects, tracks, and undoes |
| Safe Attachments | Safe Links | Safe Attachments scans files in a sandbox; Safe Links rechecks URLs at click time |
| User impersonation | Domain impersonation | User impersonation spoofs a specific person's address; domain impersonation spoofs the whole domain |
| Threat Explorer | Threat Trackers | Threat Explorer investigates your own tenant's email; Threat Trackers show Microsoft's global threat intelligence |
| Attack Simulator | Phishing Triage Agent | Attack Simulator proactively tests your users; the Phishing Triage Agent reactively triages real user reports |
| Block (Safe Attachments) | Replace (Safe Attachments) | Block stops the whole email; Replace strips the attachment but still delivers the message body |
| Monitor (Safe Attachments) | Dynamic Delivery | Monitor logs malware but still delivers it; Dynamic Delivery withholds the attachment while releasing the message body |

### Common Microsoft Service Relationships

| Layer | Service | Role |
|---|---|---|
| Identity | Microsoft Entra ID | Receives AIR triggered actions such as password reset and MFA enforcement |
| Email and collaboration protection | Microsoft Defender for Office 365 | Hosts AIR, Safe Attachments, Safe Links, Anti-phishing, Threat Explorer, Threat Trackers, Attack Simulator |
| Unified detection and response | Microsoft Defender XDR | The umbrella platform the Phishing Triage Agent and AIR operate within |
| AI assistance | Microsoft Security Copilot | Powers the Phishing Triage Agent's reasoning |
| Threat context | Microsoft Threat Intelligence | Supplies reputation and campaign data to the Phishing Triage Agent |

> **Supplementary note (added for context, verify against current Microsoft Learn material):** Microsoft Defender for Office 365 is generally licensed in two tiers. Plan 1 style capabilities center on prevention, Safe Attachments, Safe Links, and basic real time detection. Plan 2 style capabilities add the deeper investigation and response tooling covered in this guide, Threat Explorer, Threat Trackers, AIR, and Attack Simulation Training. If a question asks which tier includes automated investigation and response or Threat Explorer, the answer points toward the higher tier.

### KQL Quick Reference (Supplementary)

No KQL queries appeared in the source material, but Advanced Hunting is referenced repeatedly as the manual counterpart to AIR, so a minimal, generic syntax reference is included here for recall purposes.

```kql
EmailEvents
| where Timestamp > ago(7d)
| where DeliveryAction == "Blocked"
| summarize Count = count() by SenderFromDomain
| order by Count desc
```

| KQL Keyword | Purpose |
|---|---|
| `where` | Filters rows based on a condition |
| `project` | Selects specific columns to display |
| `summarize` | Aggregates data, for example counting events |
| `order by` | Sorts results |
| `join` | Combines data from two tables |

> **Exam tip:** You do not need to memorize entire queries for SC-200, but you should recognize `where`, `summarize`, and `project` and understand that Advanced Hunting queries always start with a table name, such as `EmailEvents`, `DeviceEvents`, or `IdentityLogonEvents`.
