## 1. What Is Microsoft Security Copilot

**Microsoft Security Copilot** is a cloud based, AI powered cybersecurity assistant developed by Microsoft. It combines **Generative AI**, **Large Language Models (LLMs)**, and Microsoft's global threat intelligence to help security teams detect, investigate, respond to, and understand cyber threats far faster than manual analysis.

```text
Analyst Prompt (natural language)
        │
        ▼
Microsoft Security Copilot (LLM + Threat Intelligence)
        │
        ▼
Plugin (connects to a data source, e.g. Defender XDR)
        │
        ▼
Capability executes (e.g. summarize incident, generate KQL)
        │
        ▼
Response returned to the analyst
```

> **Exam Tip:** Security Copilot does not replace security tools. It sits **on top of** them (Defender XDR, Sentinel, Intune, third party products) and uses natural language prompts to query, summarize, and act on data those tools already collected.

---

## 2. Capability

A **Capability** is a specific function that Security Copilot can perform. Microsoft sometimes calls a capability a **skill**. Capabilities are the individual building blocks that actually perform work.

**Examples of capabilities:**

* Summarize an incident
* Analyze code
* Generate a KQL query
* Explain malware
* Create reports
* Recommend remediation
* Analyze scripts

Each capability performs one specialized task.

---

## 3. Plugin

A **Plugin** is a connector that allows Security Copilot to communicate with a specific data source or security product and use the capabilities that product provides. A plugin is essentially a **collection of related capabilities** supplied by a specific service.

The plugin determines:

1. What data Security Copilot can access.
2. What capabilities become available.

> Without an enabled plugin, Security Copilot cannot use that product's specialized functions at all.

### How a Plugin Works, Worked Example

Suppose your organization uses **Microsoft Defender XDR**. On its own, Security Copilot does **not** automatically know your Defender XDR incidents. Once the **Microsoft Defender XDR plugin** is enabled, Security Copilot gains access to Defender XDR data and functions, and an analyst can ask things such as:

* "Summarize Incident 1234."
* "Explain this PowerShell script."
* "Generate a KQL query."
* "Recommend containment steps."

All of those responses are powered by capabilities inside the Defender XDR plugin.

## 4. Relationship Between Plugin and Capability

This is one of the most commonly confused pairs of terms on the exam.

> **Plugin = Container. Capability = What actually does the work.**

```text
Microsoft Defender XDR Plugin  (the container / connector)
        │
        ├── Capability: Incident summaries
        ├── Capability: Script analysis
        ├── Capability: Guided response
        ├── Capability: KQL generation
        └── Capability: Incident reports
```

The **plugin** provides the connection and access. The **capabilities** inside it perform the actual task.

> **Exam Tip:** If a question describes "connecting Security Copilot to a product" it is testing **Plugin**. If it describes "a single task Security Copilot performs," it is testing **Capability**.

---

## 5. Microsoft vs Non Microsoft Plugins

Security Copilot is not limited to Microsoft products, it also connects to third party security tools.

| Category | Examples |
|---|---|
| **Microsoft plugins** | Microsoft Defender XDR, Azure Firewall, Azure Web Application Firewall (Preview), Microsoft Defender External Attack Surface Management |
| **Non Microsoft plugins** | ServiceNow, Splunk, CIRCL Hash Lookup |
| **Other connector types** | Public websites, custom plugins, OpenAI plugins |

Each plugin exposes capabilities that are specific to its own product, letting organizations bring their existing security stack into Security Copilot rather than being limited to a Microsoft only toolset.

> **Exam Tip:** Know that Security Copilot's plugin architecture is **extensible and vendor neutral**. Expect exam questions that test whether you understand plugins can come from Microsoft products, non Microsoft security vendors, or custom sources.

## 6. Workspace

A **Workspace** is an independent Security Copilot working environment inside a Microsoft tenant. Organizations can create multiple workspaces, and each one operates independently with its own:

* Users
* Permissions
* Sessions
* Capacity
* Settings

A single tenant can contain multiple workspaces, each isolated from the others.

---

## 7. Tenant vs Workspace

Another frequently tested distinction.

| | Tenant | Workspace |
|---|---|---|
| **What it is** | The organization's overall Microsoft cloud environment | An independent working environment for Security Copilot inside that tenant |
| **Scope** | One per organization (typically) | Many can exist inside a single tenant |
| **Contains** | Multiple Security Copilot workspaces | Its own users, permissions, sessions, capacity, and settings |

```text
Tenant: Contoso Corporation
        │
        ├── Workspace: SOC Operations
        ├── Workspace: Incident Response
        ├── Workspace: Threat Hunting
        └── Workspace: Executive Security
```

Each workspace serves a different team while remaining part of the same tenant, so a SOC team and an executive reporting team could use Security Copilot side by side without seeing each other's sessions or data.

> **Exam Tip:** Remember the direction of containment: a **Tenant contains Workspaces**, never the reverse.

## 8. Provision Capacity: Security Compute Units (SCU)

**Security Compute Units (SCUs)** are the unit of computing power used to run Microsoft Security Copilot. Every prompt, investigation, and AI generated response consumes compute resources, and SCUs provide that resource. Without provisioned SCUs, Security Copilot cannot process prompts at all, so provisioning capacity is a required setup step, not an optional one.

### Capacity Models

| Model | How It Works |
|---|---|
| **Provisioned capacity** | A baseline number of SCUs you set up in advance. This must be provisioned before Security Copilot can be used, and it is billed by the hour regardless of how much of that capacity is actually consumed in that hour. |
| **Overage capacity** | Extra SCUs that are drawn on top of provisioned capacity during usage spikes (e.g. a busy investigation period), so access is not interrupted when demand exceeds the baseline. |
| **Microsoft 365 E5/E7 inclusion** | Eligible Microsoft 365 E5 and E7 customers are auto provisioned with SCUs at no additional cost: **400 SCUs per month for every 1,000 paid user licenses, capped at 10,000 SCUs per month.** This monthly allocation resets each month and unused SCUs do not carry over. |

```text
Prompt / Investigation / AI Response
        │
        ▼
Consumes Security Compute Units (SCUs)
        │
        ▼
Draws from Provisioned Capacity first
        │
        ▼
If capacity is exceeded → Overage Capacity is used (if configured)
```

> **Exam Tip:** A minimum baseline of provisioned SCUs is required before Security Copilot can be used at all, capacity must exist before consumption can happen. Non Microsoft 365 E5/E7 organizations must provision SCUs manually; eligible E5/E7 customers instead draw from an automatically included monthly SCU pool.

## 9. SC-200 Last Minute Revision

### One Page Cheat Sheet

**What Security Copilot is:** a cloud based, AI powered assistant built on Generative AI, LLMs, and Microsoft threat intelligence. It sits on top of existing tools like Defender XDR and Sentinel rather than replacing them.

**Four terms to keep straight:**

| Term | One Line Definition |
|---|---|
| **Capability** (a.k.a. Skill) | A single function Security Copilot performs, e.g. generate a KQL query |
| **Plugin** | The connector/container that gives Security Copilot access to a product's data and capabilities |
| **Workspace** | An independent working environment inside a tenant, with its own users, permissions, and capacity |
| **Tenant** | The organization's overall Microsoft cloud environment; can contain multiple workspaces |

**Containment direction to memorize:**

```text
Tenant
   └── Workspace(s)

Plugin
   └── Capability(ies)
```

**Plugin sources:** Microsoft (Defender XDR, Azure Firewall, Defender External Attack Surface Management) **and** non Microsoft (ServiceNow, Splunk, CIRCL Hash Lookup) **and** custom/website/OpenAI plugins. Security Copilot is vendor neutral by design.

**Capacity quick facts:**

| Fact | Detail |
|---|---|
| Unit of compute | Security Compute Unit (SCU) |
| Required before use | Yes, capacity must be provisioned first |
| Provisioned capacity billing | Charged by the hour regardless of actual consumption within that hour |
| Overage capacity | Extra SCUs used automatically when demand exceeds provisioned capacity |
| Microsoft 365 E5/E7 inclusion | 400 SCUs/month per 1,000 licensed users, capped at 10,000 SCUs/month, resets monthly, no rollover |

> **Final Reminder:** The exam tests whether you can tell **Plugin from Capability** (container vs the work it does) and **Tenant from Workspace** (one environment vs many isolated working spaces inside it). If a question describes access to a product's data, think **Plugin**. If it describes one discrete AI powered task, think **Capability**.
