# SC-200 Revision Guide: Embedded Experiences of Microsoft Security Copilot

A concise, exam focused revision resource covering how Microsoft Security Copilot is embedded across Microsoft Defender XDR, Microsoft Purview, Microsoft Entra, Microsoft Intune, and Microsoft Defender for Cloud.

> **Core exam concept:** Security Copilot can be used in two ways: the **standalone experience** (its own dedicated portal) and the **embedded experience** (built directly into another Microsoft product, using that product's data through a plugin). This guide focuses entirely on the embedded experience.

## 1. Embedded Experience Overview

Every embedded experience follows the same general pattern: a **plugin** connects Security Copilot to a specific product's data, so Copilot can answer natural language questions and generate insights using real, contextual information rather than generic knowledge.

```text
Security Copilot Engine
  │
  ▼
Product Specific Plugin (e.g. Defender XDR, Purview, Entra, Intune)
  │
  ▼
Embedded Panel Inside the Product's Admin Portal
  │
  ▼
Contextual, Data Backed AI Assistance
```

The table below is a quick reference for all five embedded experiences covered in this guide.

| Module | Embedded In | Plugin Required | Primary Focus |
|---|---|---|---|
| Microsoft Defender XDR | Microsoft Defender portal | Microsoft Defender XDR plugin | Incident response and threat investigation |
| Microsoft Purview | Microsoft Purview portal | Microsoft Purview plugin | Data security and compliance |
| Microsoft Entra | Microsoft Entra admin center | Microsoft Entra plugin | Identity investigation and governance |
| Microsoft Intune | Microsoft Intune admin center | Microsoft Intune plugin (Windows 365 plugin for Cloud PCs) | Device management and troubleshooting |
| Microsoft Defender for Cloud | Defender for Cloud portal | Uses Security Copilot and Copilot for Azure together | Cloud posture and recommendation remediation |

> **Exam tip:** A very common SC-200 question pattern is "which plugin must be enabled for Copilot to work inside product X." Learn the plugin name for each product, not just the product name.

## 2. Copilot in Microsoft Defender XDR

### What It Is

Microsoft Security Copilot is integrated directly into the **Microsoft Defender portal**, assisting analysts throughout the full incident response lifecycle. It relies on product specific Defender data, so the **Microsoft Defender XDR plugin must be enabled**.

Its goals include speeding up investigations, reducing manual analysis, improving threat hunting, generating automatic summaries, recommending response actions, helping analysts write KQL queries, analyzing scripts and files, and producing incident reports.

### Key Capabilities

**1. Incident Summaries**

Copilot automatically generates a summary when an analyst opens an incident. The summary covers what happened, the attack timeline, assets involved, Indicators of Compromise (IOCs), threat actors (when identified), and overall attack progression. An incident with up to **100 alerts** can be condensed into a single overview. Copilot also suggests follow up prompts about devices, users, IP addresses, and other related entities.

**2. Guided Responses**

Using AI, machine learning, and prior investigation knowledge, Copilot produces guided responses across four categories:

```text
Triage
  │
  ▼
Containment
  │
  ▼
Investigation
  │
  ▼
Remediation
```

| Category | Purpose | Examples |
|---|---|---|
| Triage | Classify the incident | Informational, True Positive, False Positive |
| Containment | Stop the attack from spreading | Isolate a device, block an IP address, disable a user account |
| Investigation | Suggest further investigation steps | Examine related alerts, review similar incidents, investigate affected identities |
| Remediation | Eliminate the threat | Reset passwords, remove malware, apply remediation actions to affected entities |

Every recommendation explains **why** it is suggested. Administrators can upload organization specific response guidance to customize recommendations. Guided responses are available for incident types such as phishing, ransomware, and business email compromise (BEC).

**3. Script and Command Line Analysis**

Instead of manually reading obfuscated PowerShell or command line code, Copilot analyzes it automatically and returns a plain language explanation, a malicious or benign verdict, the relevant MITRE ATT&CK techniques, an explanation of suspicious commands, and the ability to view the original code. This can be launched directly from an incident timeline. At present, **PowerShell** analysis is supported, with additional scripting languages expanding over time.

**4. Generate KQL Queries**

Copilot acts as a query assistant, converting natural language into ready to run Kusto Query Language (KQL) queries. For example, a prompt such as "give me all devices that signed in within the last 10 minutes" produces a working KQL query that can be run immediately, added to the Advanced Hunting editor, modified before execution, or copied for later use.

**5. Incident Reports**

While an incident summary is a quick overview, an incident report is far more detailed. It consolidates data from **Microsoft Defender XDR** and **Microsoft Sentinel**, and includes the incident timeline, analysts involved, incident classification, comments, investigation activities, manual remediation actions, automated remediation actions (including Sentinel playbooks), and follow up actions. Reports can be copied to the clipboard, posted to the activity log, regenerated, or opened in the standalone Security Copilot experience.

**6. File Analysis**

When a file is selected, Copilot summarizes detection information, related certificates, API calls, strings found inside the file, and other security relevant metadata. Files can be analyzed from Evidence and Response, the Incident Graph, or Search.

**7. Device Summaries**

Covers protection status, Attack Surface Reduction (ASR) information, Tamper Protection status, unusual user activity, vulnerable software, firewall configuration, and Microsoft Intune information.

**8. Identity Summaries**

Covers account creation date, user criticality level, role changes, sign in behavior, authentication methods, risks from Microsoft Entra ID, and contact information.

**9. Threat Intelligence Summaries**

Integrates with the **Microsoft Defender Threat Intelligence** plugin to summarize threat actors, intelligence reports, vulnerability disclosures, IOCs, industry specific threats, and organization exposure.

### Real World SOC Scenario

A SOC analyst receives a high severity ransomware incident spanning dozens of alerts across multiple endpoints. Instead of reviewing each alert manually, Copilot generates an incident summary and timeline, identifies affected devices, users, and IOCs, recommends guided response actions such as isolating devices and resetting accounts, analyzes suspicious PowerShell scripts and maps them to MITRE ATT&CK, generates KQL queries to hunt for similar activity, and produces a full incident report documenting the response.

### SC-200 Exam Tips

* Copilot is **embedded inside Microsoft Defender XDR** through the **Microsoft Defender portal**, and requires the **Microsoft Defender XDR plugin**.
* **Guided Responses** always fall into four categories: Triage, Containment, Investigation, Remediation. Memorize this order.
* **Script analysis currently supports PowerShell only.**
* An incident summary can cover up to **100 alerts**.
* Incident reports pull data from **both** Defender XDR and Microsoft Sentinel, incident summaries do not.
* Threat Intelligence Summaries require the separate **Microsoft Defender Threat Intelligence plugin**.

## 3. Copilot in Microsoft Purview

### What Is Microsoft Purview?

**Microsoft Purview** is Microsoft's data security, data governance, risk management, and compliance platform. It helps organizations discover where data is stored, classify sensitive data, protect sensitive information, prevent data leaks, monitor insider threats, investigate user activity involving data, and meet legal or regulatory compliance requirements.

> **Frequently confused concept:** Microsoft **Defender** protects an organization against **cyberattacks**. Microsoft **Purview** protects an organization's **data**. These two product families solve different problems even though both are part of the Microsoft security portfolio.

Purview protects data across Microsoft 365 and other supported environments, including Word documents, Excel spreadsheets, PDF files, emails, Teams messages, SharePoint documents, OneDrive files, Exchange Online mailboxes, Azure storage, and other connected cloud services (for example, files containing salary data, customer records, financial reports, or personally identifiable information).

### What Is Copilot in Microsoft Purview?

Security Copilot integrates into Microsoft Purview to help administrators assess data security risks, summarize alerts, investigate user activities, understand policies, and gain compliance insights. It is accessed from the Copilot icon inside Purview.

### The Five Purview Solutions

```text
Discover Sensitive Data (DSPM)
  │
  ▼
Prevent Data Leakage (DLP)
  │
  ▼
Detect Risky User Behavior (Insider Risk Management)
  │
  ▼
Monitor Communications (Communication Compliance)
  │
  ▼
Investigate and Collect Evidence (eDiscovery)
```

| Solution | Purpose | Think of it as |
|---|---|---|
| Data Security Posture Management (DSPM) | Find and understand data risks | Discover and assess data risk |
| Data Loss Prevention (DLP) | Prevent sensitive data leaving the organization | Stop data leakage |
| Insider Risk Management | Detect intentional or accidental misuse of data | Detect risky user behavior |
| Communication Compliance | Monitor communications for policy violations | Monitor communications |
| eDiscovery | Collect and review evidence for investigations | Find and review evidence |

**1. Data Security Posture Management (DSPM)**

Helps identify sensitive data exposure, risky users, potential data leaks, and unprotected sensitive information. Copilot assists by investigating risky users, locating sensitive data, tracking data movement, detecting suspicious activity, and identifying unauthorized transfers. DSPM includes built in **Promptbooks** (predefined AI investigation workflows), with **Risky User Investigation** and **Sensitive Data Protection** as important examples, plus a **Prompt Gallery** of ready made prompts.

**2. Data Loss Prevention (DLP)**

When a DLP alert is selected, Copilot generates an **Alert Summary** covering what happened, the policy triggered, the file involved, the user involved, severity, and timeline. Summaries can be copied, regenerated, or opened in the standalone Security Copilot experience. Copilot can also explain DLP policy behavior, effectiveness, and configuration.

**3. Insider Risk Management**

Copilot summarizes insider risk alerts, highlighting user details, data exfiltration activities, activity patterns, user roles, unusual behavior, and risk indicators. It can also summarize a user's activities over a selected period to help build an overall risk profile.

**4. Activity Explorer**

Records user activity involving sensitive data. Copilot helps drill into activity data, investigate user actions, find files involved, and filter activities using natural language (for example: "filter files copied to the cloud containing credit card information during the past 30 days").

**5. Communication Compliance**

Monitors emails, chats, and other communications for policy violations. Copilot generates contextual summaries explaining why a communication was flagged, which classifier or policy triggered, key conversation content, and relevant attachments, and supports follow up questions.

> **Exam tip:** Contextual summaries in Communication Compliance require messages or attachments of **100 words or more**, and the analyst must hold the **Communication Compliance Investigator** role.

**6. eDiscovery**

Used during legal investigations and compliance reviews. Copilot helps summarize evidence in review sets, answer questions about evidence, search using natural language, generate case summaries, and identify key participants, topics, and action items.

### Feedback on AI Responses

Every AI generated summary includes a feedback option. Users can mark a response as **Confirmed**, **Off target or inaccurate**, or **Potentially harmful or inappropriate**. Microsoft uses this feedback to improve Copilot.

### Real World SOC Scenario

An employee uploads a confidential financial document containing customer credit card numbers to SharePoint, triggering a DLP alert. Copilot summarizes the alert, the analyst reviews the file, user, and policy, investigates the user's recent activity in Insider Risk Management, searches for similar uploads using Activity Explorer, checks related emails in Communication Compliance, and if needed, uses eDiscovery to summarize evidence and generate a case summary for a legal investigation.

### SC-200 Exam Tips

* Copilot is embedded into **Microsoft Purview** and needs the **Microsoft Purview plugin**, Security Copilot onboarding, Microsoft 365 data access, and appropriate permissions.
* Memorize the **five Purview solutions**: DSPM, DLP, Insider Risk Management, Communication Compliance, eDiscovery.
* **DSPM** has built in **Promptbooks** and a **Prompt Gallery**; this is a distinguishing, testable detail.
* **Communication Compliance** contextual summaries require **100+ words** and the **Communication Compliance Investigator** role. This exact number is a common exam detail.
* AI response feedback options are exactly three: **Confirmed**, **Off target/Inaccurate**, **Potentially harmful/Inappropriate**.

## 4. Copilot in Microsoft Entra

### What It Is

Security Copilot is embedded into the **Microsoft Entra admin center** using the **Microsoft Entra plugin**, retrieving identity information directly from the tenant. It helps analysts investigate users, analyze sign in logs, review audit logs, investigate identity risks, analyze Conditional Access policies, examine authentication methods, review role assignments, investigate devices, and receive security recommendations, all through natural language instead of manually navigating the Entra portal.

### Four Supported Scenarios

```text
Microsoft Entra ID
  │
  ▼
Microsoft Entra ID Protection
  │
  ▼
Microsoft Entra ID Governance
  │
  ▼
Microsoft Entra Internet Access and Private Access (Global Secure Access)
```

| Scenario | Focus | Copilot Helps With |
|---|---|---|
| Microsoft Entra ID | Users, groups, devices, licenses, authentication, sign in logs, audit logs, Conditional Access | Investigating identities, analyzing logs, reviewing authentication methods, troubleshooting access policies |
| Microsoft Entra ID Protection | Detecting and remediating identity risks | Investigating risky users, risky sign ins, and risky applications; recommending mitigations |
| Microsoft Entra ID Governance | Identity lifecycle and access governance | Access reviews, entitlement management, Privileged Identity Management (PIM), lifecycle workflows |
| Microsoft Entra Internet Access and Private Access (Global Secure Access) | Network access monitoring and analysis | Investigating network traffic, bandwidth usage, application access, blocked connections, and threats |

### Real World SOC Scenario

An analyst receives an alert that a user account may be compromised. Using Entra and Security Copilot, the analyst opens the **Risky User** record, reviews a Copilot generated summary of risk level and recent risky sign ins, reviews sign in and audit logs using natural language, checks Conditional Access and MFA configuration, reviews administrative role assignments for excessive privilege, investigates registered devices and authentication methods, and if needed, uses **Privileged Identity Management (PIM)** to activate only the least privileged role required for remediation.

### SC-200 Exam Tips

* Copilot in Entra requires **Security Copilot onboarding**, the **Microsoft Entra plugin**, and appropriate Entra permissions.
* **Permission model:** Copilot uses the **current user's permissions**, sometimes called the **OBO (On Behalf Of) model**, and cannot access data beyond that user's assigned roles. This is a key testable difference from other embedded experiences.
* Memorize the **four Entra scenarios**: Microsoft Entra ID, Microsoft Entra ID Protection, Microsoft Entra ID Governance, and Microsoft Entra Internet Access and Private Access (Global Secure Access).
* **Open list** displays complete datasets along with the underlying Microsoft Graph query used to retrieve them, useful for validating Copilot's answers.
* AI responses should always be reviewed for accuracy; feedback is given through thumbs up or thumbs down.

## 5. Copilot in Microsoft Intune

### What It Is

Security Copilot is embedded into the **Microsoft Intune admin center** and uses the **Microsoft Intune plugin** to access Intune data. It helps administrators manage policies and settings, explore Intune data, troubleshoot devices, analyze Endpoint Privilege Management (EPM) requests, generate device queries, and gain insights into Windows 365 Cloud PCs. It can also be accessed from the standalone Security Copilot experience, but this section focuses on the embedded experience.

### Real World SOC Scenario

A user reports that their corporate laptop cannot reach company resources. The Intune administrator opens the device record and uses Copilot to generate a device summary, review installed applications and assigned security policies, analyze an error code, verify compliance status against a healthy device, confirm the correct configuration policies are assigned, and generate a KQL query to search for similar issues across all managed devices.

### SC-200 Exam Tips

* Requires configuring **Security Copilot**, enabling the **Microsoft Intune plugin**, and having appropriate **RBAC permissions**.
* The **Windows 365 plugin** is a separate requirement specifically for Windows 365 Cloud PC capabilities.
* **Permission model:** Copilot uses the signed in administrator's permissions and can only access authorized Intune data, similar in principle to the Entra permission model.
* Major capabilities to memorize:

| Capability | Description |
|---|---|
| Data Exploration | Explore Intune data using natural language |
| Policy and Setting Management | Explanations, recommendations, policy summaries, conflict detection |
| Device Details and Troubleshooting | Device summaries, apps, policies, users, error analysis |
| Device Query | AI generated KQL queries for devices |
| Endpoint Privilege Management (EPM) | Analysis of EPM requests |
| Surface Device Troubleshooting | Troubleshooting for Surface devices |
| Windows 365 Cloud PC Insights | Performance, licensing, connectivity, provisioning |

* **Device Query specifically requires Microsoft Intune Advanced Analytics licensing.** This is a precise, high value exam detail.

## 6. Copilot in Microsoft Defender for Cloud

### What It Is

Microsoft Defender for Cloud integrates **both** Microsoft Security Copilot and Microsoft Copilot for Azure. Together they let administrators ask security questions in natural language to analyze security recommendations, summarize vulnerabilities, generate remediation guidance, delegate remediation tasks, and create Infrastructure as Code (IaC) fixes.

```text
Natural Language Question
  │
  ▼
Microsoft Copilot for Azure (interface layer)
  │
  ▼
Security Copilot Skill (security specific analysis, consumes SCUs)
  │
  ▼
Recommendation Analysis, Remediation, Delegation, or IaC Fix
```

> **Frequently confused concept:** Copilot for Azure acts as the general interface, while **only Security Copilot skills consume Security Compute Units (SCUs)**. This distinction is a common exam trap.

### Prerequisites

* Defender for Cloud must be enabled.
* The user must have access to Azure Copilot.
* Security Copilot must have **Security Compute Units (SCUs)** assigned.
* Microsoft recommends enabling the **Defender CSPM (Cloud Security Posture Management)** plan for full functionality; without it, Copilot still works but with limited capability.

### Where Recommendations Come From

Defender for Cloud continuously scans resources such as virtual machines, storage accounts, SQL databases, Kubernetes clusters, app services, Azure Key Vault, networks, and Azure DevOps repositories (for IaC). It compares their configuration against Microsoft security best practices, security benchmarks (such as the Azure Security Benchmark and CIS), Defender security checks, and compliance requirements. Whenever a resource fails to meet the standard, Defender creates a **recommendation**.

### Real World SOC Scenario

A SOC analyst discovers several Azure Storage Accounts are publicly accessible. Using Defender for Cloud, the analyst asks Copilot to identify exposed resources, receives a prioritized list, reviews a summary of the security risk, requests remediation guidance, applies the provided steps or generated script, and delegates any remaining work to storage administrators using an AI generated email. If the exposure originates from Infrastructure as Code, Copilot can generate a pull request for developers to review before deployment.

### SC-200 Exam Tips

* Defender for Cloud integrates **both** Security Copilot and Copilot for Azure; know the role of each.
* **Only Security Copilot skills consume Security Compute Units (SCUs).** Copilot for Azure itself does not.
* Major capabilities: Analyze Recommendations, Summarize Recommendations, Remediate Recommendations (with step by step guidance and scripts), Delegate Recommendations (through AI generated emails), and Infrastructure as Code (IaC) Remediation (generating code fixes and pull requests).
* IaC remediation requires additional setup, including Azure DevOps integration and Microsoft Security DevOps support.
* Copilot can recommend **Just-in-Time (JIT) VM access** as part of remediation guidance.

### Frequently Confused Concepts

| Concept A | Concept B | Key Difference |
|---|---|---|
| Microsoft Defender | Microsoft Purview | Defender protects against cyberattacks; Purview protects organizational data |
| Incident Summary (Defender XDR) | Incident Report (Defender XDR) | Summary is a quick overview; report is a detailed document pulling from both Defender XDR and Sentinel |
| DSPM | DLP | DSPM discovers and assesses data risk; DLP actively stops sensitive data from leaving |
| Copilot for Azure | Security Copilot (in Defender for Cloud) | Copilot for Azure is the interface; Security Copilot performs the security specific analysis and consumes SCUs |
| Entra/Intune permission model | Defender for Cloud permission model | Entra and Intune scope Copilot to the signed in user's own permissions (OBO model); Defender for Cloud usage is governed by SCU assignment |

### Key Terminology

| PIM | Privileged Identity Management |
| BEC | Business Email Compromise |
| IaC | Infrastructure as Code |

### Quick KQL Reference (Supplementary)

Copilot converts natural language into KQL for Advanced Hunting in Defender XDR and for device queries in Intune. Knowing the basic operators helps when reviewing or editing what Copilot generates.

| Operator | Purpose |
|---|---|
| `where` | Filter rows based on a condition |
| `project` | Select specific columns to display |
| `summarize` | Aggregate data, often with `count()` or `by` |
| `extend` | Add a calculated column |
| `join` | Combine data from two tables |
| `order by` | Sort results |
| `take` | Limit the number of returned rows |

> **Exam tip:** You are not expected to memorize full KQL syntax for SC-200, but you should recognize what Copilot generated queries are doing and know that Copilot output can always be reviewed, modified, and copied before running it.

### Core Workflow to Memorize

```text
Analyst Asks a Natural Language Question
  │
  ▼
Security Copilot Uses the Relevant Plugin
  │
  ▼
Copilot Retrieves Contextual Product Data
  │
  ▼
Copilot Returns a Summary, Recommendation, or Query
  │
  ▼
Analyst Reviews, Edits if Needed, and Provides Feedback
```

### Final Reminders Before the Exam

* Every embedded experience needs its **product specific plugin** enabled; this is the single most repeated prerequisite across all modules.
* AI output is **always reviewable and editable**, and every module includes a feedback mechanism (thumbs up/down or Confirmed/Off target/Harmful).
* Permission scoping matters: Entra and Intune restrict Copilot to the signed in user's own access; Defender for Cloud usage is tracked through SCUs.
* Know which module owns which unique feature: Promptbooks and Prompt Gallery belong to **Purview DSPM**; Open list belongs to **Entra**; Device Query licensing belongs to **Intune**; JIT VM access recommendations belong to **Defender for Cloud**.
