## Overview of Microsoft Purview Audit

**Microsoft Purview Audit** is a Microsoft 365 compliance solution that records **user and administrator activities** across Microsoft 365 services. It is a forensic and compliance log source, not a real time alerting engine.

> Frequently confused concept: Purview Audit is not the same kind of tool as Microsoft Sentinel or Microsoft Defender XDR. Sentinel and Defender XDR generate real time alerts and incidents. Purview Audit stores a historical, searchable record of activity that analysts pull in to confirm, enrich, or scope an investigation that started elsewhere.

### What Gets Captured

Typical audit events include:

* User sign ins
* File access, downloads, and deletions
* Permission changes
* Mailbox activities
* Administrator actions
* Microsoft Teams activities
* Microsoft Copilot interactions

### Unified Audit Log (UAL)

The **Unified Audit Log (UAL)** is the central repository for audit records across supported Microsoft 365 workloads, including:

* Microsoft Entra ID
* Exchange Online
* SharePoint Online
* OneDrive
* Microsoft Teams

Instead of checking each service's own log, investigators search one consolidated log.

### How Purview Audit Works

```text
User or Administrator Performs an Action
        │
        ▼
Microsoft 365 Service Records the Activity
        │
        ▼
Activity Is Written to the Unified Audit Log
        │
        ▼
Microsoft Purview Indexes the Record
        │
        ▼
Investigator Searches
(Purview Portal, PowerShell, Graph API)
        │
        ▼
Results Are Reviewed or Exported
```

Every audit record typically contains:

| Field | Description |
|---|---|
| User | Who performed the action |
| Activity | What action occurred |
| Date and time | When it happened |
| Workload | Which Microsoft 365 service generated it |
| IP address | Where the action originated |
| Target object | What was acted upon |
| Additional metadata | Extra event specific details |

This lets an investigator reconstruct **who did what, when, where, and from which IP address**.

### Copilot and AI Application Auditing

Purview Audit also records interactions with Microsoft Copilot and supported AI applications, including Copilot prompts, responses, and AI interaction events, searchable through the **CopilotInteraction** operation. Records may include thread IDs and accessed resources, supporting AI usage investigations for security and compliance.

### SC-200 Exam Tips

* Purview Audit records activity into the **Unified Audit Log**.
* **Audit (Standard)** is enabled by default for eligible tenants; default retention is **180 days**.
* **Audit (Premium)** adds longer retention, Intelligent Insights, higher API bandwidth, and extra audit events (such as MailItemsAccessed).
* Entra ID, Exchange Online, SharePoint Online, and OneDrive get **one year** default retention under Audit (Premium); up to **10 years** with the right add on license.
* Retention policy changes only affect **future records**, never records already written.
* Use **Search-UnifiedAuditLog** for PowerShell based searches.
* The **Office 365 Management Activity API** enables SIEM integration and automated retrieval; this is the same API Microsoft Sentinel's Office 365 data connector uses to ingest audit events.
* Audit search results export as **CSV**.
* The **Microsoft Purview** portal is the primary interface for searching, saving, and exporting audit data.

## Configuring and Managing Purview Audit

### Licensing and Roles

Always confirm licensing before configuring auditing.

| Item | Requirement |
|---|---|
| Audit (Standard) | Enabled by default for eligible Microsoft 365 and Office 365 subscriptions |
| Audit (Premium) | Requires E5 level licensing or an equivalent compliance add on |
| Advanced Auditing | Must be enabled per licensed user for Premium features |

| Role | Search | Export | Modify Settings |
|---|---|---|---|
| Audit Manager | Yes | Yes | Yes |
| Audit Reader | Yes | Yes | No |

> Classic Exchange RBAC roles that also grant search access: **Audit Logs** and **View Only Audit Logs**.

### Timing to Remember

* **MailItemsAccessed** and **Send** events begin logging roughly **24 hours** after Advanced Auditing is enabled.
* After enabling auditing generally, allow up to **60 minutes** before events start appearing in the Unified Audit Log.
* **SearchQueryInitiatedExchange** and **SearchQueryInitiatedSharePoint** need extra PowerShell configuration.
* In multi geo environments, configure mailbox auditing in the mailbox's hosting region.

### Key Cmdlets

| Cmdlet | Purpose |
|---|---|
| `Get-AdminAuditLogConfig \| Format-List UnifiedAuditLogIngestionEnabled` | Check whether auditing is enabled |
| `Set-AdminAuditLogConfig -UnifiedAuditLogIngestionEnabled $true` | Enable Unified Audit Log ingestion |
| `Set-AdminAuditLogConfig -UnifiedAuditLogIngestionEnabled $false` | Disable ingestion (only when absolutely necessary) |
| `Set-Mailbox -AuditOwner @{Add="SearchQueryInitiated"}` | Enable mailbox search query auditing |

### SC-200 Exam Tips

* Audit (Premium) requires E5 level licensing or an equivalent compliance add on, plus per user Advanced Auditing.
* Retention policies can be scoped by **service**, **activity type**, or **user**.
* Know the exact cmdlets above; the exam tests both the verb and the parameter name.
* Remember the two timing numbers: about **24 hours** for MailItemsAccessed and Send to start logging, and up to **60 minutes** for general audit ingestion to appear.

## Conducting Searches with Audit (Standard)

### Purpose

Audit (Standard) records activity across Entra ID, Exchange Online, SharePoint Online, OneDrive, Teams, and Microsoft 365 administration. SOC analysts use these logs to investigate incidents, perform forensic work, monitor user activity, detect insider threats, verify compliance, and produce audit evidence.

Unlike a Defender alert, an audit record shows **who performed an action, what action occurred, when it happened, where it happened, and from which IP address** without needing a triggered detection.

### Investigation Workflow

```text
Open Microsoft Purview Audit
        │
        ▼
Select Activity or Record Type
        │
        ▼
Apply Filters (User, Date Range, Activity)
        │
        ▼
Run the Search
        │
        ▼
Review Results for Anomalies
        │
        ▼
Confirm Legitimate or Malicious
        │
        ▼
Escalate to Response, or Tune Monitoring
```

### Worked Example: Suspected Evidence Deletion

A hospital suspects an employee deleted confidential patient emails to hide evidence. The analyst:

1. Opens Microsoft Purview Audit and selects **Exchange mailbox activities**.
2. Filters for **Deleted messages from Deleted Items folder** and **Purged messages from mailbox**.
3. Sets the date range to the suspected incident period and scopes the search to the employee's mailbox.
4. Runs the search and reviews results for unusual patterns, such as a high volume of deletions or deletions outside normal working hours.
5. Opens each record and checks deletion time, source IP address, user account, and other details.
6. Decides whether the deletion was legitimate or malicious, then either follows incident response procedures or tunes monitoring thresholds to cut false positives.

> Takeaway: unusual volume and unusual timing are the two signals investigators lean on most when the activity itself (a deletion) is not inherently malicious.

### SC-200 Exam Tips

* Audit logging **must already be enabled** before a search can return results.
* Required permissions: **Audit Reader**, **Audit Manager**, **Audit Logs**, or **View Only Audit Logs**.
* **Activity Type** identifies the action performed; **Record Type** identifies the Microsoft service that generated the event. These are commonly confused.
* Search results include user, IP address, time, activity, record type, item, and details.
* A user can run up to **10 concurrent** search jobs; completed jobs stay available for **30 days**.
* A single search can export up to **50,000 records**.
* Automation options: **Office 365 Management Activity API** or **Search-UnifiedAuditLog**.
* Soft deleted items are usually recoverable within **14 to 30 days**; hard deleted items may need a mailbox hold or retention policy to recover.

## Auditing Microsoft Copilot Interactions

### Why It Matters

Copilot can access sensitive Microsoft 365 data while helping users write emails, summarize Teams meetings, draft Word documents, analyze Excel data, and search organizational knowledge. Administrators need to monitor usage, investigate suspicious activity, verify compliance, support forensic work, and meet regulatory requirements.

### What Purview Audit Captures (and What It Does Not)

Purview Audit records **metadata only**, never the prompt text or the AI generated response.

```text
User Sends a Prompt to Copilot
        │
        ▼
Purview Audit Records Metadata Only
        │
        ▼
User + Time + Service + File + Operation
        │
        ▼
Prompt Text and AI Response Are NOT Captured
```

| Captured | Not Captured |
|---|---|
| User who interacted with Copilot | Prompt text |
| Date and time | AI generated response |
| Microsoft 365 service involved | |
| Files and sites referenced | |
| Administrative units | |
| Operation performed | |

To review the **actual content** of a Copilot interaction, use a dedicated tool instead:

* Microsoft Purview Data Security Posture Management (DSPM)
* Microsoft Purview Communication Compliance
* Microsoft Purview eDiscovery

### Friendly Name vs Operation Name

| Term | Definition | Example |
|---|---|---|
| Friendly Name | Human readable label shown in the Audit UI | Interacted with Copilot |
| Operation Name | Internal event name used by the audit engine | `CopilotInteraction` |

### Worked Example: Healthcare Compliance Review

A hospital enables Copilot to help staff summarize patient documentation. The compliance team wants assurance that sensitive data is handled correctly, only authorized users touch patient data through Copilot, and every interaction is logged. The analyst opens Purview Audit, searches **Interacted with Copilot** activities, filters by date range, reviews specific users, checks referenced files and sites, investigates anomalies, and documents findings.

> Takeaway: Copilot auditing supports compliance verification and anomaly detection; it does not store conversation content, so content level review requires DSPM, Communication Compliance, or eDiscovery.

### SC-200 Exam Tips

* Purview Audit captures **metadata**, not conversation content, for Copilot interactions.
* The primary activity is **Interacted with Copilot**; its operation name is **CopilotInteraction**.
* Search from **Microsoft Purview → Solutions → Audit**.
* Filters available: date range, keywords, administrative units, users, activities, record types, and files, folders, or SharePoint sites.
* Copilot auditing is used mainly for compliance, insider threat investigation, and forensic analysis, not real time threat detection.

## Investigating with Audit (Premium): MailItemsAccessed

### What Audit (Premium) Adds

Audit (Premium) extends Audit (Standard) with capabilities aimed at deeper investigations: forensic analysis, detecting suspicious user behavior, investigating compromised accounts, analyzing mailbox access, reviewing richer audit records, and responding to incidents faster.

### MailItemsAccessed

**MailItemsAccessed** is a Premium only event and one of the most exam relevant items in this module. It records how, when, and in which mailbox emails were accessed, which is essential for investigating **Business Email Compromise (BEC)**, insider threats, sensitive email exposure, and data exfiltration.

> Knowing someone signed in to a mailbox is not enough. Analysts need to know which emails were opened, whether sensitive content was viewed, whether the mailbox was synchronized, and whether data was downloaded. MailItemsAccessed answers these questions.

### Sync Access vs Bind Access

| Aspect | Sync Access | Bind Access |
|---|---|---|
| Trigger | Email client synchronizes the mailbox | A single email is opened or interacted with |
| Typical clients | Outlook, Outlook for Mac, mobile mail apps | Any client opening one message |
| Volume per event | Many emails in one operation | One email per event |
| Audit events generated | **One event** for the whole sync session | **One event per email** |
| Subject to throttling | No | Yes |

```text
Outlook Client Opens
        │
        ▼
Downloads Thousands of Emails
        │
        ▼
One Sync Audit Event
```

```text
User Opens a Single Email
        │
        ▼
One Bind Audit Event
```

### Managing Audit Log Volume: Throttling

To protect Exchange Online performance, Microsoft throttles **MailItemsAccessed bind events**:

* Triggered when a mailbox logs more than **1,000 bind events within 24 hours**.
* Affects **less than 1%** of mailboxes.
* Only **bind** events are affected; **sync** events and all other audit activities continue normally.
* Throttling can create gaps where some bind events are not recorded.

> Exam trap: throttling never touches sync events, only bind events past the 1,000 in 24 hours threshold.

### SC-200 Exam Tips

* Audit (Premium) extends Audit (Standard) with longer retention, richer records, Intelligent Insights, and higher API capacity.
* Default retention for supported services is **1 year**, extendable to **10 years** with the right add on.
* **MailItemsAccessed** is the key event for Exchange Online mailbox access investigations.
* Sync logs a synchronization session; Bind logs an individual email open.
* Compare **ClientIPAddress**, **SessionId**, **LogonType**, **ClientInfoString**, **MailboxUPN**, and **MailAccessType** to separate legitimate activity from unauthorized access.
* Audit (Premium) filters duplicate records within the same hour when properties have not changed significantly, to cut volume without losing forensic value.

## Exporting Audit Log Data

### Export Basics

* Both Audit (Standard) and Audit (Premium) can export to **CSV**.
* A single export is capped at **50,000 records**; narrow the search or split it into multiple exports if more results are returned.
* The **AuditData** column holds detailed event information as **JSON**.
* Use Excel **Power Query** (**Data → From Text/CSV → Transform Data**) to expand **AuditData** into readable columns, clicking **Load more** if not every property appears at first.
* Use **Search-UnifiedAuditLog** for scripted or automated exports.
* Filter by **RecordType** and **Operations** to focus an export on specific workloads and activities.

### Memory Trick

```text
Audit Search (max 50,000 records)
        │
        ▼
Export to CSV
        │
        ▼
AuditData Column Holds JSON
        │
        ▼
Power Query Expands the JSON
        │
        ▼
Search-UnifiedAuditLog Automates It All
```

> "**50K → CSV → JSON → Power Query → PowerShell**"

### SC-200 Exam Tips

* Know the export cap: **50,000 records** per export.
* **AuditData** is JSON; Power Query is the standard way to flatten it in Excel.
* **Search-UnifiedAuditLog** is the automation and SIEM friendly path, not the portal.

## Configuring Audit Retention with Audit (Premium)

### Audit Log Retention Policies

An **Audit Log Retention Policy** defines how long Purview keeps specific audit records before permanent deletion. With the right licensing, retention can extend up to **10 years**. A policy can target:

* One or more Microsoft 365 services, or specific activities within a service
* All users, or selected users only
* Different record types
* Different retention durations
* Different priorities when multiple policies could apply

### Policy Priority

Multiple policies can be active at once; a conflict only needs resolving when more than one policy matches the same record. Audit (Premium) resolves conflicts using **Priority**, where **lower numbers win**.

| Scenario | Policy A | Policy B | Outcome |
|---|---|---|---|
| Only one policy matches (Teams users, priority 100, 5 year retention) | Applies | Not applicable | Record retained **5 years**; no comparison needed |
| Two policies match (Alice is a Finance user on Teams) | Applies to Teams users, priority 100, 1 year retention | Applies to Finance users, priority 10, 7 year retention | **Policy B wins** because priority 10 is lower than 100; record retained **7 years** |

> A tenant can hold up to **50 retention policies**, and Microsoft checks every new audit record against all of them.

### Key Cmdlets

| Cmdlet | Purpose |
|---|---|
| `New-UnifiedAuditLogRetentionPolicy` | Create a policy |
| `Get-UnifiedAuditLogRetentionPolicy` | View policies |
| `Set-UnifiedAuditLogRetentionPolicy` | Modify a policy |
| `Remove-UnifiedAuditLogRetentionPolicy` | Delete a policy |

### Memory Trick

```text
Up to 10 Years Maximum Retention
        │
        ▼
Up to 50 Retention Policies per Tenant
        │
        ▼
Lowest Priority Number Wins on Overlap
        │
        ▼
Default Policy Covers Core Workloads for 1 Year
        │
        ▼
Retention Length Is Fixed at Record Creation Time
```

> "**10 Years → 50 Policies → Priority 1 Wins → Default 1 Year → Retention Fixed at Record Creation**"

### SC-200 Exam Tips

* Audit (Premium) supports custom retention policies; Audit (Standard) does not.
* The built in default policy retains Entra ID, Exchange, OneDrive, and SharePoint logs for **1 year** and **cannot be modified**.
* Custom policies override the default policy when they apply.
* Policies can target services, activities, users, record types, and durations.
* Lower priority number equals higher precedence.
* Maximum of **50** retention policies per tenant.
* Retention beyond **180 days** needs Microsoft 365 E5, Office 365 E5, or an equivalent add on.
* **10 year** retention needs the dedicated **10-Year Audit Log Retention Add-on**.
* Retention is fixed at **record creation time**; later policy or license changes are not retroactive.

## SC-200 Last Minute Revision

### One Page Cheat Sheet: Key Numbers

| Number | What It Means |
|---|---|
| 180 days | Default retention, Audit (Standard) |
| 1 year | Default retention for Entra ID, Exchange Online, SharePoint Online, OneDrive under Audit (Premium) |
| 10 years | Maximum retention with the 10-Year Audit Log Retention Add-on |
| 50 | Maximum retention policies per tenant |
| 50,000 | Maximum records per search export |
| 10 | Maximum concurrent search jobs per user |
| 30 days | How long completed search jobs remain available |
| 60 minutes | Delay before general audit events appear after enabling auditing |
| 24 hours | Delay before MailItemsAccessed and Send events start logging after Advanced Auditing is enabled |
| 1,000 bind events / 24 hours | Threshold that triggers MailItemsAccessed throttling |
| Under 1% | Share of mailboxes affected by throttling |
| 14 to 30 days | Typical soft delete recovery window |

### Frequently Confused Concepts

| Concept A | Concept B | How to Tell Them Apart |
|---|---|---|
| Activity Type | Record Type | Activity Type is the action; Record Type is the service that produced the event |
| Friendly Name | Operation Name | Friendly Name is shown in the UI (Interacted with Copilot); Operation Name is the internal event id (CopilotInteraction) |
| Sync access | Bind access | Sync covers many emails in one event; Bind covers one email per event, and only Bind can be throttled |
| Audit Manager | Audit Reader | Both can search and export; only Audit Manager can change settings |
| Audit (Standard) | Audit (Premium) | Premium adds MailItemsAccessed, custom retention policies, Intelligent Insights, and longer default retention |
| Soft delete | Hard delete | Soft deleted items usually recover in 14 to 30 days; hard deleted items need a hold or retention policy |
| Purview Audit | Sentinel or Defender XDR | Purview Audit is a compliance and forensic log; Sentinel and Defender XDR generate real time alerts and incidents |

### Service Relationships to Remember

```text
Microsoft 365 Activity
        │
        ▼
Unified Audit Log (Purview Audit)
        │
        ▼
Office 365 Management Activity API
        │
        ▼
Microsoft Sentinel Office 365 Data Connector
        │
        ▼
Analytics Rules, Incidents, Investigation
```

> Purview Audit is the compliance grade record of what happened. Sentinel and Defender XDR are where that activity, alongside signals from other sources, gets correlated into detections and incidents.
