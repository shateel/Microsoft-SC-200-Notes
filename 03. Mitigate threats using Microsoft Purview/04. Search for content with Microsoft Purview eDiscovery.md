## Overview of Microsoft Purview eDiscovery

**Microsoft Purview eDiscovery** is a tool that helps organizations **find, preserve, collect, review, and export** electronically stored information (ESI) across Microsoft 365 services.

> The "e" stands for electronic; Discovery means finding evidence. eDiscovery equals Electronic Discovery.

**SC-200 style definition:** Microsoft Purview eDiscovery is a compliance and investigation tool that searches for electronically stored information across Microsoft 365 services.

### Primary Use Cases

* Security investigations
* Insider threat investigations
* HR investigations
* Legal investigations
* Compliance investigations
* Regulatory requests
* Litigation

### What eDiscovery Lets Authorized Users Do

* Create investigation cases
* Search for content across Microsoft 365 workloads
* Preserve evidence
* Review collected data
* Export search results for legal or forensic purposes

Available features depend on the organization's Microsoft 365 license; advanced capabilities may need higher tier licensing.

### Microsoft 365 Services eDiscovery Can Search

| Service | What It Stores |
|---|---|
| Exchange Online | Email and calendars |
| SharePoint Online | Team sites and document libraries |
| OneDrive for Business | Personal cloud file storage |
| Microsoft Teams | Chat, meetings, channels, collaboration |
| Microsoft Entra ID | Identity and authentication |
| Microsoft Viva Engage (Yammer) | Enterprise social networking |
| Microsoft Planner, Forms, Loop | Task, form, and collaborative content |
| Microsoft Copilot for Microsoft 365 | Copilot related content |

### Why eDiscovery Matters: Audit Logs Are Not Enough

**Audit** logs answer activity questions: who accessed a file, when, and from which IP address. They do not show the content itself. Investigators often also need to know what was inside an email, which document was shared, what message was sent in Teams, or which files held sensitive information. **eDiscovery retrieves that content.**

> Frequently confused concept: **Audit** records the **activity**. **eDiscovery** retrieves the **actual content**. Use Audit to see that something happened; use eDiscovery to see what was actually said or shared.

### Licensing and Access

Only users with the right Microsoft Purview permissions can use eDiscovery. Common roles are **eDiscovery Manager** and **eDiscovery Administrator**, which grant access to **eDiscovery → Cases**, where investigations are created and managed.

### SC-200 Exam Tips

* eDiscovery is used to **search, preserve, review, and export** Microsoft 365 content.
* Main use cases: security investigations, insider risk investigations, legal discovery, regulatory compliance, and incident response.
* An **eDiscovery Case** is the central workspace for an investigation.
* eDiscovery can search **Exchange Online, SharePoint Online, OneDrive, and Microsoft Teams**, among other workloads.
* **Audit** shows activity; **eDiscovery** retrieves content. Know this distinction cold.
* Core capabilities are included with **Microsoft 365 E3 and E5**; advanced features may need extra licensing.
* Always verify both **permissions** and **licensing** before starting an investigation.
* Memorize the flow: **Alert → Audit Logs → eDiscovery Case → Content Search → Preserve Evidence → Review → Export.**

## Prerequisites: Licensing and eDiscovery Roles

### eDiscovery Manager

Intended for investigators doing day to day investigation work. Permissions include:

* Create eDiscovery cases
* Manage investigation cases
* Run content searches
* View search results
* Export search results

This role is sufficient for most SOC analysts, compliance investigators, and legal investigators.

### eDiscovery Administrator

Includes every **eDiscovery Manager** permission, plus administrative capabilities:

* Manage eDiscovery role assignments
* Configure role settings
* Manage all eDiscovery cases across the organization

Typically assigned to security administrators or compliance administrators who manage the whole eDiscovery environment.

| Role | Create / Run Searches | Manage Own Cases | Manage Role Assignments | Manage All Cases Org Wide |
|---|---|---|---|---|
| eDiscovery Manager | Yes | Yes | No | No |
| eDiscovery Administrator | Yes | Yes | Yes | Yes |

### SC-200 Exam Tips

* **eDiscovery Manager**: day to day investigator role, case level access.
* **eDiscovery Administrator**: everything a Manager has, plus org wide case management and role assignment.
* Assigning the right role is a licensing and access control decision the exam expects you to reason through, not just memorize.

## Creating an eDiscovery Case and Search

### Why Every Search Needs a Case

Every eDiscovery search must belong to an **eDiscovery case**. The case is the investigation workspace that stores searches, holds, exported data, and investigation information, which keeps every investigation organized, secure, and fully auditable.

> An eDiscovery case is more than a folder; it is the investigation workspace that keeps all evidence and actions organized. A case provides controlled access to investigation data, an audit trail of search and export activity, and a structured workspace for managing the investigation.

### Case Membership

The user who creates the case automatically becomes a **case member**. Every other investigator must be added manually.

> Exam trap: having the correct eDiscovery role is not enough. A user cannot access a case unless they are also a member of that specific case.

### Required Permissions

To create and run an eDiscovery search, the user must hold one of:

* eDiscovery Manager
* eDiscovery Administrator

### Two Ways to Create a Search

| Method | What It Does | When to Use |
|---|---|---|
| Method 1: Create a Search Directly | Creates the **case and the search in one step** | Starting a brand new investigation |
| Method 2: Create a Search Through an Existing Case | Adds a **new search to a case that already exists** | Continuing or expanding an existing investigation |

**Method 1 steps:** open Microsoft Purview, go to **Solutions → eDiscovery → Cases**, select the arrow beside **Create case**, choose **Create search**, enter the case name and search name (descriptions optional), then select **Create**.

**Method 2 steps:** open **Solutions → eDiscovery → Cases**, select **Create case**, enter the case name and optional description, create the case, open the **Searches** tab, select **Create search**, enter the search name and optional description, then create the search.

> Creating a search does not run it. You still need to configure search criteria and run the search separately.

### SC-200 Exam Tips

* Every eDiscovery search must belong to an eDiscovery case.
* A case gives controlled access, an auditable record of activity, and a structured investigation workspace.
* Only **eDiscovery Manager** or **eDiscovery Administrator** can create cases and searches.
* The case creator is automatically a case member; everyone else must be added manually.
* Two creation paths exist: case and search together, or search added to an existing case.
* Creating a search is not the same as running it.
* Use descriptive case names, search names, and descriptions to keep investigations manageable for a team.

## Conducting an eDiscovery Search

### The Four Phases

```text
Define Search Criteria
     │
     ▼
Identify Data Sources
     │
     ▼
Build the Query
     │
     ▼
Run and Review the Results
```

### Supported Microsoft 365 Workloads

* Exchange Online
* SharePoint Online
* OneDrive for Business
* Microsoft Teams
* Microsoft 365 Groups
* Viva Engage

Select only the data sources actually needed; this improves search performance and reduces noise. Common data sources are users, groups, SharePoint sites, OneDrive accounts, and Teams. Use **Add tenant-wide sources** only when the investigation genuinely needs to search the entire organization.

### Building the Query: Condition Builder vs KQL

| Approach | Description | Skill Needed |
|---|---|---|
| Condition Builder | Build search logic through a visual interface | No query language required |
| KQL (Keyword Query Language) | Write precise, advanced search filters directly | Query syntax knowledge |

> Important exam distinction: this **KQL** (Keyword Query Language, used in eDiscovery content search) is a completely different language from the **KQL** (Kusto Query Language) used in Microsoft Sentinel and Log Analytics. They share an abbreviation only. Do not mix up their syntax on the exam.

Common search conditions:

* Date
* Subject / Title
* Participants
* Type
* Keywords (KeyQL/KQL)

Multiple conditions are combined with **AND**, so returned content must satisfy every condition specified.

| Operator | Meaning |
|---|---|
| Equals | Exact match |
| Contains | Value appears within the field |
| Starts With | Field begins with the given value |

> Microsoft Security Copilot can generate KeyQL queries from natural language prompts (Preview), which is useful when an analyst knows what they want but not the exact syntax.

### Search by File (Preview)

**Search by file** lets you upload a reference file so Purview can find similar or related content automatically.

| Rule | Detail |
|---|---|
| Supported formats | `.txt` (find similar content) or `.csv` (find reference content) |
| Maximum size | 10 MB |
| Effect on other tools | KQL and the Condition Builder are disabled while Search by file is active |

### Validating and Iterating

After running a query, review **Statistics** for item counts, result size, and a location breakdown. Review the **Sample** results to confirm the criteria are correct before exporting. If results look wrong, refine the conditions or data sources and rerun the search.

> For the exam: eDiscovery searching is an iterative process. Adjusting filters, sources, or queries and rerunning the search multiple times is normal, not a sign of doing it wrong.

Once results are validated, export the evidence or add it to a Review Set.

### SC-200 Exam Tips

* Know the four phases: define criteria, identify data sources, build the query, run and review results.
* Selecting fewer, more relevant data sources improves performance; **Add tenant-wide sources** is for organization wide investigations only.
* Condition Builder needs no query language; KQL (Keyword Query Language) supports advanced precise filtering.
* Multiple search conditions combine with **AND** logic.
* Know the three operators: Equals, Contains, Starts With.
* Search by file supports `.txt` or `.csv`, capped at 10 MB, and disables KQL and the Condition Builder while active.
* Review Statistics and Sample results before exporting; treat searching as iterative.

## Exporting eDiscovery Search Results

### Choosing What to Export

| Option | What It Includes | Speed | Typical Use |
|---|---|---|---|
| Only indexed items that matched the search query | Searchable items matching the search conditions | Fastest | Most investigations |
| Indexed items and partially indexed items | Searchable items plus items that could not be fully indexed | Slower | Maximum evidence coverage |
| Only partially indexed items | Items that were not fully processed | Slowest, least common | Investigating indexing problems or recovering missed evidence |

### Export Details by Workload

| Workload | Export Options |
|---|---|
| SharePoint and OneDrive | Latest version only, multiple versions, all versions, subfolder items, SharePoint list attachments |
| Exchange Online and Microsoft Teams | Export conversations as HTML transcripts, include contextual Teams and Viva Engage conversations, include cloud attachments stored in SharePoint or OneDrive |

Mailbox data can be exported as **PST** or **MSG** files. Export options can also preserve original folder structure, source location, and friendly item names.

### Monitoring and Downloading

The **Process Manager** monitors export status, completion time, number of items, and the export options used. Once complete, download the export package from the **Exports** tab. Packages commonly include PST or MSG files, item reports, and export reports.

### Export Workflow

```text
Validate Search
     │
     ▼
Configure Export
     │
     ▼
Start Export
     │
     ▼
Monitor Process
     │
     ▼
Download Export Package
```

### SC-200 Exam Tips

* Exporting is the **final step**, after validating the search results.
* Export packages contain both **content and metadata**.
* Always verify results are accurate before exporting.
* Choose **Indexed items only** for standard investigations; add **partially indexed items** when maximum coverage matters; use **partially indexed items only** when troubleshooting indexing issues.
* Know the workload specific export options for SharePoint/OneDrive versus Exchange Online/Teams.
* Mailbox exports use **PST** or **MSG** format.
* The **Process Manager** tracks export progress; completed packages download from the **Exports** tab.
* Memorize the workflow: **Validate Search → Configure Export → Start Export → Monitor Process → Download Export Package.**

### Frequently Confused Concepts

| Concept A | Concept B | How to Tell Them Apart |
|---|---|---|
| Audit | eDiscovery | Audit shows the activity happened; eDiscovery retrieves the actual content |
| eDiscovery Manager | eDiscovery Administrator | Administrator has every Manager permission plus role assignment and org wide case management |
| KQL, Keyword Query Language (eDiscovery) | KQL, Kusto Query Language (Sentinel) | Same abbreviation, unrelated syntax and purpose; do not confuse them on the exam |
| Condition Builder | KQL search | Condition Builder is visual and code free; KQL gives precise, advanced filtering |
| Indexed items only | Indexed plus partially indexed | The first is fast and standard; the second maximizes coverage at the cost of speed |
| Creating a search | Running a search | Creating configures it; you must still run it to get results |
