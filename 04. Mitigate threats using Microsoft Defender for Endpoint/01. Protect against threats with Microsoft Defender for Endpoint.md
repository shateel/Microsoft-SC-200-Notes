## Overview

**Microsoft Defender for Endpoint (MDE)** is a cloud based endpoint security platform that protects **Windows, macOS, Linux, Android, and iOS** devices across the entire attack lifecycle.

> Unlike traditional antivirus, which mainly blocks known malware, MDE continuously monitors endpoint activity, detects suspicious behavior, investigates attacks, and supports both automated and manual response.

**Primary objectives:**

* Prevent malware infections
* Detect attacks that bypass traditional antivirus
* Investigate suspicious activity
* Respond automatically or manually to threats
* Reduce attack surfaces
* Continuously assess endpoint vulnerabilities

### SC-200 Exam Tips

* MDE is Microsoft's **Endpoint Detection and Response (EDR)** platform, but it does far more than EDR alone; it spans prevention, detection, investigation, and response.
* Know the five supported platforms: Windows, macOS, Linux, Android, iOS.

## Core Technologies

MDE relies on three major technologies that work together.

### 1. Endpoint Behavioral Sensors

Built directly into Windows 10 and later, these sensors continuously monitor endpoint activity rather than relying only on malware signatures. Collected signals include process creation, file activity, registry modifications, network connections, user activity, and security events.

Telemetry is **not stored locally**; it is transmitted securely to the organization's isolated MDE cloud instance. This behavioral approach detects things like PowerShell abuse, credential dumping, suspicious process execution, lateral movement, and privilege escalation.

> These sensors are the foundation of EDR.

### 2. Cloud Security Analytics

Telemetry is analyzed in Microsoft's cloud using big data analytics, machine learning, AI, and Microsoft threat intelligence, correlated with signals from the wider Windows ecosystem, Microsoft 365, and other Microsoft cloud services.

Rather than analyzing a single event, Microsoft correlates **millions of events across customers** to judge whether activity is malicious, turning raw signals into insights, detections, incidents, and recommended remediation actions. Because this runs in the cloud, detection logic improves continuously without requiring endpoint software updates.

### 3. Threat Intelligence

Generated by Microsoft security researchers, threat hunters, incident response teams, security partners, and global intelligence providers. It captures knowledge of attacker tools, malware families, and **Tactics, Techniques, and Procedures (TTPs)**.

Because detections are matched against this intelligence, MDE can generate alerts even for malware never seen before, enabling detection of:

* Zero day attacks
* Advanced Persistent Threats (APTs)
* Living off the land attacks
* Fileless malware

### SC-200 Exam Tips

* Three technologies to memorize: **Behavioral Sensors, Cloud Security Analytics, Threat Intelligence.**
* Behavioral telemetry goes to the cloud; it is not analyzed only on the device.
* Threat intelligence is what enables detection of attacks that have **never been seen before** (zero day, fileless, living off the land).

## MDE Architecture: The Six Pillars

All MDE capabilities are managed through centralized administration and APIs, and operate as part of the **Microsoft Defender XDR** platform.

| Pillar | Purpose |
|---|---|
| Core Defender Vulnerability Management | Discovers vulnerabilities, misconfigurations, and prioritizes remediation |
| Attack Surface Reduction (ASR) | Reduces opportunities for attackers before exploitation |
| Next-Generation Protection (NGAV) | Prevents malware using cloud intelligence and machine learning |
| Endpoint Detection and Response (EDR) | Detects, investigates, and responds to advanced attacks |
| Automated Investigation and Remediation (AIR) | Automatically investigates and remediates confirmed threats |
| Microsoft Threat Experts | Provides expert managed threat hunting and investigation support |

> **Core Defender Vulnerability Management** uses a modern risk based approach: discover vulnerabilities, assess risk, prioritize remediation, recommend corrective action. It is built into MDE and does **not** require a separate vulnerability scanner.

### SC-200 Exam Tips

* Memorize the six pillars and be able to match a scenario description to the correct pillar.
* Quick distinction:
    * **NGAV** prevents malware.
    * **EDR** detects, investigates, and responds after suspicious activity occurs.
    * **ASR** reduces attack opportunities before exploitation.
    * **AIR** automates investigation and remediation.
    * **Threat Intelligence** enriches detections with known attacker context.

## Threat and Vulnerability Management (TVM)

TVM is Microsoft's built in vulnerability management capability inside MDE. Unlike traditional scanners that rely on scheduled scans, **TVM continuously monitors devices in real time using built in sensors**, without requiring a separate scanning agent.

It evaluates devices for:

* Missing security updates
* Vulnerable or unsupported applications
* Security configuration weaknesses
* Operating system vulnerabilities
* Security control misconfigurations

Risk prioritization considers severity, active exploitation in the wild, threat intelligence, device exposure, business importance, sensitive data presence, and likelihood of attack.

### Exposure Score and Configuration Score

| Metric | What It Measures |
|---|---|
| **Exposure Score** | Overall organizational cybersecurity risk from endpoint vulnerabilities and weaknesses. Higher score means more vulnerable devices, greater attack opportunity, and greater risk. Decreases as vulnerabilities are remediated. |
| **Configuration Score** | How securely devices are configured against security baselines. |

The TVM dashboard also shows device exposure, severity distribution, top vulnerable software, and active remediation tasks.

### TVM Workflow

```text
Sensors collect endpoint data
      │
      ▼
Defender identifies installed software and configuration
      │
      ▼
Vulnerabilities and misconfigurations detected in real time
      │
      ▼
Cloud intelligence evaluates severity and exploitability
      │
      ▼
Risk scores assigned and remediation prioritized
      │
      ▼
Security recommendations generated
      │
      ▼
Administrator remediates (manually, or via Intune / Endpoint Manager)
      │
      ▼
Risk scores recalculated
```

### Security Recommendations and Remediation

Examples of recommendations: update vulnerable applications, install missing patches, enable ASR rules, enable Microsoft Defender Antivirus, configure BitLocker, enable Credential Guard, fix sensor communication problems, configure Controlled Folder Access.

Each recommendation shows affected device count, severity, related threats, security impact, and expected exposure score reduction.

TVM integrates directly with **Microsoft Intune** and **Microsoft Endpoint Manager**, letting administrators raise remediation requests straight from Defender for Endpoint instead of updating every device manually.

### SC-200 Exam Tips

* TVM does **not** depend on periodic, agent based scans; it is continuous and sensor driven.
* Know the difference: **Exposure Score** (risk) versus **Configuration Score** (secure configuration adherence).
* TVM remediation flows through **Intune** or **Endpoint Manager**.

## Attack Surface Reduction (ASR)

ASR is a **preventive** capability designed to stop attacks before malware executes, by blocking common attack techniques rather than detecting malware afterward. Its goal is to reduce the number of ways an attacker can compromise a device.

| ASR Component | Function |
|---|---|
| Hardware-based Isolation | Isolates browser and sensitive processes using virtualization based security |
| Application Control | Allows only trusted applications to run |
| Exploit Protection | Mitigates exploitation techniques such as memory corruption |
| Network Protection | Blocks access to malicious and phishing websites |
| Controlled Folder Access | Prevents unauthorized changes to protected folders; main defense against ransomware |
| Attack Surface Reduction Rules | Block specific risky behaviors, e.g. Office applications spawning child processes |
| Microsoft Defender Firewall | Host based firewall control |

### SC-200 Exam Tips

* If an exam scenario mentions **ransomware protecting specific folders**, the answer is **Controlled Folder Access**.
* If it mentions **Office apps launching scripts or child processes**, think **Attack Surface Reduction Rules**.
* ASR is about **prevention before execution**, not detection after the fact.

## Next-Generation Protection (NGP / NGAV)

Next-Generation Protection is Microsoft's advanced antivirus capability. It combines traditional antivirus with Cloud-delivered protection, machine learning, artificial intelligence, the Intelligent Security Graph, and behavioral monitoring, allowing detection of both known and previously unseen threats much faster than signature only antivirus.

**Microsoft Defender Antivirus** is the underlying antivirus engine that provides NGAV capabilities.

### SC-200 Exam Tips

* NGAV = **prevention focused**, powered by cloud intelligence rather than signatures alone.
* Do not confuse NGAV (prevents malware) with EDR (detects and investigates after suspicious activity occurs).

## Endpoint Detection and Response (EDR) and Automated Investigation and Remediation (AIR)

EDR continuously records endpoint telemetry (processes, registry changes, network activity, sign ins, file activity, memory events) so analysts can investigate advanced attacks.

| Term | Definition |
|---|---|
| **Alert** | A single detection of suspicious activity |
| **Incident** | A collection of related alerts representing one attack |

**AIR (Automated Investigation and Remediation)** automatically investigates alerts and remediates confirmed threats: it can quarantine malicious files, stop malicious processes, and mark investigations as remediated.

The **Security Operations Dashboard** gives visibility into alerts, investigations, devices at risk, users at risk, and automated investigations.

Additional technical detail worth remembering: the MDE sensor runs under the **LocalSystem** account and communicates using **WinHTTP** (not WinINet), so WinHTTP proxy settings apply independently of browser proxy settings.

### Layered Security Workflow

```text
TVM
 │
 ▼
ASR
 │
 ▼
NGAV
 │
 ▼
EDR
 │
 ▼
AIR
```

### SC-200 Exam Tips

* An **incident groups related alerts**; do not treat alert and incident as the same thing.
* Memorize the layered workflow order: **TVM → ASR → NGAV → EDR → AIR**.
* Remember the sensor runs as **LocalSystem** and uses **WinHTTP**, a detail that has appeared in exam style questions about proxy configuration.

## Advanced Hunting

**Advanced Hunting** is a query based investigation feature in Microsoft Defender XDR and MDE that lets analysts search endpoint telemetry proactively, rather than waiting for an alert.

It allows analysts to:

* Search across endpoint telemetry
* Investigate suspicious activity and ongoing incidents
* Hunt for Indicators of Compromise (IOCs)
* Identify attacker techniques and hidden threats
* Validate threat intelligence
* Detect attacks that predefined rules may have missed
* Build custom detection rules

**Location:** Microsoft Defender Portal → Hunting → Advanced Hunting. This opens the query editor where analysts write and run **KQL (Kusto Query Language)** against Defender telemetry.

> Advanced Hunting is proactive: the analyst decides what to search for, instead of relying only on automated alerts.

**Example KQL pattern** (illustrative, not from the source material, added for exam practice) to hunt for suspicious PowerShell activity:

```kql
DeviceProcessEvents
| where FileName =~ "powershell.exe"
| where ProcessCommandLine has_any ("EncodedCommand", "DownloadString", "IEX")
| project Timestamp, DeviceName, AccountName, ProcessCommandLine
| order by Timestamp desc
```

Useful tables to know for the exam: `DeviceProcessEvents`, `DeviceNetworkEvents`, `DeviceFileEvents`, `DeviceRegistryEvents`, `DeviceLogonEvents`.

### SC-200 Exam Tips

* Advanced Hunting = **proactive, query driven** investigation, distinct from alert driven, reactive monitoring.
* Custom Advanced Hunting queries can be saved and converted into **custom detection rules**.
* Know the query language name: **KQL**.

## End to End Workflow: How MDE Works

1. A device (Windows, macOS, Linux, Android, or iOS) is onboarded to MDE.
2. The built in sensor continuously collects telemetry: process creation, file activity, registry changes, network connections, user sign ins, PowerShell and script execution.
3. Telemetry is securely sent to the Microsoft Defender cloud.
4. Microsoft analyzes the data using machine learning, behavioral analytics, threat intelligence, and AI/cloud analytics.
5. If suspicious behavior is found, an **alert** is generated, and related alerts are grouped into an **incident**.
6. SOC analysts investigate the incident in the Microsoft Defender portal.
7. Defender can respond automatically by quarantining files, stopping malicious processes, isolating devices, or running AIR.

```text
Windows Device
      │
      ▼
Microsoft Defender for Endpoint Sensor
      │
      ▼
Microsoft Defender for Endpoint Cloud Service
      │
      ▼
Microsoft Defender Portal
      │
      ▼
SOC Analyst
```

### SC-200 Exam Tips

* Be able to reproduce this pipeline from memory: **Device → Sensor → Cloud Service → Portal → SOC Analyst.**
* Response actions to know: **quarantine files, stop malicious processes, isolate devices, run AIR.**

## The Microsoft Defender Cloud Service

This is Microsoft's backend cloud infrastructure that powers MDE, sometimes described as the **brain** of Defender for Endpoint. It receives endpoint telemetry and performs machine learning analysis, AI analysis, threat intelligence correlation, behavioral analytics, detection logic, incident correlation, and alert generation.

### SC-200 Exam Tips

* If an exam question asks **where detection logic and correlation actually happen**, the answer is the Microsoft Defender cloud service, not the local sensor.

## Scenario Walkthrough: 5,000 Windows Laptops

A company with 5,000 Windows laptops sets up MDE as follows: purchase MDE licenses, connect Intune with Defender, create an onboarding policy, deploy the policy to all Windows devices, and devices automatically onboard.

**If ransomware is detected:**

```text
Ransomware behavior detected
      │
      ▼
Alert generated
      │
      ▼
Related alerts grouped into an incident
      │
      ▼
SOC analyst investigates device timeline
      │
      ▼
Device isolated
      │
      ▼
AIR automatically remediates
      │
      ▼
Analyst runs Advanced Hunting for similar activity org wide
```

**Takeaway:** onboarding through Intune plus continuous telemetry plus AIR plus Advanced Hunting together form a complete detect, contain, remediate, and hunt cycle.

## Onboarding and Deployment Methods

| Method | Best Suited For |
|---|---|
| **Microsoft Intune** | Most common method; cloud managed, Microsoft managed environments. Admin creates and assigns an onboarding policy; Intune configures MDE, security settings, and device onboarding automatically. |
| **Microsoft Configuration Manager (SCCM)** | Large enterprises already using Configuration Manager. |
| **Group Policy (GPO)** | On premises Active Directory environments; admin downloads the onboarding package and applies it via GPO. |
| **Local Script** | Testing or small labs; admin downloads and runs a script locally from the Defender portal. |
| **Manual Onboarding** | A small number of individual devices. |

### SC-200 Exam Tips

* **Intune is the preferred, most tested method** for Microsoft managed environments; expect exam scenarios that hint at cloud managed devices to point toward Intune.
* GPO and SCCM both suit **existing on premises infrastructure**, GPO for Active Directory specifically, SCCM for organizations already using Configuration Manager.

## Supplementary Context: MDE, Defender XDR, and Sentinel

This section adds brief, widely documented context beyond the source material, to help position Defender for Endpoint within the broader SC-200 syllabus.

* **Microsoft Defender XDR** is the umbrella extended detection and response platform. MDE is one workload within it, alongside Microsoft Defender for Identity, Microsoft Defender for Office 365, and Microsoft Defender for Cloud Apps. Defender XDR correlates signals across these workloads into unified incidents.
* **Microsoft Sentinel** is Microsoft's cloud native SIEM and SOAR platform. It is separate from Defender XDR but commonly integrated with it: Sentinel can ingest Defender XDR incidents through a connector, correlate them with data from other log sources using KQL based analytics rules, and trigger automated playbooks.
* For the SC-200 exam, understand this relationship at a conceptual level: **MDE protects endpoints and feeds signal upward into Defender XDR; Defender XDR can, in turn, feed incidents into Sentinel for broader, cross source correlation.**

### SC-200 Exam Tips

* Do not confuse **Microsoft Defender XDR** (a correlation and investigation platform across Microsoft security workloads) with **Microsoft Sentinel** (a general purpose, cloud native SIEM/SOAR that ingests data from many sources, Microsoft and non Microsoft alike).

### Frequently Confused Concepts

* **NGAV vs EDR:** NGAV prevents malware before it runs; EDR detects and investigates suspicious activity that has already occurred.
* **Exposure Score vs Configuration Score:** Exposure Score reflects overall vulnerability risk; Configuration Score reflects adherence to secure configuration baselines.
* **Alert vs Incident:** an alert is one detection; an incident is a correlated group of alerts representing a single attack.
* **AIR vs Advanced Hunting:** AIR is automatic, system driven remediation; Advanced Hunting is manual, analyst driven, proactive querying.
* **Defender XDR vs Sentinel:** Defender XDR correlates Microsoft security workloads; Sentinel is a broader SIEM/SOAR that can ingest Defender XDR incidents plus many other data sources.
* **TVM vs traditional vulnerability scanners:** TVM is continuous and sensor based, with no separate scanning agent required, unlike scheduled, agent based scanners.
