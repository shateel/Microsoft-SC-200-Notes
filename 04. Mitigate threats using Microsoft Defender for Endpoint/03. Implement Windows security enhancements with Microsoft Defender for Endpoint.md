## Part 1: Attack Surface Reduction Overview

### 1.1 What Is an Attack Surface

An **attack surface** is every entry point an attacker could use to try to compromise a system.

Common examples of attack surface elements:

1. Vulnerable applications
2. Weak operating system settings
3. Office macros
4. USB devices
5. Network connections
6. Web browsers
7. User credentials
8. File system access

### 1.2 What Is Attack Surface Reduction (ASR)

**Attack Surface Reduction (ASR)** is a collection of Microsoft Defender security technologies that reduce the number of ways an attacker can compromise a device.

Key idea for the exam: ASR is **preventive**, not reactive.

| Traditional Antivirus | Attack Surface Reduction |
|---|---|
| Detects malware after execution or by signature | Hardens the system so risky behavior is blocked before malware executes |
| Reacts to known malicious files | Proactively blocks common attack techniques |
| Single detection layer | Multiple layered protection technologies |

> **Exam Tip:** If a question describes stopping an attack technique before any malicious code runs, think ASR, not signature based antivirus detection.

### 1.3 Relationship Between ASR and Microsoft Defender for Endpoint

ASR is **one of several protection technologies inside Microsoft Defender for Endpoint**. When an ASR component blocks something, that event becomes telemetry that flows into the Microsoft Defender portal for SOC investigation.

```text
Windows Device
      │
      ▼
Attack Surface Reduction (blocks the risky action)
      │
      ▼
Alert Generated
      │
      ▼
Microsoft Defender for Endpoint (collects telemetry)
      │
      ▼
Microsoft Defender Portal
      │
      ▼
SOC Analyst Investigates
```

### 1.4 ASR Protection Technologies at a Glance

The exam frequently asks **"which ASR component protects against X?"** Learn this table cold.

| Component | Primary Purpose | Requires Microsoft Defender Antivirus |
|---|---|---|
| **ASR Rules** | Blocks specific malicious behaviors (macros, scripts, credential theft, etc.) | Yes |
| **Hardware Based Isolation** | Uses Virtualization based security (VBS) to isolate sensitive system components and protect credentials | No |
| **Application Control** | Allows only trusted, explicitly approved applications to run | No |
| **Exploit Protection** | Protects the OS and apps from exploitation techniques; works alongside third party antivirus | No |
| **Network Protection** | Blocks outbound connections to malicious or low reputation network destinations | Yes |
| **Web Protection** | Blocks malicious and phishing websites and unwanted web content categories | No |
| **Controlled Folder Access** | Protects designated folders from ransomware and unauthorized changes | Yes (part of ASR feature set) |
| **Device Control** | Manages removable storage such as USB drives to reduce data loss and block untrusted media | No |

> **Exam Tip:** Memorize the pairing of threat to defense: ransomware → Controlled Folder Access, malicious websites → Web Protection, removable media risk → Device Control, untrusted applications → Application Control, credential isolation → Hardware Based Isolation.

### 1.5 Real World SOC Scenario: Phishing to Ransomware

A user receives a phishing email with a malicious Word document. The document tries to launch PowerShell, download ransomware, and encrypt files.

Outcome when ASR technologies are enabled:

1. **ASR Rules** block Word from launching PowerShell.
2. **Network Protection** blocks the connection to the malicious download server.
3. **Controlled Folder Access** prevents ransomware from modifying protected folders.
4. **Application Control** blocks execution of the untrusted executable.
5. **Device Control** prevents copying sensitive files to an unauthorized USB drive.

**Takeaway:** The phishing email still reached the inbox, but layered ASR protections stopped the attack before compromise, and Microsoft Defender generated alerts for SOC review.

### 1.6 SC-200 Exam Tips (Part 1)

> 1. Attack Surface Reduction reduces the number of ways attackers can compromise a device.
> 2. ASR is preventive and behavior focused, not signature based detection.
> 3. ASR is a **collection** of technologies, not a single feature.
> 4. Hardware Based Isolation uses Virtualization based security (VBS) to protect credentials and isolate sensitive processes.
> 5. Exploit Protection is the one component that explicitly supports third party antivirus.
> 6. Many ASR components (ASR Rules, Network Protection, Controlled Folder Access) require Microsoft Defender Antivirus to be active.
> 7. Expect scenario based questions asking which component stops a specific threat (ransomware, phishing site, rogue USB device, untrusted app).

## Part 2: Attack Surface Reduction Rules

### 2.1 What Are ASR Rules

**ASR Rules** are behavior based security rules that reduce the attack surface of Windows devices by blocking risky actions before malware can execute.

Unlike traditional antivirus signatures, ASR Rules watch for **malicious behavior patterns**, for example:

1. Executable files launched from emails
2. Office applications creating child processes
3. Office applications creating executable content
4. Office applications injecting code into other processes
5. JavaScript or VBScript launching downloaded executable files
6. Obfuscated or suspicious script execution
7. Credential theft attempts
8. Ransomware behaviors
9. Untrusted processes running from USB devices

### 2.2 Why ASR Rules Matter

Attackers frequently abuse **legitimate Windows features** rather than introducing obviously malicious tools. ASR Rules restrict how these legitimate tools can be misused, without blocking normal business use when tuned correctly.

Commonly abused legitimate features:

1. Microsoft Office
2. PowerShell
3. Windows Script Host
4. WMI (Windows Management Instrumentation)
5. PSExec
6. USB devices
7. Signed drivers

### 2.3 ASR Rule States

Each ASR Rule can be set to one of four states.

| State | Effect |
|---|---|
| **Not Configured** | Rule is disabled |
| **Block** | Rule is enabled and actively blocks the behavior |
| **Audit** | Evaluates what would happen if the rule were enabled, without blocking anything |
| **Warn** | Enabled, blocks by default, but lets the end user choose to bypass the block |

> **Exam Tip:** Audit mode never blocks anything. Warn mode blocks but gives the user an override prompt. These two are the most commonly confused states on the exam.

Recommended rollout progression:

```text
Audit Mode
      │
      ▼
Review Impact in Reports
      │
      ▼
Tune Exclusions if Needed
      │
      ▼
Switch to Block (or Warn)
      │
      ▼
Monitor Alerts in Microsoft Defender for Endpoint
```

### 2.4 Common ASR Rules by Category

| Category | Rule Behavior Blocked |
|---|---|
| Email and Web | Block executable content from email clients and webmail |
| Office Macros and Scripts | Block Office applications from creating child processes |
| Office Macros and Scripts | Block Office applications from creating executable content |
| Office Macros and Scripts | Block Office applications from injecting code into other processes |
| Office Macros and Scripts | Block Win32 API calls from Office macros |
| Office Macros and Scripts | Block Office communication applications from creating child processes |
| Scripts | Block JavaScript or VBScript from launching downloaded executable content |
| Scripts | Block execution of obfuscated scripts |
| Credential Theft | Block credential stealing from the Windows Local Security Authority Subsystem (LSASS) |
| Ransomware | Use advanced protection against ransomware |
| Lateral Movement / Admin Tools | Block process creation originating from PSExec and WMI commands |
| Lateral Movement / Admin Tools | Block persistence through WMI event subscription |
| Removable Media | Block untrusted or unsigned processes running from USB |
| Application Trust | Block executable files unless they meet prevalence, age, or trusted list requirements |
| Application Specific | Block Adobe Reader from creating child processes |
| Drivers | Block abuse of exploited vulnerable signed drivers |

> **Exam Tip:** You do not need every rule memorized word for word, but you should be able to recognize the **category** a described behavior belongs to (macro abuse, script abuse, credential theft, lateral movement, removable media, driver abuse).

### 2.5 Excluding Files and Folders

Legitimate business applications can sometimes trigger ASR Rules. Administrators can configure **ASR exclusions** for:

1. Specific files
2. Specific folders
3. Applications identified by certificate or file hash

Excluded applications are skipped by most ASR Rules.

> **Exam Tip:** Exclusions should be kept to a minimum. Overusing exclusions weakens endpoint protection and is a common wrong answer trap (do not treat exclusions as a "fix everything" setting).

### 2.6 Audit Mode Deployment Strategy

Microsoft recommends deploying ASR Rules in **Audit Mode first**, then moving to Block.

Benefits of Audit Mode:

1. Identify applications affected by the rules
2. Evaluate business impact before enforcement
3. Reduce disruption to normal operations
4. Fine tune exclusions if required

After confirming legitimate applications are unaffected, administrators switch the rule from Audit to Block.

### 2.7 ASR Events and Logging

When an ASR Rule triggers, an event is recorded locally in **Windows Event Viewer**.

Location:

**Applications and Services Logs → Microsoft → Windows**

These events are valuable forensic evidence and are also visible centrally in the **Microsoft Defender portal** for investigation.

### 2.8 Managing ASR Rules with PowerShell

| Cmdlet | Behavior |
|---|---|
| `Set-MpPreference` | **Overwrites** the current ASR configuration |
| `Add-MpPreference` | **Appends** new rules or exclusions without removing existing ones |

General syntax pattern for setting a rule's action:

```text
Add-MpPreference -AttackSurfaceReductionRules_Ids <RuleGUID> -AttackSurfaceReductionRules_Actions Enabled
```

Common action values used with ASR Rule cmdlets:

| Action Value | Meaning |
|---|---|
| `Disabled` | Not Configured / rule off |
| `Enabled` | Block mode |
| `AuditMode` | Audit mode |
| `Warn` | Warn mode |

To add a folder or application exclusion:

```text
Add-MpPreference -AttackSurfaceReductionOnlyExclusions "<path or file>"
```

> **Exam Tip:** Remember the verb difference: **Set** replaces the whole configuration, **Add** appends to it. This distinction is a classic SC-200 trick question.

### 2.9 Supported Deployment Methods

ASR Rules can be deployed at scale using:

1. Microsoft Intune
2. Mobile Device Management (MDM)
3. Microsoft Endpoint Configuration Manager (MECM)
4. Group Policy
5. PowerShell

### 2.10 Real World SOC Scenario: Coordinated ASR Defense

A user opens a phishing email with a malicious Word document. The document tries to launch PowerShell, download ransomware, steal Windows credentials, and execute additional malware from a USB drive.

With ASR Rules configured:

1. **Block Office applications from creating child processes** stops Word from launching PowerShell.
2. **Block JavaScript/VBScript from launching downloaded executables** stops the malware download.
3. **Use advanced protection against ransomware** prevents unauthorized file encryption.
4. **Block credential stealing from LSASS** stops credential extraction attempts.
5. **Block untrusted processes running from USB** prevents execution from removable media.

Because the organization tested all rules in **Audit Mode** before switching to **Block Mode**, there were no unexpected application conflicts. The attack is prevented, and Microsoft Defender raises alerts for SOC follow up.

### 2.11 SC-200 Exam Tips (Part 2)

> 1. ASR Rules are part of **Microsoft Defender Antivirus** and are behavior based, not signature based.
> 2. Four rule states: Not Configured, Block, Audit, Warn.
> 3. Audit Mode is the recommended first deployment step to avoid business disruption.
> 4. `Set-MpPreference` overwrites; `Add-MpPreference` appends.
> 5. Exclusions should be minimal; overuse reduces protection.
> 6. ASR events log locally in Windows Event Viewer under **Applications and Services Logs → Microsoft → Windows**, and centrally in Microsoft Defender for Endpoint.
> 7. Deployment tools: Intune, MDM, MECM, Group Policy, PowerShell.
> 8. Know which rule category maps to which attack technique (macro abuse, script abuse, LSASS credential theft, PSExec/WMI lateral movement, USB abuse, driver abuse).

## Part 3: Extra Exam Focused Context

The following material is not restating the source document. It is added because these distinctions and this context are commonly tested on SC-200 and directly support the topics above.

### 3.1 Frequently Confused ASR Components

| Comparison | Key Difference |
|---|---|
| **Audit mode vs Warn mode** | Audit never blocks and never notifies the end user; Warn blocks by default but shows the user a prompt they can choose to bypass |
| **ASR Rules vs Exploit Protection** | ASR Rules block specific malicious *behaviors* (macro abuse, script abuse); Exploit Protection applies OS and application level *exploit mitigations* and can coexist with third party antivirus |
| **Controlled Folder Access vs Network Protection vs Web Protection** | Controlled Folder Access guards the local file system from unauthorized writes (ransomware); Network Protection blocks outbound connections at the network layer; Web Protection blocks malicious or phishing URLs and content categories in the browser |
| **Application Control vs ASR Rules** | Application Control (allow listing) permits only explicitly trusted applications to run at all; ASR Rules allow normal application use but block specific risky behaviors within otherwise trusted apps |
| **Device Control vs "Block untrusted USB processes" ASR rule** | Device Control is the broader policy engine governing removable media access generally; the ASR rule is a narrower behavior block specifically for untrusted or unsigned processes launching from USB |

### 3.2 Where ASR Fits Inside Microsoft Defender for Endpoint

Microsoft Defender for Endpoint is built from several capability pillars. ASR is one pillar among several, and the exam expects you to place features into the correct pillar.

```text
Microsoft Defender for Endpoint
      │
      ├── Threat and Vulnerability Management
      │
      ├── Attack Surface Reduction   (this guide's focus)
      │
      ├── Next Generation Protection (Microsoft Defender Antivirus)
      │
      ├── Endpoint Detection and Response (EDR)
      │
      ├── Automated Investigation and Remediation
      │
      └── Microsoft Threat Experts
```

> **Exam Tip:** If a question describes blocking risky behavior before execution, that is Attack Surface Reduction. If it describes detecting and investigating a device after suspicious activity is already present, that is Endpoint Detection and Response (EDR), a different pillar.

### 3.3 SC-200 Exam Tips (Part 3)

> 1. Know that ASR is one pillar of Microsoft Defender for Endpoint, not the whole product.
> 2. Distinguish prevention focused pillars (ASR, Next Generation Protection) from detection and response focused pillars (EDR, Automated Investigation and Remediation).
> 3. Expect "which pillar does this belong to" style questions describing a scenario rather than naming the feature directly.

## SC-200 Last Minute Revision (Cheat Sheet)

### Core Definitions

| Term | One Line Definition |
|---|---|
| Attack Surface | Every possible entry point an attacker could exploit |
| Attack Surface Reduction (ASR) | Collection of Defender technologies that harden a device to prevent attacks before execution |
| ASR Rules | Behavior based rules that block specific risky actions (part of Microsoft Defender Antivirus) |
| Controlled Folder Access | Protects designated folders from ransomware and unauthorized changes |
| Network Protection | Blocks outbound connections to malicious or low reputation destinations |
| Web Protection | Blocks malicious and phishing websites and unwanted content categories |
| Application Control | Allow lists trusted applications only |
| Device Control | Governs removable storage (USB) usage |
| Hardware Based Isolation | Uses Virtualization based security (VBS) to isolate sensitive components and protect credentials |
| Exploit Protection | Applies exploit mitigations at OS and app level; supports third party antivirus too |

### ASR Rule States Quick Reference

| State | Blocks Action? | Notifies User? |
|---|---|---|
| Not Configured | No | No |
| Audit | No | No |
| Warn | Yes, but user can bypass | Yes |
| Block | Yes | No |

### PowerShell Quick Reference

```text
Set-MpPreference   → overwrites existing ASR configuration
Add-MpPreference   → appends new rules or exclusions

Add-MpPreference -AttackSurfaceReductionRules_Ids <GUID> -AttackSurfaceReductionRules_Actions Enabled
Add-MpPreference -AttackSurfaceReductionOnlyExclusions "<path>"
```

### Threat to Defense Mapping (memorize this)

| Threat | Correct ASR Component |
|---|---|
| Ransomware encrypting files | Controlled Folder Access |
| Malicious or phishing website | Web Protection |
| Malware download from a bad server | Network Protection |
| Untrusted app trying to run | Application Control |
| Malicious USB device | Device Control |
| Credential theft from LSASS | ASR Rule: Block credential stealing from LSASS |
| Word launching PowerShell | ASR Rule: Block Office applications from creating child processes |
| PSExec or WMI lateral movement | ASR Rule: Block process creation from PSExec and WMI commands |

### End to End Alert Flow (memorize this diagram)

```text
Risky Action on Device
      │
      ▼
ASR Component Blocks It
      │
      ▼
Alert Generated
      │
      ▼
Telemetry Sent to Microsoft Defender for Endpoint
      │
      ▼
Visible in Microsoft Defender Portal
      │
      ▼
SOC Analyst Investigates and Confirms
```

### Deployment Order Checklist

1. Configure ASR Rule in **Audit Mode**.
2. Review reporting to identify affected business applications.
3. Add minimal, targeted exclusions only if truly required.
4. Switch the rule to **Warn** or **Block**.
5. Monitor alerts in Microsoft Defender for Endpoint.
6. Cross check raw events in Windows Event Viewer if deeper forensic detail is needed.

### Common Exam Traps

1. Assuming Audit Mode blocks anything. It does not.
2. Confusing `Set-MpPreference` (overwrite) with `Add-MpPreference` (append).
3. Assuming ASR Rules alone stop ransomware. Controlled Folder Access is the correct match for that scenario.
4. Assuming Exploit Protection requires Microsoft Defender Antivirus. It does not, and it also supports third party antivirus.
5. Treating exclusions as a general troubleshooting fix rather than a minimal, targeted, last resort setting.
6. Mixing up which Defender for Endpoint pillar a described behavior belongs to (prevention like ASR versus detection and response like EDR).
