## 2. Device Actions Overview

**Device Actions** are remote response capabilities inside **Microsoft Defender for Endpoint** that let a SOC analyst investigate, contain, and remediate threats directly from the Microsoft Defender portal, without physical access to the machine.

They allow an analyst to:

* Contain a compromised device.
* Prevent malware from executing.
* Run an antivirus scan.
* Collect forensic evidence.
* Access a device remotely.
* Trigger automated investigation.
* Block a rogue unmanaged device.

### Two Categories of Device Actions

| Category | Purpose | Actions |
|---|---|---|
| **Containment Actions** | Stop or limit an ongoing attack | Isolate Device, Restrict App Execution, Run Antivirus Scan, Contain Device |
| **Investigation Actions** | Gather evidence and investigate | Initiate Automated Investigation, Collect Investigation Package, Initiate Live Response Session |

### The Action Center

The **Action Center** is the audit log for every response action performed on a device or file. It records:

* Action status.
* Time performed.
* The user who initiated the action.
* Success or failure.
* Current progress.

> Exam Tip: Every device action, whether containment or investigation, is logged in the Action Center and also appears on the device timeline. If a question asks "where would an analyst confirm a response action completed," the answer is the Action Center.

```text
Suspicious Activity Detected
        │
        ▼
Analyst Opens Device Page
        │
        ▼
Select a Device Action
        │
        ▼
Containment Action  or  Investigation Action
        │
        ▼
Result Logged in Action Center and Device Timeline
```

### SC-200 Exam Tips

* Device Actions split into **Containment Actions** and **Investigation Actions**. Memorize which action belongs to which category.
* **Initiate Automated Investigation** triggers **Automated Investigation and Response (AIR)**, which is also relevant to the newer exam objective on automatic attack disruption.
* The **Action Center** is the single place to audit all response activity.

## 3. Isolate Device

**Isolate Device** disconnects a compromised, **managed** endpoint from the network while it keeps talking to Microsoft Defender for Endpoint.

Purpose:

* Stop attacker communication.
* Prevent lateral movement.
* Prevent data exfiltration.
* Continue monitoring through Microsoft Defender.

> Exam Tip: Unlike pulling a network cable, an isolated device still sends telemetry to Microsoft Defender, so the analyst can keep investigating live.

### Selective Isolation

Available on **Windows 10 (1709 and later)** and **Windows 11**. It allows specific applications, such as Outlook, Microsoft Teams, and Skype for Business, to keep communicating while the rest of the device stays isolated.

### SC-200 Exam Tips

* Isolate Device requires the device to be **managed** and onboarded to Microsoft Defender for Endpoint.
* Communication with Microsoft Defender itself is preserved during isolation.
* Selective Isolation is the keyword for allowing named business apps to keep working during isolation.

## 4. Restrict App Execution

**Restrict App Execution** prevents applications from running on a compromised Windows device.

Purpose:

* Stop malware execution.
* Prevent an attacker from launching additional tools.
* Lock the endpoint down while the investigation continues.

When enabled, Windows applies a **Windows Defender Application Control (WDAC)** code integrity policy that allows only applications signed by Microsoft to run.

| Requirement | Detail |
|---|---|
| Supported OS | Windows 10 (1709 and later), Windows 11 |
| Dependency | Requires Microsoft Defender Antivirus |
| Not supported on | macOS, Linux |

### SC-200 Exam Tips

* Restrict App Execution is enforced through **WDAC**, a code integrity policy, not through a firewall rule.
* Only Microsoft signed applications are allowed to run once this action is active.
* This action is Windows only.

## 5. Run Antivirus Scan

An on demand **Microsoft Defender Antivirus Scan** started remotely from the Microsoft Defender portal, with no user interaction required.

Purpose:

* Detect malware.
* Remove malicious files.
* Verify endpoint health after remediation.

### SC-200 Exam Tips

* This is the fastest way to confirm a device is clean after other containment actions.
* No end user action is needed; it runs entirely from the portal.

## 6. Contain Device

**Contain Device** is for **unmanaged or rogue devices** discovered through **Device Discovery** that do **not** have Microsoft Defender for Endpoint installed.

Since an unmanaged device cannot receive Defender commands directly, Microsoft Defender instructs the **managed endpoints** on the same network to block communication with the rogue device.

Purpose:

* Block inbound network traffic.
* Block outbound network traffic.
* Prevent lateral movement.
* Stop an attacker from using the unmanaged device as a foothold.

```text
Open Device Inventory
        │
        ▼
Select the Unmanaged Device
        │
        ▼
Choose Contain Device
        │
        ▼
Add a Comment
        │
        ▼
Confirm the Action
        │
        ▼
Status Appears in Action Center
```

### SC-200 Exam Tips

* Contain Device targets devices with **no Defender agent**. Managed neighbors do the blocking on its behalf.
* Requires Device Discovery to have already found the rogue device.

## 7. Isolate Device vs Contain Device

> Exam Tip: This comparison is one of the most commonly tested distinctions in the Defender for Endpoint domain of SC-200.

| Aspect | Isolate Device | Contain Device |
|---|---|---|
| Target device | Managed, onboarded device | Unmanaged or rogue device |
| Requires Defender agent | Yes | No |
| How it blocks traffic | The device itself disconnects from the network | Nearby managed devices refuse to talk to it |
| Communication with Defender | Maintained for investigation | Not applicable, no agent present |
| Typical trigger | Active compromise on a known device | Device Discovery flags a suspicious unmanaged device |
| Used during | Ransomware, active compromise | Rogue device on the network |

```text
Device Is Compromised
        │
        ▼
Does the device have Microsoft Defender for Endpoint installed?
        │
   ┌────┴────┐
  Yes         No
   │           │
   ▼           ▼
Isolate      Contain
 Device       Device
```

## 8. Collect Investigation Package

An **Investigation Package** is a forensic snapshot of a device, downloaded as a **ZIP file**, containing logs, configuration data, system information, network details, and other artifacts.

> Exam Tip: An Investigation Package is a point in time snapshot for **offline analysis**. Live Response is an **interactive** session. This contrast is a favorite exam distinction.

### How to Collect It

From the Device Page:

1. Open the affected device.
2. Select **Collect Investigation Package** from the response actions.
3. Enter a reason for collecting the package.
4. Select **Confirm**.
5. Microsoft Defender generates and downloads a ZIP file.

Alternative path: **Action Center** then select the package collection action then download the ZIP.

```text
Open Device Page
        │
        ▼
Select Collect Investigation Package
        │
        ▼
Enter a Reason
        │
        ▼
Confirm
        │
        ▼
ZIP File Generated and Downloaded
        │
        ▼
Offline Forensic Analysis
```

### What the ZIP Contains

| Item | What Analysts Look For |
|---|---|
| Autoruns | Startup persistence (ASEPs) |
| Installed Programs | Installed software inventory |
| Network Connections (ActiveNetConnections.txt, Arp.txt, DnsCache.txt, IpConfig.txt, firewall logs) | Command and control connections, lateral movement |
| Prefetch Files | Recently executed applications |
| Processes | Currently running processes |
| Scheduled Tasks | Malicious persistence |
| Security Event Log | Logon, logoff, and audit events |
| Services | Installed services and their states |
| SMB Sessions | Lateral movement, file sharing activity |
| System Information | OS and hardware details |
| Temporary Directories | Dropped malware or payloads |
| Users and Groups | Unauthorized accounts, privilege escalation |
| WdSupportLogs | Microsoft Defender support logs |
| CollectionSummaryReport.xls | Summary of the collection status and any errors |

### SC-200 Exam Tips

* Downloaded as a **ZIP file**, always.
* Collected from the **Device Page** or the **Action Center**.
* **Autoruns** is the folder to check first for persistence mechanisms.
* **Investigation Package** = offline forensic analysis. **Live Response** = interactive remote investigation. Do not mix these up.

## 9. Live Response

**Live Response** is a **cloud based, interactive command line shell** that lets a SOC analyst securely connect to an onboarded device and investigate or respond in real time, without Remote Desktop or physical access.

It supports:

* Executing commands.
* Running PowerShell scripts.
* Collecting files and forensic evidence.
* Investigating running processes.
* Downloading malware samples.
* Uploading investigation scripts.
* Performing remediation actions.
* Hunting for emerging threats.

> Exam Tip: Live Response focuses on security investigation and incident response, not general desktop administration. Do not confuse it with RDP.

### Prerequisites

| Requirement | Detail |
|---|---|
| Live Response enabled | Turned on in **Advanced Features** settings, only by users with admin permissions |
| Automation Remediation Level | The device group must have one assigned, or Live Response cannot start |
| RBAC permissions | Only authorized users can start a session |
| Supported Windows version | Onboarded, supported device required |

### RBAC Models for Live Response

| Model | Scope | Notes |
|---|---|---|
| Microsoft Defender XDR Unified RBAC | Centralized, across Defender XDR workloads | Microsoft's recommended model |
| Standalone RBAC | Defender for Endpoint only | Legacy, per workload model |

### The Live Response Library

Stores files an analyst wants to run remotely, typically PowerShell scripts, investigation scripts, and custom response tools.

```text
Upload Script to Live Response Library
        │
        ▼
Verify the Script Exists in the Library
        │
        ▼
Execute the Script Using the run Command
        │
        ▼
Review Script Output
        │
        ▼
Continue the Investigation
```

> Exam Tip: Unsigned PowerShell scripts can be run in Live Response but require a specific setting to be enabled first, and Microsoft does not recommend it because it increases risk.

## 10. Live Response Commands and Limits

| Command or Flag | Purpose |
|---|---|
| `getfile` | Downloads a file from the device |
| `run` | Executes a PowerShell script stored in the Live Response library |
| `putfile` | Copies a file from the library onto the endpoint |
| `library` | Lists uploaded files available for execution |
| `remediate` | Removes or remediates a malicious entity |
| `undo` | Reverses a supported remediation action |
| `-auto` | Automatically runs prerequisite commands |
| `CTRL + C` | Cancels a currently running command |

| Command Type | Used For |
|---|---|
| Basic commands | Investigation and information gathering |
| Advanced commands | Investigation, file transfer, script execution, and remediation |

### Size Limits

| Action | Limit |
|---|---|
| GetFile | 3 GB |
| FileInfo | 10 GB |
| Library | 250 MB |

> Exam Tip: These exact limits (3 GB, 10 GB, 250 MB) are the kind of detail SC-200 loves to test directly.

```text
Analyst Opens Device Page
        │
        ▼
Initiate Live Response Session
        │
        ▼
Cloud Based Interactive Shell Connects
        │
        ▼
Run Basic or Advanced Commands
        │
        ▼
Collect Evidence or Remediate
        │
        ▼
Session Ends, Actions Logged in Action Center
```

### SC-200 Exam Tips

* Live Response is a **cloud based interactive shell**, not Remote Desktop.
* A script must be uploaded to the **Live Response Library** before it can be run with `run`.
* Microsoft recommends **Microsoft Defender XDR Unified RBAC** over Standalone RBAC.
* Memorize the exact size limits: GetFile 3 GB, FileInfo 10 GB, Library 250 MB.

## 11. Real World Scenario Takeaways

**Scenario A, managed device compromise:** A Windows 11 laptop onboarded to Microsoft Defender for Endpoint is talking to a known command and control server. The analyst performs **Isolate Device** to cut network access while Defender keeps collecting telemetry, then starts a **Live Response** session to run a PowerShell script, collect an investigation package, and launch an antivirus scan.

> Takeaway: managed and compromised leads to Isolate Device, then Live Response for interactive cleanup.

**Scenario B, unmanaged rogue device:** Device Discovery finds an unknown network appliance with no Defender sensor. Isolate Device cannot be used because there is no agent. The analyst performs **Contain Device**, so nearby managed endpoints refuse to talk to the rogue device until it can be investigated.

> Takeaway: unmanaged and rogue leads to Contain Device, never Isolate Device.

**Scenario C, forensic evidence without touching the system:** An alert shows a finance employee's computer talking to a malicious command and control domain. To preserve evidence without changing the system, the analyst selects **Collect Investigation Package**. Reviewing the ZIP, **Autoruns** reveals a malicious registry Run key, **Processes** shows a suspicious PowerShell process, **Prefetch** confirms an unknown executable ran, **DNS Cache** shows contact with the attacker domain, the **Security Event Log** shows an odd admin logon, and **Users and Groups** reveals a new local administrator account used for persistence.

> Takeaway: the Investigation Package is how an analyst reconstructs an attacker's persistence and lateral movement story after the fact, without an interactive session.

## 12. SC-200 Last Minute Revision

### One Page Cheat Sheet

| Action | Target | Agent Required | Interactive or Snapshot | Key Use |
|---|---|---|---|---|
| Isolate Device | Managed device | Yes | Neither, blocks network | Active compromise containment |
| Restrict App Execution | Managed Windows device | Yes, plus Defender AV | Neither | Stop malware execution via WDAC |
| Run Antivirus Scan | Managed device | Yes | Neither | Detect or remove malware |
| Contain Device | Unmanaged rogue device | No | Neither, neighbors block it | Block a device with no agent |
| Collect Investigation Package | Managed device | Yes | Snapshot | Offline forensic ZIP |
| Live Response | Managed device | Yes | Interactive | Real time command line investigation |

### Frequently Confused Concepts

| Concept A | Concept B | Key Difference to Remember |
|---|---|---|
| Isolate Device | Contain Device | Isolate needs the Defender agent on the target. Contain works against devices with no agent, using neighbors to block them. |
| Investigation Package | Live Response | Investigation Package is a downloaded ZIP snapshot for offline analysis. Live Response is a live, interactive shell. |
| Containment Actions | Investigation Actions | Containment stops the attack (isolate, restrict, scan, contain). Investigation gathers evidence (automated investigation, package, live response). |
| Microsoft Defender XDR Unified RBAC | Standalone RBAC | Unified is centralized across Defender XDR and is Microsoft's recommended model. Standalone is scoped only to Defender for Endpoint. |
| Basic Live Response commands | Advanced Live Response commands | Basic is for investigation and information gathering only. Advanced adds file transfer, script execution, and remediation. |

### Key Terms to Memorize

* **RBAC**: Role Based Access Control, controls who can run response actions and Live Response sessions.
* **WDAC**: Windows Defender Application Control, the code integrity policy behind Restrict App Execution.
* **AIR**: Automated Investigation and Response, triggered by Initiate Automated Investigation.
* **Action Center**: the audit trail for every device action.
* **ASEP**: Auto Start Extensibility Point, what the Autoruns folder in an Investigation Package reveals.

### Final Reminders Before the Exam

> * If the scenario device **has the Defender agent** and is compromised, think **Isolate Device**.
> * If the scenario device is **unmanaged or rogue**, think **Contain Device**.
> * If the scenario needs a **ZIP for offline review**, think **Investigation Package**.
> * If the scenario needs **live, real time commands**, think **Live Response**.
> * If the question asks about **application lockdown through code integrity**, think **Restrict App Execution and WDAC**.
> * If the question asks **where actions are audited**, think **Action Center**.
