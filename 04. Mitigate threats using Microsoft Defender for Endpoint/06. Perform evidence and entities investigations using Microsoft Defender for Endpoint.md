## 1. Overview: What Is Entity Investigation?

An **entity** is any object connected to a security event: a **file**, a **user account**, an **IP address**, or a **domain/URL**. In Microsoft Defender for Endpoint and Microsoft Defender XDR, each entity type has its own dedicated details page that centralizes everything an analyst needs to decide whether the entity is malicious and how far it has spread.

Instead of investigating one alert at a time, analysts pivot from an alert into the related entities to build the full picture of an attack.

| Entity | Central Investigation Page | Primary Question It Answers |
| --- | --- | --- |
| File | File Profile Page | Is this file malicious, and where has it spread? |
| User Account | User Account Details Page | Is this identity compromised or misused? |
| IP Address | IP Details Page | Is this network endpoint malicious or part of an attack? |
| Domain / URL | URL / Domain Details Page | Is this domain malicious, and what contacted it? |

> **Exam Tip:** Questions often describe a scenario and ask "which entity would you investigate next?" Match the artifact in the scenario (hash, username, IP, domain) to the correct entity type and page.

## 2. File Investigation

### 2.1 What Is File Investigation?

A file investigation analyzes a suspicious or malicious file linked to:

* Security alerts
* Incidents
* Device events
* Process executions
* Threat hunting results

The goal is to determine:

* Whether the file is malicious
* Which devices contain the file
* How widespread the file is
* What actions the file performed
* Whether remediation is required

### 2.2 Accessing the File Profile Page

A file can be opened from several locations in Microsoft Defender for Endpoint:

* Alerts
* Incidents
* Device Timeline
* Process Tree
* Artifact Timeline
* Search results

The **File Profile Page** is the central location for investigating a file.

### 2.3 Real World SOC Scenario

Microsoft Defender for Endpoint generates an alert after an employee downloads a suspicious executable from a phishing email. An analyst opens the file profile page and reviews the file's SHA256 hash, signer information, and VirusTotal detection ratio. The file has only been observed on two devices, which raises suspicion.

The analyst submits the file for **Deep Analysis**. Microsoft executes it in a secure cloud sandbox, and the report shows the executable creates registry Run keys for persistence, drops additional files, and connects to a known Command and Control (C2) server. The analyst confirms the file is malicious, uses **Stop and Quarantine File**, and then verifies remediation in the **Action Center**.

```text
Suspicious File Detected
        │
        ▼
Alert Generated in Microsoft Defender for Endpoint
        │
        ▼
Analyst Opens the File Profile Page
        │
        ▼
Review File Details, Prevalence, and Related Alerts
        │
        ▼
Submit File for Deep Analysis (Cloud Sandbox)
        │
        ▼
Review Behaviors, Registry Changes, Dropped Files, Network Connections
        │
        ▼
Confirm Malicious Verdict
        │
        ▼
Stop and Quarantine File
        │
        ▼
Track Remediation Status in the Action Center
```

### 2.4 File Profile Page Components

| Section | What It Shows |
| --- | --- |
| File Details | SHA1, SHA256, MD5, file size, signer, malware detection status |
| File Prevalence | How common the file is inside the organization and globally |
| Observed in Organization | Which devices contain the file |
| Alerts | All incidents and alerts associated with the file |
| Deep Analysis | Cloud sandbox behavioral report |
| Action Center | Remediation status of actions taken on the file |

### 2.5 Deep Analysis

**Deep Analysis** runs the file in a secure Microsoft cloud sandbox and reports on:

* Behaviors
* Observables
* Registry changes
* Dropped files
* Network connections
* Contacted IP addresses

Deep Analysis only supports **Portable Executable (PE)** files:

* `.exe`
* `.dll`

If Deep Analysis fails, check the following:

* The file is a supported PE file
* The file still exists (has not been deleted or altered)
* Sample collection is allowed by policy

### 2.6 Remediation: Stop and Quarantine File

The **Stop and Quarantine File** action:

* Stops the malicious process
* Quarantines the file
* Removes persistence where applicable

### 2.7 Action Center

The **Action Center** tracks the status of remediation actions, including:

* Submission Time
* Success
* Failed
* Pending

### 2.8 SC-200 Exam Tips

> Expect scenario questions asking which section of the file profile page provides a specific piece of information. Match the need to the feature:

| You Need To Know | Use This Feature |
| --- | --- |
| File reputation | Malware Detection |
| Spread across devices | Observed in Organization |
| Frequency of occurrence | File Prevalence |
| Sandbox behavior | Deep Analysis |
| Remediation progress | Action Center |

* File investigation is performed from the **File Profile Page**.
* Deep Analysis only works on **PE files** (`.exe`, `.dll`); it cannot analyze scripts, macros, or documents.
* **Stop and Quarantine File** is a remediation action, not an investigation feature; know the difference between investigation tools (read only, informational) and remediation actions (take effect on the device).
* The **Action Center** is the common tracking hub for remediation actions across the whole platform, not only for files.

### 2.9 Exam Keywords

| Term | Meaning |
| --- | --- |
| File Profile Page | Central location for file investigation |
| File Prevalence | Number of devices with the file |
| Observed in Organization | Devices where the file exists |
| Deep Analysis | Cloud sandbox execution and behavioral analysis |
| Stop and Quarantine File | Stops malicious processes and quarantines files |
| Action Center | Tracks remediation actions and their status |

## 3. User Account Investigation

### 3.1 What Is User Account Investigation?

A user account investigation analyzes all security related information associated with a specific identity. Microsoft Defender XDR correlates user activity across multiple devices and services instead of forcing the analyst to review each alert separately.

SOC analysts investigate user accounts to answer questions such as:

* Has this user's account been compromised?
* Which devices has the user logged on to?
* Are there active alerts involving this user?
* Is the account being used for lateral movement?
* Has the user authenticated from unusual locations or devices?
* Does the user's identity show signs of compromise?

### 3.2 How It Fits Into the Microsoft Security Ecosystem

```text
Microsoft Defender for Endpoint  →  Endpoint telemetry and logon events, links alerts to accounts
Microsoft Defender for Identity  →  Detects identity attacks (Pass the Hash, Pass the Ticket, Kerberoasting, suspicious AD activity)
Microsoft Entra ID               →  Sign-in logs, user risk, sign-in risk, MFA status, group memberships
Microsoft Sentinel               →  Ingests user alerts and correlates them with logs from other products
        │
        ▼
        Microsoft Defender XDR
        │
        ▼
   Unified User Account Investigation
```

| Service | Contribution to the User Profile |
| --- | --- |
| Microsoft Defender for Endpoint | Endpoint telemetry, logon events, alert to account association |
| Microsoft Defender XDR | Correlates alerts, incidents, devices, users, and identities into one investigation |
| Microsoft Defender for Identity | Identity attack detection: Pass the Hash, Pass the Ticket, Kerberoasting, suspicious Active Directory activity |
| Microsoft Entra ID | Sign-in logs, user risk, sign-in risk, MFA status, group memberships |
| Microsoft Sentinel | Broader correlation across products for SIEM level investigation |

### 3.3 Accessing a User Account

A user account can be opened from several locations:

* Dashboard (**Users at Risk**)
* Alert Queue
* Device Details page

Each location contains a clickable user account that opens the **User Account Details** page.

### 3.4 User Account Details Page Components

| Tab / Section | What It Shows |
| --- | --- |
| User Details | Related open incidents, active alerts, SAM account name, SID, number of devices logged on to, first and last observed activity, user role, logon types |
| Overview | Incident information, devices the user logged on to, logon activity per device |
| Alerts | Every alert tied to the account: last detected activity, description, associated device, severity, status, assigned analyst |
| Observed in Organization | Where the account has been used throughout the environment |

> **Acronym check:** SAM = Security Account Manager account name. SID = Security Identifier. Both uniquely identify the account within Windows/Active Directory.

### 3.5 SC-200 Exam Tips

* User account investigation focuses on **identity**, not the device or file itself.
* Know the entry points: **Users at Risk** dashboard, **Alert Queue**, **Device Details** page.
* The **User Details** pane always includes SAM name, SID, first/last observed activity, user role, logon types, and device count.
* Integrating **Microsoft Defender for Identity** adds identity attacks and Active Directory context.
* Integrating **Microsoft Entra ID** adds sign-in risk, user risk, MFA registration status, and group memberships.
* User account investigation is commonly used after phishing attacks, credential theft, suspicious sign-ins, and identity compromise.

> **Exam Tip — commonly confused:** User = identity activity. Device = endpoint activity. File = malware and file behavior. IP Address = network connections and communications. Scenario questions often hinge on picking the right one of these four.

## 4. IP Address Investigation

### 4.1 What Is IP Address Investigation?

An IP address investigation analyzes an IP address that has communicated with one or more devices in the organization. Unlike device investigations that focus on a single endpoint, IP investigations focus on **network communications across the whole organization**.

It helps answer:

* Is the IP address malicious?
* Which devices communicated with it?
* When did the communication occur?
* How many devices are affected?
* Is the IP associated with active security alerts?
* Could the IP be part of a Command and Control (C2) infrastructure?

### 4.2 IP Details Page Components

| Section | What It Shows |
| --- | --- |
| IP Worldwide | Global reputation, prior observation, and registration information from Microsoft's threat intelligence |
| Reverse DNS Names (rDNS) | Maps the IP address back to a hostname or domain name |
| Alerts Related to This IP | All alerts associated with the IP address |
| IP in Organization | Details on the prevalence of the IP inside the organization |
| Prevalence | Number of devices connected, first/last seen; default window is **30 days** and is filterable |
| Most Recent Observed Devices with IP | Chronological timeline of devices that communicated with the IP |

The page also displays additional attributes such as the **ASN** (Autonomous System Number, which identifies the network operator the IP belongs to).

### 4.3 SC-200 Exam Tips

* IP investigation focuses on **network communication**, not files or users.
* Common investigation targets: Command and Control servers, malware download servers, phishing infrastructure, data exfiltration destinations.
* Search for an IP from: **Microsoft Defender Portal → Global Search → IP**.
* Remember: **Prevalence defaults to a 30 day window** on both the IP and Domain pages; this is a frequently tested number.

> **Exam Tip:** User Investigation = identity activity. Device Investigation = endpoint activity. File Investigation = malware analysis. IP Investigation = network communication. Microsoft Defender XDR correlates all of these together.

## 5. Domain Investigation

### 5.1 What Is Domain Investigation?

A domain investigation determines whether a suspicious or malicious domain has communicated with devices inside the organization. It lets analysts identify affected devices, review related alerts, understand the domain's reputation, and determine the scope of compromise.

### 5.2 Domain / URL Details Page Components

| Section | What It Shows |
| --- | --- |
| URL Details | Domain/URL information, contact information, name servers (DNS information); helps verify ownership and legitimacy |
| URL Worldwide | Microsoft's global intelligence: link to more URL information, open incident count, worldwide active alert count |
| Incident | Incidents involving the domain over the **last 180 days** |
| Prevalence | How frequently the domain has been seen in the organization; default view is **30 days**, customizable |
| Alerts | Alert severity, status, associated incident, classification, investigation status |
| Observed in Organization | Chronological timeline of communications: time, device, event description, associated alerts |

> A domain contacted by hundreds of devices may represent legitimate business activity. A domain contacted by only a single endpoint may warrant deeper investigation. Low prevalence often signals a targeted attack; high prevalence still requires validation, not automatic trust.

### 5.3 SC-200 Exam Tips

| You Need To Know | Use This Section |
| --- | --- |
| Domain reputation | URL Worldwide |
| Devices that contacted the domain | Observed in Organization |
| Frequency of domain usage | Prevalence |
| Security alerts related to the domain | Alerts |
| Previous incidents involving the domain | Incident (180 day window) |

* **Prevalence** measures how widespread the domain is inside the tenant.
* **Observed in Organization** helps identify patient zero and lets the analyst pivot directly into a device investigation.
* Remember the two different default time windows: **Prevalence = 30 days**, **Incident = 180 days**.

## 6. Cross Entity Investigation: Pivoting Between Entities

The SC-200 exam frequently tests the ability to move between related entities during an investigation rather than treating each entity page as isolated.

```text
Alert
  │
  ▼
Device
  │
  ▼
File / User / IP Address / Domain
  │
  ▼
Incident (correlates related alerts and entities)
  │
  ▼
Investigation and Response
```

Common pivot paths called out for the exam:

* Alert → Device
* Device → URL/Domain
* URL → Device
* Incident → Related alerts

### 6.1 Entity Comparison Table

| Entity | Central Page | Common Entry Points | Investigation Focus |
| --- | --- | --- | --- |
| File | File Profile Page | Alerts, Incidents, Device Timeline, Process Tree, Artifact Timeline, Search | Malware and file behavior |
| User Account | User Account Details Page | Users at Risk dashboard, Alert Queue, Device Details page | Identity activity and compromise |
| IP Address | IP Details Page | Global Search in Microsoft Defender Portal | Network communication |
| Domain / URL | URL/Domain Details Page | Alerts, Incidents, Search (same global search model as other entities) | Domain reputation and communication scope |

### 6.2 Why This Matters for the Exam

> Microsoft Defender XDR exists specifically to correlate entities. A single incident can bundle related alerts, devices, files, users, IPs, and domains together so the analyst investigates the whole attack chain instead of isolated events. Expect exam scenarios that give you one entity (for example, a hash or an IP) and ask which page or pivot path to use next to continue the investigation.

## 7. SC-200 Last Minute Revision

### 7.1 One Page Cheat Sheet

| Entity | Central Page | Default Time Window | Signature Feature |
| --- | --- | --- | --- |
| File | File Profile Page | N/A | Deep Analysis (sandbox, PE files only) |
| User | User Account Details Page | N/A | Correlated identity view (Defender for Identity + Entra ID) |
| IP Address | IP Details Page | 30 days (Prevalence) | IP Worldwide, Reverse DNS |
| Domain/URL | URL/Domain Details Page | 30 days (Prevalence), 180 days (Incident) | URL Worldwide, Observed in Organization |

### 7.2 Frequently Confused Concepts

| Concept A | Concept B | Key Difference |
| --- | --- | --- |
| File Prevalence | Observed in Organization | Prevalence = how common; Observed in Organization = which devices specifically |
| Deep Analysis | Action Center | Deep Analysis = investigation/analysis (sandbox report); Action Center = remediation tracking |
| Stop and Quarantine File | Deep Analysis | Stop and Quarantine File = remediation action; Deep Analysis = investigative, read only |
| IP Prevalence | Domain Incident window | IP/Domain Prevalence defaults to 30 days; Domain Incident view defaults to 180 days |
| User Investigation | Device Investigation | User = identity; Device = endpoint |

### 7.3 Key Numbers to Memorize

* **30 days** — default Prevalence window for both IP addresses and domains.
* **180 days** — default window for Incidents involving a domain.
* **PE files only** (`.exe`, `.dll`) — the only file types Deep Analysis supports.
