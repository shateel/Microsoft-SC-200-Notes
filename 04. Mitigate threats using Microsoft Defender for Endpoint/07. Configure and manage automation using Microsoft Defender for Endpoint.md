## Overview

Microsoft Defender for Endpoint provides several automation layers that reduce the manual workload of SOC analysts:

1. **Advanced Features** — toggles that turn on automated investigation, alert resolution, and file blocking.
2. **Automation Uploads and Folder Exclusions** — controls over what content is sent to the cloud for deeper analysis, and what is skipped.
3. **Automated Investigation and Remediation (AIR)** — the engine that actually investigates alerts and remediates threats.
4. **Block At Risk Devices** — integration with Microsoft Intune and Microsoft Entra ID Conditional Access to stop risky devices from reaching corporate resources.

> **Exam framing:** the SC 200 exam frequently tests *where* a setting is configured and *which product* is responsible for a given action. Pay close attention to the navigation paths throughout this guide.

## Advanced Features

**Location:** `Microsoft Defender Portal → Settings → General → Advanced Features`

Advanced Features are optional, mostly On/Off toggles that extend the default functionality of Microsoft Defender for Endpoint. They let an organization automate investigations, automatically remediate threats, block malicious files, and reduce analyst workload. Without them, analysts must manually investigate and remediate every single alert, which increases Mean Time to Respond (MTTR) and contributes to alert fatigue.

### 1. Automated Investigation

Turning this on enables **Automated Investigation and Remediation (AIR)**. Once enabled, Defender automatically:

* Investigates alerts.
* Collects evidence.
* Determines whether files or activities are malicious.
* Recommends remediation.
* Remediates threats automatically, when permitted.

### 2. Automatically Resolve Alerts

Automatically changes an alert's status to **Resolved** when either:

* Automated Investigation returns a verdict of **No Threats Found**, or
* All malicious artifacts have been successfully remediated.

> **Important behavior:** if an analyst has manually set an alert to **In Progress** or **Resolved**, automatic resolution will **not** overwrite that decision. Manual analyst actions always take priority over automated status updates.

### 3. Allow or Block File

Lets administrators explicitly allow or block a file across the entire organization. A blocked file cannot be executed, opened, read, or written on any managed device — this gives centralized control over known malicious files.

**Two requirements must be met before this feature works:**

| Requirement | Why it matters |
|---|---|
| Microsoft Defender Antivirus must be the active antimalware solution | If another antivirus product is active on the device, the block/allow indicator cannot be enforced |
| Cloud based protection must be enabled | Cloud protection is what distributes the allow/block indicators across the whole organization |

### Real World SOC Scenario (Summary)

A user opens a malicious attachment from a phishing email. AIR automatically investigates, confirms the file is ransomware, removes it, and restores affected artifacts. Because remediation succeeded, **Automatically Resolve Alerts** closes the alert without analyst effort. The analyst then uses **Allow or Block File** to create an organization wide block for the ransomware sample so it cannot run on any other endpoint.

### SC 200 Exam Tips

* Advanced Features live under `Settings → General → Advanced Features`.
* Three automation related features: **Automated Investigation**, **Automatically Resolve Alerts**, **Allow or Block File**.
* **Automated Investigation** toggle is what actually turns on **AIR**.
* **Automatically Resolve Alerts** only fires on "No Threats Found" or full remediation, and it never overrides a manual analyst decision.
* **Allow or Block File** needs both Microsoft Defender Antivirus as the active engine **and** cloud based protection enabled.
* Blocked files: cannot be read, written, opened, or executed.

## Automation Uploads and Folder Exclusions

*(Source module: "Manage automation upload and folder settings")*

**Location:** `Microsoft Defender Portal → Settings → Endpoints → Rules → Automation Uploads`

Automation Uploads control whether Defender automatically uploads suspicious files, email attachments, or process memory to the Microsoft Defender cloud during an automated investigation. Cloud engines can perform deeper inspection than what is possible locally on the device, which improves malware classification and remediation accuracy.

### File Content Analysis

Uploads **selected suspicious files and email attachments** for cloud inspection during an Automated Investigation. Administrators configure two extension lists so that only matching files are uploaded (not every file):

* File Extension Names (for example `.exe`, `.bat`, `.dll`)
* Email Attachment Extension Names

### Memory Content Analysis

Uploads the **memory of suspicious processes** rather than files on disk. This is essential for detecting threats that leave little or no trace on disk, such as:

* Fileless malware
* In memory attacks
* Malicious PowerShell activity
* Process injection
* Reflective DLL loading
* Advanced persistent threats (APTs)

### Automation Folder Exclusions

**Location:** `Settings → Endpoints → Rules → Automation Folder Exclusions`

Tells **Automated Investigation only** to skip specific folders so trusted directories are not unnecessarily analyzed. Adding an exclusion requires:

1. Folder path
2. File extensions
3. File names
4. Description

> **Common exam trap:** Automation Folder Exclusions affect Automated Investigation **only**. They do **not** disable or exclude anything from Microsoft Defender Antivirus scanning — those are two completely separate exclusion lists.

### Quick Comparison

| Setting | Analyzes | Scope |
|---|---|---|
| File Content Analysis | Files and email attachments on disk | Cloud upload for deeper file inspection |
| Memory Content Analysis | Memory of running suspicious processes | Cloud upload for in memory threat detection |
| Automation Folder Exclusions | Nothing — it skips folders | Automated Investigation only, not Defender Antivirus |

### SC 200 Exam Tips

* Automation Uploads configured at `Settings → Endpoints → Rules → Automation Uploads`.
* File Content Analysis = suspicious files and email attachments; controlled by two separate extension lists.
* Memory Content Analysis = memory of suspicious processes; catches fileless and in memory threats.
* Automation Folder Exclusions apply to Automated Investigation only — never confuse with Defender Antivirus exclusions.
* Expect a question that asks you to distinguish Automation Folder Exclusions from Microsoft Defender Antivirus exclusions.

## Automated Investigation and Remediation (AIR)

*(Source module: "Configure automated investigation and remediation capabilities")*

**AIR** is the intelligent investigation engine inside Microsoft Defender for Endpoint. When a suspicious alert fires, AIR automatically investigates the alert, collects evidence, analyzes suspicious files and processes, determines whether the activity is malicious, and performs remediation based on the **automation level** assigned to the device's **device group**.

```text
Alert Triggered
       │
       ▼
AIR Investigates Alert
       │
       ▼
Collects Evidence and Analyzes
Files / Processes
       │
       ▼
Verdict: Malicious or Clean?
       │
       ▼
Remediation Action Determined
       │
       ▼
Automation Level of the Device Group
Decides: Auto Remediate or
Wait for Analyst Approval
```

### Device Groups

A **Device Group** is a logical collection of endpoints that share common settings and permissions. Instead of configuring every endpoint one by one, administrators assign settings — including automation level, user access, security policies, and investigation behavior — at the group level.

**Location:** `Settings → Endpoints → Device Groups`

### Automation (Remediation) Levels

This is one of the **most heavily tested** SC 200 topics in this domain. Microsoft supports five levels, configured at `Settings → General → Auto Remediation`.

| Level | Investigation | Remediation | Analyst Approval Needed | Best For |
|---|---|---|---|---|
| **Full Automation** ("Full — remediate threats automatically") | Automatic | Automatic | No | Standard workstations, well managed enterprise environments, high volume environments |
| **Semi Automation — Approval for Any Remediation** | Automatic | Manual only | Yes, for every action | Highly sensitive systems, critical production servers, regulated industries |
| **Semi Automation — Approval for Core Folders** | Automatic | Automatic outside core folders (for example `C:\Windows\`) | Yes, only for files in core Windows folders | Protecting critical OS files from unintended auto remediation |
| **Semi Automation — Approval for Non Temporary Folders** | Automatic | Automatic inside temporary folders only | Yes, for files outside temp folders | Balancing speed with control over non temp locations |
| **No Automation** | Automatic | None — nothing is queued or performed | Fully manual | Not recommended by Microsoft |

**Temporary folder examples used by the "Non Temporary Folders" level:**

* `\Users\*\AppData\Local\Temp\`
* `\Windows\Temp\`
* `\Users\*\Downloads\`

> **Exam tip:** Microsoft does **not** recommend "No Automation" because it weakens the organization's security posture. Microsoft recommends Full Automation, or at minimum one of the Semi Automation levels.

### Action Center

The **Action Center** is where all remediation actions — automatic or manual — are recorded.

| Tab | Contains |
|---|---|
| **Pending** | Remediation actions waiting on analyst approval |
| **History** | Completed remediation actions (including fully automatic ones) |

Remediation actions performed under Full Automation, or automatically inside an allowed folder under a Semi Automation level, can still be **undone** later if needed from the Action Center.

### SC 200 Exam Tips

* AIR = **Automated Investigation and Remediation**, and it is **enabled by default** in Microsoft Defender for Endpoint.
* Automation behavior is always controlled at the **Device Group** level, not per device.
* Memorize the five automation levels and which ones require approval, and for what scope (all files, core folders only, or non temp folders only).
* "Full" always means investigate **and** remediate automatically, with **no** approval step.
* "No Automation" still **investigates**, it just never remediates or queues anything.
* Pending approvals show in **Action Center → Pending**; completed actions show in **Action Center → History**.

## Block At Risk Devices

*(Source module: "Block at risk devices")*

**Block At Risk Devices** uses **Conditional Access** to stop a compromised endpoint from reaching corporate cloud resources such as Microsoft 365, SharePoint Online, Exchange Online, and Teams — even after malware has already been detected on it. This helps prevent lateral movement, data exfiltration, and further compromise while remediation is underway.

### How It Works — End to End Flow

```text
Windows Device
       │
       ▼
Microsoft Defender for Endpoint
Detects Threats
       │
       ▼
Calculates Machine Risk Score
       │
       ▼
Microsoft Intune
Evaluates Compliance Policy
       │
       ▼
Microsoft Entra ID
Conditional Access
       │
       ├── Device Compliant     → Access Granted
       └── Device Noncompliant  → Access Blocked
```

### Configuration Steps

**Step 1: Enable the Microsoft Intune Connection**
`Microsoft Defender XDR → Settings → Endpoints → Advanced Features → Microsoft Intune Connection (On) → Save`
This lets Defender share device risk information with Intune.

**Step 2: Enable Defender for Endpoint Integration in Intune**
`Microsoft Intune Admin Center → Endpoint Security → Microsoft Defender for Endpoint → Allow Microsoft Defender for Endpoint to enforce Endpoint Security Configurations (On) → Save`
This lets Intune receive device risk information from Defender.

**Step 3: Create a Device Compliance Policy**
`Devices → Compliance → Create Policy` → Platform: **Windows 10 and later** → under **Microsoft Defender for Endpoint**, configure **"Require the device to be at or under the Machine Risk Score"**.

**Step 4: Create a Conditional Access Policy**
`Microsoft Entra ID → Conditional Access → New Policy` → configure Users or workload identities, Cloud applications, Client apps → under **Grant**, choose **"Require device to be marked as compliant"** → enable and save.

### Machine Risk Score Levels

| Level | Behavior | Relative Security |
|---|---|---|
| **Clear** | No threats allowed at all; any detected threat makes the device noncompliant | Most secure / most restrictive |
| **Low** | Low risk threats tolerated; Medium and High risk devices become noncompliant | Strong |
| **Medium** | Low and Medium risk threats tolerated; only High risk devices become noncompliant | Moderate |
| **High** | Least restrictive; devices with High, Medium, or Low risk are still considered compliant | Weakest |

> **Exam tip:** choosing a **lower** risk threshold (Clear or Low) provides **stronger** security because fewer risk conditions are tolerated before a device is blocked.

### Complete Workflow

```text
Windows Device
       │
       ▼
Microsoft Defender for Endpoint
Threat Detection → Machine Risk Score
       │
       ▼
Microsoft Intune
Compliance Policy Evaluation
       │
       ▼
   Compliant?
       │
 ┌─────┴─────┐
 ▼           ▼
Yes          No
 │           │
 ▼           ▼
Microsoft Entra ID   Microsoft Entra ID
Grants Access        Blocks Access
```

### Relationship Between Defender, Intune, and Entra ID

| Product | Responsibility |
|---|---|
| **Microsoft Defender for Endpoint** | Detects threats and calculates the Machine Risk Score |
| **Microsoft Intune** | Evaluates device compliance against the configured Machine Risk Score threshold |
| **Microsoft Entra ID Conditional Access** | Grants or blocks access to cloud resources based on the compliance result |

> This division of responsibility across three products is a recurring SC 200 exam theme — expect questions asking which product performs which step.

### Real World SOC Scenario (Summary)

A finance employee's device is infected via a phishing email and receives a **High** Machine Risk Score. Intune's policy requires **Low** or better, so the device is marked **noncompliant**, and Entra ID Conditional Access blocks access to Microsoft 365, SharePoint Online, and Exchange Online. After the analyst remediates the malware and the risk score drops back to an acceptable level, Conditional Access automatically restores access — no manual unblock step is required.

### SC 200 Exam Tips

* Block At Risk Devices requires **three** products working together: Defender for Endpoint, Intune, and Entra ID.
* Devices must be Windows 10 or later, Microsoft Entra ID joined, and Intune managed.
* Defender detects and scores; Intune evaluates compliance; Entra ID Conditional Access enforces the block or the grant.
* Enable the Intune Connection under **Defender's** Advanced Features first — this is a common first step exam candidates forget.
* Memorize the four Machine Risk Score levels (Clear, Low, Medium, High) and that a **lower** threshold equals **stronger** security.
* Access restoration is automatic once the device becomes compliant again — this is a frequently tested detail.

## Related Concepts and Common Exam Confusions

The following clarifications are not verbatim from the source material but directly support SC 200 preparation for this topic area, since these distinctions are commonly tested and easy to mix up.

### AIR vs Live Response vs Sentinel Automation

| Capability | Where It Lives | What Triggers It | Typical Use |
|---|---|---|---|
| **AIR (Automated Investigation and Remediation)** | Microsoft Defender for Endpoint | An alert on a managed endpoint | Automatic per alert investigation and remediation, governed by device group automation level |
| **Live Response** | Microsoft Defender for Endpoint | Manually started by an analyst | Real time, hands on remote investigation and remediation session on a single device (running scripts, collecting files, killing processes) |
| **Automation Rules and Playbooks** | Microsoft Sentinel | An incident or alert in Sentinel, or run manually | Incident level automation across the wider security stack, often using Logic Apps to notify teams, enrich data, or call external systems |

> **Do not confuse** AIR's device group automation level with a Microsoft Sentinel automation rule or playbook. AIR remediates on the endpoint itself; Sentinel automation rules and playbooks operate at the incident level and can span many connected data sources, not just endpoints.

### Automated Investigation vs Automatic Attack Disruption

Microsoft Defender XDR also includes **Automatic Attack Disruption**, a related but distinct capability that automatically contains a compromised user or device across the whole XDR stack (not just a single endpoint) during a high confidence, active attack such as ransomware or business email compromise. AIR focuses on investigating and remediating a specific alert; Attack Disruption focuses on rapidly containing the broader attack to buy the SOC team time. Both reduce analyst workload, but they operate at different scopes and are frequently contrasted in exam questions about Defender XDR automation.

### SC 200 Exam Tips

* If a question mentions a single endpoint and a specific alert, think **AIR**.
* If a question mentions an analyst manually running commands on one device in real time, think **Live Response**.
* If a question mentions an incident spanning multiple products, or a Logic App, think **Sentinel Automation Rules / Playbooks**.
* If a question mentions automatically containing a user or device organization wide during an active attack, think **Automatic Attack Disruption**.

## SC 200 Last Minute Revision

A one page style cheat sheet for the day before the exam.

### Core Facts to Memorize

1. Advanced Features live at `Settings → General → Advanced Features`.
2. Automated Investigation toggle enables **AIR**.
3. Automatically Resolve Alerts never overrides a manual analyst status change.
4. Allow or Block File needs Microsoft Defender Antivirus active **and** cloud based protection enabled.
5. Automation Uploads live at `Settings → Endpoints → Rules → Automation Uploads`.
6. File Content Analysis = files and email attachments; Memory Content Analysis = process memory.
7. Automation Folder Exclusions affect **Automated Investigation only**, never Defender Antivirus scanning.
8. AIR is enabled by default and works through **Device Groups**.
9. There are **five** automation levels: Full, Semi (Any Remediation), Semi (Core Folders), Semi (Non Temporary Folders), No Automation.
10. Microsoft does not recommend "No Automation."
11. Action Center has two tabs: **Pending** and **History**.
12. Block At Risk Devices needs Defender for Endpoint, Intune, and Entra ID Conditional Access together.
13. Machine Risk Score levels: **Clear, Low, Medium, High** — a lower threshold means stronger security.
14. Devices must be Windows 10+, Entra ID joined, and Intune managed for this integration to work.
15. Access is restored automatically once a device becomes compliant again.

### Frequently Confused Concepts

| Easily Confused | Key Distinction |
|---|---|
| Automation Folder Exclusions vs Defender Antivirus Exclusions | Automation Folder Exclusions only affect Automated Investigation; Antivirus exclusions are separate |
| File Content Analysis vs Memory Content Analysis | Files/attachments on disk vs memory of running processes |
| Full Automation vs Semi Automation (Core Folders) | Full = no approvals anywhere; Core Folders = approval only inside `C:\Windows\` type paths |
| AIR vs Live Response | AIR is automatic per alert; Live Response is a manual, analyst driven session |
| AIR vs Sentinel Automation Rules/Playbooks | AIR = endpoint level; Sentinel automation = incident level, cross product |
| AIR vs Automatic Attack Disruption | AIR = single alert remediation; Attack Disruption = organization wide containment during active attacks |

### Final Reminders

* Three products, three jobs: **Defender detects and scores. Intune evaluates. Entra ID enforces.**
* Lower risk threshold = stronger security posture, but potentially more blocked devices.
* Manual analyst decisions always beat automated ones.
* "No Automation" is investigated but never recommended.
* Know your tabs: **Pending** = waiting for you, **History** = already done.
