## 1. Scope and Exam Context

The SC-200 exam measures your ability to mitigate threats using three major Microsoft solution areas: **Microsoft Defender XDR**, **Microsoft Defender for Cloud**, and **Microsoft Sentinel**. This guide covers the **Cloud Security Posture Management (CSPM)** capability of Defender for Cloud, meaning how Microsoft evaluates, scores, and reports on the security posture of Azure, AWS, and Google Cloud (GCP) resources.

> **Exam Tip:** CSPM is proactive (fix weaknesses before an attack happens), while incident response and threat hunting in Sentinel and Defender XDR are largely reactive/investigative. The exam frequently tests whether you understand this distinction.

Core building blocks covered in this guide:

* **Security Policy**
* **Security Initiative**
* **Security Recommendation**
* **Security Control**
* **Secure Score**
* **Regulatory Compliance**
* **Azure Monitor Workbooks**

## 2. Security Policies, Initiatives, and Recommendations

Microsoft Defender for Cloud continuously evaluates cloud resources against **security standards, regulatory requirements, and best practices**. It does this using **Security Policies**, grouped into **Security Initiatives**, and produces **Security Recommendations** whenever resources do not meet the required configuration.

### 2.1 Security Policy

A **Security Policy** is an **Azure Policy definition** that specifies a security rule or condition your Azure resources must follow. Think of it as **one individual rule**.

Examples:

* Storage accounts must disable public access.
* Virtual machines must use managed disks.
* SQL databases must enable encryption.
* Resources must have required tags.
* Storage accounts should restrict network access.

Key facts:

* Managed through **Azure Policy**; Microsoft provides many built in policies, and organizations can create custom ones.
* Assigned via the Azure portal, PowerShell, or Azure CLI.
* Defender for Cloud mainly uses **Audit** policies to check compliance, while **Enforce (Deny)** policies can automatically block noncompliant configurations.

### 2.2 Security Initiative

A **Security Initiative** is a **collection of multiple Azure Policies** grouped together to achieve a common security objective. Think of it as a **folder containing many related security policies**.

Example: **Azure Security Benchmark Initiative** contains policies such as:

* Enable encryption
* Restrict public access
* Require MFA
* Enable Defender plans
* Restrict network access

Instead of assigning each policy individually, you assign one initiative that bundles all required policies. Initiatives can be assigned across **subscriptions** or **management groups**.

### 2.3 Default Security Initiative

When Microsoft Defender for Cloud is enabled, every subscription automatically receives the **Azure Security Benchmark** (now largely superseded in messaging by the **Microsoft Cloud Security Benchmark**, see Section 5.2). It is Microsoft authored and based on:

* CIS Controls
* NIST
* Cloud security best practices

You can edit the built in initiative, enable or disable individual policies, create custom initiatives, and add regulatory compliance standards as additional initiatives.

### 2.4 Security Recommendation

A **Security Recommendation** is an action suggested by Defender for Cloud after evaluating resources against assigned policies. If a resource violates a policy, the recommendation explains:

* What is wrong
* Why it matters
* Which resources are affected
* How to fix it

### 2.5 Continuous Assessment Cycle

```text
Azure / AWS / GCP Resources
         │
         ▼
Defender for Cloud scans resources
         │
         ▼
Compares against assigned Security Initiatives
         │
         ▼
Identifies noncompliant resources
         │
         ▼
Generates Security Recommendations
         │
         ▼
Analyst remediates the issue
         │
         ▼
Compliance status updates automatically
```

### 2.6 Quick Memory Aid

| Term | Meaning | Example |
|---|---|---|
| Security Policy | One rule | "Storage accounts must restrict network access." |
| Security Initiative | Many rules together | Azure Security Benchmark (encryption, MFA, network security, logging, identity protection) |
| Security Recommendation | Action required | "Restrict network access for this storage account." |

### SC-200 Exam Tips

* **Security Policy** = a single Azure Policy rule.
* **Security Initiative** = a collection of related Azure Policies.
* **Security Recommendation** = guidance generated when a resource does not comply with assigned policies.
* Defender for Cloud primarily uses **Audit** policies for posture assessment.
* Policies can be **built in** or **custom**.
* Initiatives can be assigned to **subscriptions** or **management groups**.
* The default initiative is the **Azure Security Benchmark / Microsoft Cloud Security Benchmark**.
* Recommendations include the issue, affected resources, and remediation guidance.
* Fixing recommendations improves **Secure Score**.

## 3. Secure Score

### 3.1 What Is Secure Score

**Secure Score** is a **security posture measurement** in Microsoft Defender for Cloud showing how well your cloud resources comply with Microsoft's security recommendations. It is displayed as:

* A percentage
* A numerical score
* Individual scores for each connected cloud environment (Azure, AWS, GCP)

Secure Score changes continuously as resources are added, removed, or reconfigured (for example, a new unsecured VM lowers the score; fixing a recommendation raises it).

> **Exam Tip:** For a Security Operations Center (SOC) analyst, Secure Score answers the question **"How secure is our cloud environment right now?"** in a single glance, instead of reviewing hundreds of individual recommendations.

### 3.2 Why Secure Score Matters

* Measures overall security posture.
* Identifies security weaknesses.
* Prioritizes remediation efforts.
* Tracks security improvements over time.
* Reduces attack surface.
* Improves regulatory compliance.
* Provides a measurable security KPI (Key Performance Indicator).

### 3.3 Components: Continuous Assessment and Recommendations

Defender for Cloud continuously scans Azure, AWS, and Google Cloud resources and evaluates them against the Azure Security Benchmark, security policies, regulatory standards, and Microsoft best practices. New assessments run automatically whenever resources change or are deployed.

Every failed assessment generates one or more recommendations, for example:

* Enable Microsoft Defender plans.
* Install Azure Monitor Agent.
* Enable disk encryption.
* Restrict management ports.
* Enable MFA.
* Configure endpoint protection.

Each recommendation contributes to one or more **Security Controls**.

### 3.4 Security Controls

A **Security Control** is a **logical group of related security recommendations**. Instead of showing hundreds of individual recommendations separately, Defender for Cloud organizes them into categories such as:

* Endpoint Protection
* Network Security
* Identity Management
* Data Protection
* Secure Management Ports
* Vulnerability Management

This helps analysts see **which area of security needs improvement** at a glance rather than reviewing recommendations one by one.

### 3.5 How Secure Score Is Calculated

Secure Score is based on **Security Controls**, not directly on individual recommendations. Each control contains multiple recommendations, and a control only receives **full points** once **every** recommendation in it is remediated for **every** affected resource.

Example, Security Control **Secure Management Ports**:

| Recommendation | Status |
|---|---|
| Close RDP from the Internet | Remediated |
| Close SSH from the Internet | Remediated |
| Use Just-in-Time (JIT) VM Access | Not remediated |
| Restrict unnecessary management ports | Not remediated |

Result: only partial points are awarded because two of the four recommendations remain open. Only once all four are remediated does the control reach maximum score.

### 3.6 The CSPM Scoring Chain

```text
Security Policy
      │
      ▼
Compliance Assessment
      │
      ▼
Security Recommendation
      │
      ▼
Security Control (group of recommendations)
      │
      ▼
Secure Score
```

> **Exam Tip:** This chain, **Policy → Assessment → Recommendation → Security Control → Secure Score**, is a very common exam relationship question. Memorize the order.

### SC-200 Exam Tips

* Secure Score measures your overall cloud security posture; higher score = more secure environment.
* Secure Score is calculated from **Security Controls**, not directly from individual recommendations.
* A Security Control receives full points only when **all** associated recommendations are remediated across **all** affected resources.
* Secure Score supports **Azure**, **AWS**, and **GCP**.
* The **Security Posture** page shows: overall Secure Score, per cloud scores, unhealthy resources, recommendations, and Security Controls.
* Remediating recommendations automatically improves Secure Score after the next reassessment.
* Secure Score is a **prioritization tool** to help analysts focus on the most impactful fixes first.

## 4. Exploring Security Recommendations

### 4.1 What Are Security Recommendations

A **Security Recommendation** is a remediation suggestion generated when a resource does not comply with a security policy or best practice. Recommendations are based primarily on:

* Azure Security Benchmark
* Azure Policies
* Regulatory compliance initiatives (such as CIS or NIST)

Each recommendation tells you: the security issue, which resources are affected, why it matters, how to fix it, and how fixing it affects Secure Score.

> **Exam Tip:** Recommendations are often the **starting point for investigating cloud misconfigurations** before they escalate into actual security incidents. This ties CSPM directly into the SOC investigation workflow.

### 4.2 Secure Score Recommendations vs All Recommendations

| View | What It Shows | Contributes to Secure Score |
|---|---|---|
| Secure Score Recommendations | Only recommendations grouped under Security Controls | Yes |
| All Recommendations | Every recommendation, including regulatory compliance and Secure Score items | Not all of them |

### 4.3 Recommendation Detail Fields

| Field | Purpose |
|---|---|
| Enforce and Deny | Prevents future noncompliant deployments |
| View Policy Definition | Shows the Azure Policy responsible for the recommendation |
| Open Query | Launches **Azure Resource Graph Explorer** to investigate affected resources |
| Severity | Risk level of the finding |
| Freshness Interval | How often the recommendation is reassessed |
| Exempted Resources | Resources excluded from the recommendation |
| MITRE ATT&CK Mapping | Available only for **Azure scored** recommendations |
| Related Recommendations | Other findings linked to the same issue |
| Remediation Steps | How to fix the problem, manually or via the **Fix** button (automated remediation, where supported) |

### 4.4 Resource Compliance Status

Every assessed resource is categorized as one of:

* **Healthy** (compliant)
* **Unhealthy** (noncompliant)
* **Not Applicable** (recommendation does not apply to this resource)

### SC-200 Exam Tips

* Recommendations are generated from the Azure Security Benchmark, Azure Policies, and regulatory compliance initiatives.
* **Secure Score Recommendations** directly affect Secure Score; **All Recommendations** includes Secure Score plus compliance related items.
* Recommendations are grouped into **Security Controls**.
* Prioritize recommendations offering the **highest potential Secure Score increase**.
* The **Fix** button automates remediation for supported recommendations.
* **Open Query** opens **Azure Resource Graph Explorer**.
* **MITRE ATT&CK mapping** applies only to Azure scored recommendations, a common distractor on the exam.

## 5. Regulatory Compliance

### 5.1 What Is Regulatory Compliance

**Regulatory Compliance** is a Defender for Cloud feature that compares your cloud resources against recognized compliance standards and industry frameworks, not just general best practices. Examples of supported frameworks include PCI DSS, ISO 27001, NIST, HIPAA, CIS Benchmarks, FedRAMP, and SOC TSP. The **Regulatory Compliance dashboard** continuously evaluates resources and updates results as they change.

> **Important:** Regulatory Compliance in Defender for Cloud does **not** guarantee certification or legal compliance. It only helps measure your security posture against the controls of a selected standard.

### 5.2 Microsoft Cloud Security Benchmark (MCSB)

* MCSB is the **default compliance benchmark assigned automatically to every Azure subscription**.
* It represents Microsoft's own recommended cloud security best practices, acting as a baseline even if an organization follows no specific regulatory framework.
* Most organizations start by addressing MCSB findings before layering on industry specific standards.

### 5.3 What Is Azure Policy

**Azure Policy** enforces, audits, and maintains compliance across Azure resources using rules called **policy definitions** that determine how resources should be configured.

| Effect | What Happens |
|---|---|
| Audit | Detects the violation but takes no blocking action |
| Deny | Blocks the noncompliant deployment |
| Deploy / Modify | Automatically fixes or remediates the issue |
| (reporting) | Generates compliance reports |

Defender for Cloud relies heavily on Azure Policy to continuously assess cloud security posture, and **every regulatory compliance standard in Defender for Cloud is implemented as an Azure Policy Initiative**.

### 5.4 Supported Regulatory Standards (examples)

| Standard | Region / Focus |
|---|---|
| PCI DSS | Payment card data |
| ISO 27001 | International information security |
| NIST SP 800-53 / NIST SP 800-171 | US federal / controlled information |
| HIPAA / HITRUST | US healthcare |
| SOC TSP | Service organization trust |
| CIS Azure Foundations | General Azure hardening baseline |
| FedRAMP | US federal cloud authorization |
| SWIFT CSP | Financial messaging |
| CMMC | US defense contractors |
| UK OFFICIAL / UK NHS | United Kingdom |
| Canada Federal PBMM | Canada |
| New Zealand ISM Restricted | New Zealand |

Other standards beyond MCSB must be **added manually** if the organization requires them.

### 5.5 Adding a New Compliance Standard

1. Open **Microsoft Defender for Cloud**.
2. Go to **Regulatory Compliance**.
3. Select **Manage Compliance Policies**.
4. Choose the subscription or management group.
5. Add the required regulatory standard.
6. Configure the scope, parameters, and remediation settings.
7. Return to the Regulatory Compliance dashboard to view the new standard.

**Prerequisites:**

* Defender for Cloud **enhanced security features** must be enabled.
* The account needs **Owner** or **Policy Contributor** permissions.

Compliance standards can be assigned at the **Management Group** or **Subscription** level. Microsoft automatically updates **Microsoft managed initiatives** when new controls or regulatory requirements are released.

### 5.6 Regulatory Compliance Workflow

```text
Regulatory Standard selected (e.g. PCI DSS)
         │
         ▼
Implemented as an Azure Policy Initiative
         │
         ▼
Azure Policy continuously evaluates resources
         │
         ▼
Compliance Assessment (Compliant / Noncompliant)
         │
         ▼
Results mapped to Regulatory Compliance dashboard
         │
         ▼
Analyst reviews failed assessments and remediates
```

The Regulatory Compliance dashboard lets you view compliance status, review failed assessments, download compliance reports, and monitor compliance over time.

### 5.7 Commonly Confused Concepts

| Term | Meaning |
|---|---|
| Azure Policy | Evaluates and enforces compliance rules |
| Policy Initiative | A collection of Azure Policies representing a compliance standard |
| Compliance Assessment | The result of evaluating a resource against a policy |
| Security Recommendation | Guidance generated when an assessment fails |
| Regulatory Compliance Dashboard | Displays compliance status across selected standards |
| Secure Score | Measures overall security posture (best practice based) |
| Regulatory Compliance | Measures adherence to a **specific named framework** (PCI DSS, ISO, etc.) |

### SC-200 Exam Tips

* Defender for Cloud continuously evaluates Azure, AWS, and GCP resources against industry standards, regulatory standards, and security benchmarks.
* Every **regulatory compliance standard** is implemented as an **Azure Policy Initiative**.
* **MCSB is assigned by default**; all other standards must be added manually.
* Regulatory Compliance does **not** equal certification, it only measures posture against a standard's controls.
* Adding a standard requires **enhanced security features enabled** plus **Owner** or **Policy Contributor** role.
* Distinguish clearly: **Secure Score** (general posture) vs **Regulatory Compliance** (adherence to a named framework).

## 6. Azure Monitor Workbooks

Azure Monitor Workbooks are interactive dashboards used to visualize, analyze, and monitor security and operational data. Defender for Cloud includes several built in workbooks that help teams track posture, compliance, vulnerabilities, updates, and alerts. Analysts can also create custom workbooks by combining data from multiple Azure data sources.

### 6.1 What Is a Workbook

A **Workbook** is an **interactive dashboard and reporting tool** in **Azure Monitor** that visualizes and monitors data from one or more Azure services using charts, graphs, maps, metrics, tables, and filters, instead of raw logs across multiple portals.

### 6.2 Built in Workbooks vs Custom Workbooks

| Type | Description |
|---|---|
| Built in | Ready to use workbooks provided by Defender for Cloud; can be customized |
| Custom | Built by organizations to combine multiple data sources, create executive reports, build SOC dashboards, visualize trends, track KPIs, and monitor org specific metrics |

### 6.3 Built in Workbook Reference Table

| Workbook | Purpose | SOC Use |
|---|---|---|
| Secure Score Over Time | Tracks Secure Score trend and how recommendations affect it | Measure progress after remediation; report to management |
| System Updates | Shows missing OS updates; filter by OS, resource, severity | Identify systems needing patching |
| Vulnerability Assessment Findings | Displays vulnerability scan results | Prioritize remediation; identify high risk systems |
| Compliance Over Time | Tracks compliance status against standards over time | Monitor improvements; prepare for audits |
| Active Alerts | Displays current alerts; filter by severity, alert type, MITRE ATT&CK tactic, location | Monitor threats; prioritize investigations |

### 6.4 Workbook Data Flow

```text
Azure, AWS, GCP resource data
         │
         ▼
Microsoft Defender for Cloud (posture, alerts, vulnerabilities)
         │
         ▼
Azure Monitor Workbooks (visualization layer)
         │
         ▼
Interactive dashboard (charts, tables, filters)
         │
         ▼
SOC analyst reviews trends and prioritizes action
```

### 6.5 Tool Comparison

| Tool | Primary Role |
|---|---|
| Azure Monitor Workbooks | Visualization and reporting dashboards |
| Azure Policy | Governance and compliance enforcement |
| Microsoft Defender XDR | Threat detection and response across endpoints, identities, email, apps |
| Microsoft Sentinel | SIEM/SOAR platform; also uses Workbooks heavily for SOC dashboards and threat hunting visualizations |

> **Exam Tip:** A very common SC-200 question asks which tool provides dashboards for Secure Score, compliance trends, vulnerabilities, and alerts. The answer is **Azure Monitor Workbooks integrated with Microsoft Defender for Cloud**. Workbooks **visualize** data, they do **not** block attacks, enforce policy, or perform automated response actions.

### SC-200 Exam Tips

* Workbooks are **visualization and reporting tools**, not detection engines.
* Azure Monitor provides the underlying Workbook engine; Defender for Cloud supplies the posture data displayed inside it.
* Know the purpose of each built in workbook (Secure Score Over Time = trend, System Updates = missing patches, Vulnerability Assessment Findings = scan results, Compliance Over Time = regulatory trend, Active Alerts = current alerts).
* Sentinel also relies heavily on Azure Monitor Workbooks for dashboards and threat hunting visualizations.
* Do not confuse Workbooks (visualization) with Azure Policy (enforcement), Defender XDR (detection and response), or Sentinel (SIEM/SOAR).

## 7. SC-200 Last Minute Revision (Cheat Sheet)

### 7.1 The One Diagram to Remember

```text
Resources (Azure / AWS / GCP)
         │
         ▼
Security Policy  (one rule, Azure Policy definition)
         │
         ▼
Security Initiative  (many policies bundled, e.g. MCSB)
         │
         ▼
Compliance Assessment  (Healthy / Unhealthy / Not Applicable)
         │
         ▼
Security Recommendation  (what, why, affected resources, how to fix)
         │
         ▼
Security Control  (group of related recommendations)
         │
         ▼
Secure Score        Regulatory Compliance Dashboard
         │                        │
         └───────────┬────────────┘
                      ▼
        Azure Monitor Workbooks (visualization)
```

### 7.2 Master Terms Table

| Term | One Line Definition |
|---|---|
| Security Policy | A single Azure Policy rule/condition |
| Security Initiative | A bundle of related policies (e.g. Azure Security Benchmark / MCSB) |
| Security Recommendation | Suggested fix when a resource fails a policy check |
| Security Control | A logical group of related recommendations |
| Secure Score | Overall posture score, calculated from Security Controls |
| Regulatory Compliance | Adherence to a named external framework (PCI DSS, ISO 27001, etc.) |
| Microsoft Cloud Security Benchmark (MCSB) | Microsoft's default baseline, auto assigned to every subscription |
| Azure Policy | Engine that audits, denies, or auto remediates configuration |
| Azure Resource Graph Explorer | Query tool opened via "Open Query" on a recommendation |
| Azure Monitor Workbook | Interactive dashboard visualizing posture, compliance, vulnerabilities, alerts |

### 7.3 Frequently Confused Pairs

| A | B | Key Difference |
|---|---|---|
| Secure Score | Regulatory Compliance | Secure Score = general best practice posture. Regulatory Compliance = adherence to a specific named standard |
| Security Policy | Security Initiative | Policy = one rule. Initiative = a collection of policies |
| Security Recommendation | Security Control | Recommendation = a single fix. Control = a group of related recommendations |
| Audit | Deny | Audit only flags noncompliance. Deny blocks the deployment outright |
| Secure Score Recommendations | All Recommendations | Former only shows Secure Score contributing items; latter shows everything including compliance only items |
| Workbooks | Azure Policy | Workbooks visualize data. Azure Policy enforces and evaluates compliance |

### 7.4 Quick Facts to Memorize

1. Defender for Cloud covers **Azure, AWS, and Google Cloud (GCP)**.
2. The default initiative assigned to every subscription is the **Microsoft Cloud Security Benchmark (MCSB)**, built on the Azure Security Benchmark, CIS Controls, and NIST.
3. Secure Score is calculated from **Security Controls**, never directly from raw recommendation counts.
4. A control needs **every** recommendation remediated on **every** affected resource for full points.
5. **MITRE ATT&CK mapping** on a recommendation is available only for **Azure scored** recommendations.
6. **Open Query** on a recommendation opens **Azure Resource Graph Explorer**.
7. Every regulatory standard in Defender for Cloud is technically an **Azure Policy Initiative** behind the scenes.
8. Adding a compliance standard requires **enhanced security features enabled** and **Owner** or **Policy Contributor** rights.
9. Regulatory Compliance results do **not** equal legal certification.
10. Workbooks live in **Azure Monitor**; they are the visualization layer, not an enforcement or detection engine.
11. Resource compliance states are only ever **Healthy**, **Unhealthy**, or **Not Applicable**.
12. Sentinel and Defender for Cloud both use **Azure Monitor Workbooks** for dashboards, this is a key cross service relationship the exam likes to test.

### 7.5 One Page Cheat Sheet

> Policy = one rule → Initiative = bundle of policies → Assessment = pass/fail check → Recommendation = suggested fix → Control = group of recommendations → Secure Score = overall number.
>
> MCSB = default baseline for every subscription. Other frameworks (PCI DSS, ISO 27001, NIST, HIPAA, FedRAMP, etc.) must be added manually and appear on the Regulatory Compliance dashboard.
>
> Azure Policy effects: **Audit** (flag only), **Deny** (block), **Deploy/Modify** (auto fix).
>
> Workbooks = Azure Monitor's interactive dashboards; Defender for Cloud supplies posture data; Sentinel also leans on Workbooks for SOC dashboards.
>
> Never confuse: Secure Score (how secure) vs Regulatory Compliance (how compliant with a named standard) vs Workbooks (how it is displayed).
