## 1. Overview: What Is Cloud Workload Protection (CWP)?

**Microsoft Defender for Cloud** is Microsoft's Cloud Security Posture Management (CSPM) and Cloud Workload Protection Platform (CWPP). It combines two roles:

* **Posture management**: continuously assesses configuration and generates recommendations (secure score).
* **Workload protection (CWP)**: a set of plans, one per resource type, that detect active threats in near real time and generate **security alerts**.

Every CWP plan discussed in this guide follows the same basic pattern once it detects a threat.

```text
Resource activity (server, app, storage, SQL, key vault, ARM, container, DNS)
  │
  ▼
Defender for Cloud plan analyzes telemetry
(Microsoft Threat Intelligence + behavioral analytics + machine learning)
  │
  ▼
Security alert generated in Microsoft Defender for Cloud
  │
  ▼
Alert forwarded to Microsoft Sentinel (SIEM)
  │
  ▼
Correlated with related signals in Microsoft Defender XDR
(endpoint, identity, email, cloud apps)
  │
  ▼
SOC analyst investigates, contains, and remediates
```

> **Exam Tip**: Almost every "Real World SOC Scenario" in this module ends the same way: alert generated in Defender for Cloud, sent to Microsoft Sentinel, correlated by Microsoft Defender XDR. If a question asks "how would a SOC team get a unified view of this alert alongside identity and endpoint signals," the answer is nearly always **Microsoft Sentinel plus Microsoft Defender XDR correlation**.

### SC-200 Exam Tips

* Defender for Cloud = **CSPM (posture) + CWP (workload protection plans)**.
* Each resource type (servers, storage, SQL, containers, and so on) has its **own CWP plan** that must be individually enabled.
* Almost all plans rely on **Microsoft Threat Intelligence** plus **behavioral analytics / machine learning**.
* Almost all plans can forward alerts to **Microsoft Sentinel** and correlate with **Microsoft Defender XDR** incidents.
* Know each plan's protected resource type cold. The exam frequently asks "which Defender plan protects X."

## 2. Microsoft Defender for Servers

**Definition**: A CWP plan that protects **Windows and Linux servers** in Azure, AWS, GCP, and on-premises. Servers outside Azure, including on-premises servers, are onboarded through **Azure Arc**.

### Plans

| Plan | Includes |
|---|---|
| **Plan 1** | Core protection via **Microsoft Defender for Endpoint (MDE)** integration and EDR |
| **Plan 2** | Everything in Plan 1, plus advanced workload protection |

> **Exam Tip**: Knowing which feature requires **Plan 2** is heavily tested.

### Plan 2 exclusive features

* Agentless vulnerability scanning
* Agentless malware scanning
* Machine secrets scanning
* File Integrity Monitoring (FIM), detects unauthorized changes to files and registry settings
* Just-in-Time (JIT) VM access, temporarily opens management ports only when needed
* Microsoft Defender Vulnerability Management Premium
* OS baseline assessment
* OS update assessment, identifies missing security patches
* DNS threat protection (absorbed from the deprecated standalone Defender for DNS plan, see Section 9)

### Data collection

| Platform | Method |
|---|---|
| Windows | Integrates with Azure services; collects security alerts and remediation information |
| Linux | Uses the **auditd** framework to collect audit records |
| Hybrid / multicloud | **Azure Arc** onboards servers outside Azure, including on-premises servers |

### SC-200 Exam Tips

* Defender for Servers is part of Microsoft Defender for Cloud.
* Protects Windows and Linux servers across Azure, AWS, GCP, and on-premises environments.
* **Azure Arc is required** to onboard servers that are not natively in Azure.
* Plan 1 gives you MDE and EDR. Plan 2 adds everything workload protection related (scanning, FIM, JIT, vulnerability management).
* Agentless scanning is available **only in Plan 2**.
* Linux audit data comes from **auditd**.
* Defender for Endpoint alerts surface directly inside Defender for Cloud.

## 3. Microsoft Defender for App Service

**Definition**: A CWP plan that protects applications hosted on **Azure App Service** (a Platform as a Service, PaaS). It focuses on **web applications and APIs**, not virtual machines or endpoints.

### What it protects

* Azure App Service web apps
* Azure hosted APIs
* App Service management interface
* Underlying App Service virtual machine instance
* Inbound and outbound application traffic

### How it detects attacks

Instead of relying on a single application's logs, Defender for Cloud analyzes telemetry across the whole Azure App Service platform: requests, responses, internal App Service logs, and attack patterns observed across many Azure customers. This cloud scale visibility lets it spot **distributed attack campaigns** that a single web app could never see on its own.

Detects: web application scanning, distributed attack campaigns, exploitation attempts against known vulnerabilities, suspicious request patterns, automated reconnaissance.

> **Key takeaway (SOC scenario)**: When many Azure hosted sites are hit by the same scripted exploitation attempt (for example, scanning for a newly disclosed RCE vulnerability), Defender for App Service recognizes the pattern as a known campaign and raises a high severity alert, even if only one request hit the organization's app. Analysts correlate the alert with Defender XDR and confirm whether the app was actually patched.

### SC-200 Exam Tips

* Protects **Azure App Service web apps and APIs**, not VMs or endpoints.
* Azure App Service = **PaaS**.
* No extra security agent is required, it is a native Azure integration.
* Detects distributed reconnaissance/scanning campaigns using cloud wide visibility.
* Generates both **security alerts** and **security recommendations**.

**Don't confuse**

| Service | Protects |
|---|---|
| Defender for App Service | Azure hosted web apps and APIs |
| Defender for Servers | Windows/Linux servers |
| Defender for Endpoint | Endpoints and servers via EDR |

## 4. Microsoft Defender for Storage

**Definition**: A CWP plan that protects **Azure Storage accounts** (Blob Storage, Azure Files, Azure Data Lake Storage Gen2) using Microsoft Threat Intelligence, security AI, and behavioral analytics.

### Benefits

* Azure native: one step enablement, no separate security infrastructure needed.
* Centralized management inside Defender for Cloud.
* Detects anonymous access, compromised credentials, activity related to social engineering, privilege abuse, suspicious access attempts, malicious uploads.
* Integrates with automation (Logic Apps, workflow automation) for scaled response.

### Hash Reputation Analysis (key exam concept)

Defender for Storage does **not scan file contents**. It calculates a file's **cryptographic hash** (a digital fingerprint) and compares that hash against Microsoft Threat Intelligence's database of known malicious file hashes.

```text
File uploaded to Blob Storage / Azure Files / Data Lake
  │
  ▼
Defender for Storage computes the file's cryptographic hash
  │
  ▼
Hash compared against Microsoft Threat Intelligence malware hash database
  │
  ▼
Match found → "Potential malware uploaded to a storage account" alert
  │
  ▼
Alert sent to Defender for Cloud and Microsoft Sentinel
  │
  ▼
Automated Logic App can quarantine the file and notify the SOC
```

> **Exam Tip**: If a question describes malware detection in storage **without content inspection**, the concept being tested is **Hash Reputation Analysis**.

### SC-200 Exam Tips

* Protects **Blob Storage, Azure Files, Data Lake Storage Gen2**.
* Azure native with one step (single click) enablement.
* Alert categories: suspicious access patterns, suspicious activities, malicious content uploads.
* Detection is hash based, not content based.
* Alerts can be exported to Sentinel or a third party SIEM.

## 5. Microsoft Defender for SQL

**Definition**: A CWP plan that protects SQL databases and database servers from SQL injection, brute force attacks, abnormal access, and vulnerabilities, using Microsoft Threat Intelligence and behavioral analytics.

### Supported databases

* Azure SQL Database
* Azure SQL Managed Instance
* Dedicated SQL Pool in Azure Synapse Analytics
* SQL Server on Azure Virtual Machines
* SQL Server on-premises (connected through Azure Arc)
* SQL Server on Windows machines without Azure Arc (limited supported scenarios)

### Two protection plans

| Plan | Protects |
|---|---|
| **Defender for Azure SQL Databases** | Azure SQL Database, Azure SQL Managed Instance, Synapse dedicated SQL pools |
| **Defender for SQL Servers on Machines** | SQL Server on Azure VMs, on-premises, hybrid via Azure Arc, other supported clouds |

### Capabilities

* **Vulnerability Assessment**: continuously scans for missing configurations, insecure settings, and produces prioritized findings reports.
* **Advanced Threat Protection**: monitors for SQL injection, brute force attacks, privilege abuse, and suspicious activity; alerts include attack description, investigation guidance, and remediation steps.

> **Exam Tip**: Microsoft Defender for Cloud also protects **Azure Database for PostgreSQL**, **Azure Database for MySQL**, and **Azure Cosmos DB**, each with detections tailored to its own attack surface. Cosmos DB protection analyzes **telemetry only**, not database contents, so there is no performance impact.

### SC-200 Exam Tips

* Two plans to memorize: Azure SQL Databases plan, and SQL Servers on Machines plan.
* Hybrid SQL Server protection extends through **Azure Arc**.
* Vulnerability Assessment ≠ Advanced Threat Protection: one finds weaknesses, the other detects active attacks.
* PostgreSQL, MySQL, and Cosmos DB are protected too, but through their own dedicated detections (see Section 6).

**Don't confuse**

| Service | Protects |
|---|---|
| Defender for SQL | SQL databases and SQL Server |
| Defender for Storage | Azure Storage accounts |
| Defender for App Service | Azure hosted web apps |
| Defender for Servers | Windows/Linux servers |

## 6. Microsoft Defender for Open Source Relational Databases

**Definition**: A CWP plan that protects **Azure Database for PostgreSQL** and **Azure Database for MySQL** by monitoring telemetry and raising alerts for suspicious behavior.

### Three alert categories (memorize)

1. **Anomalous database access and query patterns**: high numbers of failed sign ins, multiple logins with different credentials, credential guessing.
2. **Suspicious database activities**: a legitimate account behaving abnormally, often meaning it is being used from a compromised device or suspicious infrastructure.
3. **Brute force attacks**: Defender distinguishes between a simple brute force attempt, a brute force attempt against a valid account, and a **successful** brute force attack, so analysts can prioritize by real severity.

### SC-200 Exam Tips

* Protects **PostgreSQL** and **MySQL** only, not Microsoft SQL workloads.
* Three alert categories: anomalous access/query patterns, suspicious activities, brute force attacks.
* Alerts are enriched with threat intelligence.
* Sentinel ingestion and Defender XDR correlation apply here too.

> **Exam Tip**: "Which Defender capability protects Azure Database for PostgreSQL and MySQL?" → **Microsoft Defender for Open Source (Relational) Databases**, not Defender for SQL.

## 7. Microsoft Defender for Key Vault

**Definition**: A CWP plan that provides advanced threat protection for **Azure Key Vault**, which stores encryption keys, secrets, certificates, connection strings, and passwords.

### Why it matters

Key Vault often holds the "keys to the kingdom." A compromised vault can expose application secrets, database connection strings, encryption keys, certificates, and service credentials, all of which can be reused to pivot into other Azure resources.

### Benefits

* Continuously monitors for unusual or potentially harmful access attempts and exploitation attempts.
* Alerts include details, investigation guidance, and remediation recommendations.
* Alert notifications can optionally be emailed to the organization.
* Alerts are visible from the **Key Vault Security page** and the **Defender for Cloud dashboard**.

> **Exam Tip**: Always investigate every Key Vault alert, even for a trusted application or known user. A compromised identity can look completely legitimate.

### SC-200 Exam Tips

* Protects Azure Key Vault (keys, secrets, certificates, connection strings, passwords).
* Detects unusual or malicious attempts to access or exploit the vault.
* Sentinel ingestion and Defender XDR correlation apply.

## 8. Microsoft Defender for Resource Manager

**Definition**: A CWP plan that monitors **Azure Resource Manager (ARM)**, the deployment and management layer for all Azure resources, for suspicious or malicious management plane operations performed via the Azure portal, REST APIs, Azure CLI, PowerShell, or other management tools.

> **Exam Tip**: This plan protects the **management plane**, not workloads themselves. Because every Azure resource is provisioned and controlled through ARM, compromising the management plane can compromise an entire Azure environment.

### Key detections

1. **Suspicious resource management operations**: activity from suspicious IPs, attempts to disable malware protection, suspicious scripts run through VM extensions.
2. **Exploitation toolkits**: use of well known Azure attack tooling such as **MicroBurst** and **PowerZure**, associated with reconnaissance and post compromise activity.
3. **Lateral movement**: moving from the management plane into the data plane, for example using stolen management credentials to reach VMs, storage, or databases.

```text
Attacker steals Azure administrator credentials
  │
  ▼
Signs in to Azure portal / CLI / PowerShell (management plane)
  │
  ▼
Disables anti malware, deploys malicious VM extension script
  │
  ▼
Defender for Resource Manager flags suspicious management operations
  │
  ▼
Lateral movement attempted: management plane → data plane (VMs, storage, DBs)
  │
  ▼
Analyst investigates using the Azure Activity Log
  (filter by subscription, timeframe, and account)
```

### SC-200 Exam Tips

* Protects the **ARM management plane**, not individual workloads.
* Monitors operations through Azure portal, REST APIs, CLI, PowerShell.
* Watch for **MicroBurst** and **PowerZure** as named exploitation toolkits, common exam distractors.
* **Azure Activity Log** is the primary evidence source for investigating these alerts, filter by subscription, timeframe, and user account.

**Don't confuse**

| Service | Protects |
|---|---|
| Defender for Resource Manager | Azure management plane (ARM) |
| Defender for Servers | Windows/Linux servers |
| Defender for Storage | Azure Storage accounts |
| Defender for Key Vault | Azure Key Vault |
| Defender for App Service | Azure hosted web apps |

## 9. Microsoft Defender for DNS (Deprecated)

**Definition**: Previously a standalone CWP plan that monitored **DNS queries** generated by Azure resources for malicious activity such as data exfiltration, command and control (C2) communication, and contact with malicious domains.

> **Exam Tip (high value)**: The standalone **Defender for DNS plan was deprecated in August 2023**. DNS threat protection is now included in **Microsoft Defender for Servers Plan 2**. There is no separate plan to enable anymore. If the exam asks "where is DNS threat protection provided today," the answer is **Defender for Servers Plan 2**, not a standalone Defender for DNS plan.

### Detection scenarios (still relevant, now under Servers Plan 2)

* DNS tunneling (data exfiltration over DNS)
* Malware communicating with command and control (C2) servers
* Communication with phishing or malicious domains
* Communication with malicious DNS resolvers

### SC-200 Exam Tips

* Standalone Defender for DNS = **deprecated (August 2023)**.
* DNS threat protection now lives inside **Defender for Servers Plan 2**.
* Don't confuse **Microsoft Defender for DNS** (threat detection) with **Azure DNS** (Azure's DNS hosting/resolution service, a completely different product).

## 10. Microsoft Defender for Containers

**Definition**: A CWP plan that protects containerized workloads and **Kubernetes** clusters across their whole lifecycle.

### Three core capabilities

```text
Environment hardening
  │
  ▼
Vulnerability assessment
  │
  ▼
Runtime threat protection
```

1. **Environment hardening**: uses the **Azure Policy add-on for Kubernetes** to evaluate Kubernetes API requests against security best practices, and continuously assesses cluster configuration.
2. **Vulnerability assessment**: scans container images for vulnerabilities. The recommendation **"Running container images should have vulnerability findings resolved"** flags vulnerable images actively running in a cluster. This scanning is based on images stored in **Azure Container Registry (ACR)**; images not sourced from ACR show as **Not applicable**.
3. **Runtime threat protection**: detects suspicious Kubernetes activity such as exposed dashboards, creation of high privilege roles, creation of sensitive resources, and runtime attacks. Uses Kubernetes aware analytics, AI, behavioral anomaly detection, and host level threat detection. Detections map to the **MITRE ATT&CK Matrix for Containers**.

### Supported Kubernetes environments

| Environment | Notes |
|---|---|
| **Azure Kubernetes Service (AKS)** | Microsoft's managed Kubernetes service |
| **Amazon Elastic Kubernetes Service (Amazon EKS)** | Requires connecting the AWS account to Defender for Cloud, then enabling the Containers plan |
| **Azure Arc-enabled Kubernetes** | Unmanaged clusters hosted on-premises or on IaaS, hybrid/multicloud coverage |

### SC-200 Exam Tips

* Three capabilities to memorize in order: hardening, vulnerability assessment, runtime protection.
* Hardening uses the **Azure Policy add-on for Kubernetes**.
* Vulnerability scanning of running images depends on **ACR**, images from other registries show as **Not applicable**.
* Runtime detections align to **MITRE ATT&CK for Containers**.
* Supported platforms: AKS, Amazon EKS, Azure Arc enabled Kubernetes.

**Don't confuse**

| Service | Function |
|---|---|
| Defender for Containers | Protects running Kubernetes clusters end to end |
| Defender for Container Registries | Scans images stored in registries |
| Azure Policy | Enforces Kubernetes security/compliance rules |
| Azure Container Registry (ACR) | Stores images, source of vulnerability data |

## 11. Additional Defender for Cloud Protections

Beyond the named CWP plans above, Defender for Cloud extends visibility through several supporting integrations.

### Network layer threat protection

Analyzes **sample IPFIX (IP Flow Information Export) data** collected from Azure core routers using machine learning and Microsoft Threat Intelligence (also used to enrich IP reputation).

Requirements for network alerts to fire:

* The VM must have a **public IP address**, or sit behind a **load balancer with a public IP**.
* Outbound (egress) traffic must **not** be blocked by an external IDS solution.

### Azure Cosmos DB protection

Detects potential SQL injection attempts, access from suspicious IPs, access from malicious applications, abnormal access behavior, and attempts to exploit Cosmos DB accounts. Analyzes telemetry only, so there is no performance impact on the database.

### Azure WAF alert integration

Azure Application Gateway's **Web Application Firewall (WAF)** protects web apps using the **OWASP Core Rule Set (CRS) 3.2 or later**, with automatically updated rules. If WAF is licensed, its alerts stream into Defender for Cloud automatically, no extra configuration required.

### Azure DDoS Protection alert integration

Azure DDoS Protection defends internet facing resources against Distributed Denial of Service attacks (an attempt to overwhelm a service with excessive traffic). Requires a license (multiple tiers available). Alerts surface directly inside Defender for Cloud. Application design best practices remain recommended for additional resilience.

### Microsoft Defender for Cloud Apps integration

**Microsoft Defender for Cloud Apps** is a **Cloud Access Security Broker (CASB)**. Supported deployment methods:

* Log collection
* API connectors
* Reverse proxy

Once integrated, Defender for Cloud's hardening recommendations automatically surface inside Defender for Cloud Apps, with no additional configuration.

### SC-200 Exam Tips

* Network alerts require a public IP (direct or via load balancer) and unblocked egress traffic.
* Cosmos DB protection is **telemetry based**, not content based, no performance hit.
* WAF uses **OWASP CRS 3.2+**; alerts stream automatically once licensed.
* DDoS Protection requires a license and protects internet facing resources.
* Defender for Cloud Apps = **CASB**; deployment via log collection, API connectors, or reverse proxy.

**Don't confuse**

| Service | Role |
|---|---|
| Azure WAF | Blocks web application attacks |
| Azure DDoS Protection | Blocks volumetric denial of service attacks |
| Microsoft Defender for Cloud Apps | CASB, visibility/control across cloud apps |
| Microsoft Defender for Cloud | Central hub for alerts, recommendations, posture |

## 13. SC-200 Last Minute Revision (Cheat Sheet)

### Must know facts

* Microsoft Defender for Cloud = **CSPM + CWP**. CWP plans are enabled per resource type.
* Nearly every plan uses **Microsoft Threat Intelligence + behavioral analytics/ML**, and every plan can send alerts to **Microsoft Sentinel**, which then correlates with **Microsoft Defender XDR**.
* **Azure Arc** is the universal bridge for protecting resources outside Azure, including on-premises resources (servers, SQL Server, Kubernetes).

### Frequently confused pairs

| If the exam says... | The correct answer is... |
|---|---|
| Protects Azure hosted web apps/APIs | Defender for **App Service**, not Defender for Servers |
| Protects Blob Storage/Files/Data Lake | Defender for **Storage** |
| Protects Azure SQL / SQL Server | Defender for **SQL** |
| Protects PostgreSQL / MySQL | Defender for **Open Source (Relational) Databases** |
| Protects Key Vault | Defender for **Key Vault** |
| Protects the ARM management plane | Defender for **Resource Manager** |
| Monitors DNS queries today | Defender for **Servers Plan 2** (standalone DNS plan deprecated August 2023) |
| Protects Kubernetes/containers | Defender for **Containers** |
| No file content scanning, hash based malware detection | **Hash Reputation Analysis** (Defender for Storage) |
| CASB across cloud apps | Microsoft Defender for **Cloud Apps** |

### Plan 2 only features (Defender for Servers)

1. Agentless vulnerability scanning
2. Agentless malware scanning
3. Machine secrets scanning
4. File Integrity Monitoring (FIM)
5. Just-in-Time (JIT) VM access
6. Defender Vulnerability Management Premium
7. OS baseline assessment
8. OS update assessment
9. DNS threat protection

### Key numbers and thresholds

* Defender for DNS deprecated: **August 2023**.
* WAF rule set: **OWASP CRS 3.2 or later**.
* Kubernetes vulnerability scanning source: **Azure Container Registry (ACR)** only.

### One page incident flow (memorize this shape)

```text
Threat activity on a protected resource
  │
  ▼
Defender for Cloud CWP plan detects it
  │
  ▼
Security alert + remediation guidance generated
  │
  ▼
Alert ingested into Microsoft Sentinel
  │
  ▼
Microsoft Defender XDR correlates with endpoint, identity, email, and cloud app signals
  │
  ▼
SOC analyst investigates root cause, contains, and remediates
  │
  ▼
Recommendations reviewed to prevent recurrence
```

### Quick self test prompts

1. Which plan protects a compromised storage account uploading ransomware, and how does it detect it without scanning content? → **Defender for Storage, Hash Reputation Analysis.**
2. Which log is the primary evidence source for a suspicious Azure Resource Manager operation? → **Azure Activity Log.**
3. Which tools are named examples of Azure exploitation toolkits under Defender for Resource Manager? → **MicroBurst and PowerZure.**
4. Where does DNS threat protection live today? → **Microsoft Defender for Servers Plan 2.**
5. Which registry is required for Defender for Containers to assess a running image's vulnerabilities? → **Azure Container Registry (ACR).**
6. What are the three alert categories for Defender for Open Source Databases? → **Anomalous access/query patterns, suspicious database activities, brute force attacks.**
