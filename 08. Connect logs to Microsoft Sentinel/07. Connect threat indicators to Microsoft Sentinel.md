## 1. Threat Intelligence Fundamentals

### 1.1 What Is Threat Intelligence

**Threat Intelligence** is information about known or potential cyber threats that helps an organization detect, investigate, and respond to attacks. It is built from **Indicators of Compromise (IOCs)**.

### 1.2 Indicators of Compromise (IOC)

An **IOC** is a piece of information that shows a system may have been attacked or may be communicating with malicious infrastructure. Microsoft Sentinel imports IOCs and continuously compares them against collected log data.

| IOC Type | Example |
|---|---|
| IP Address | 185.220.101.5 |
| Domain | malicious-example.com |
| URL | http://malicious-example.com/login |
| File Hash | SHA256 value |
| Email Address | attacker@example.com |

### 1.3 Sentinel Features Built on Threat Intelligence

| Feature | Purpose |
|---|---|
| **Analytics Rules** | Automatically compare collected log events against imported IOCs. A match can raise an alert and create an incident. |
| **Workbooks** | Dashboards that visualize imported indicators, analytics rule results, IOC matches, and threat intelligence trends. |
| **Hunting Queries** | Let analysts proactively search historical logs for IOC matches, even for activity that happened before an analytics rule existed. |
| **Playbooks** | Automate response actions after an IOC match occurs, for example blocking a malicious IP, sending a notification, creating a ticket, disabling a user account, or isolating an endpoint. Playbooks are built with **Microsoft Sentinel automation** together with **Azure Logic Apps**. |

```text
Firewall Log (Source IP: 185.220.101.5)
        │
        ▼
Matches Imported IOC
        │
        ▼
Analytics Rule Triggers
        │
        ▼
Alert
        │
        ▼
Incident
```

> **Exam Tip:** Hunting Queries are proactive (analyst searches history). Analytics Rules are reactive/automatic (system compares logs continuously and raises alerts on its own).

### SC-200 Exam Tips

* Threat Intelligence is made of IOCs such as IP addresses, domains, URLs, file hashes, and email addresses.
* **Analytics Rules** generate alerts and incidents automatically when a log matches an IOC.
* **Workbooks** visualize threat intelligence, they do not generate alerts.
* **Hunting Queries** are analyst driven and search historical data.
* **Playbooks** run automated response actions and depend on **Azure Logic Apps**.

## 2. Ways to Import Threat Intelligence into Sentinel

### 2.1 Microsoft Defender Threat Intelligence (MDTI)

**MDTI** is Microsoft's cloud based threat intelligence service. It provides Microsoft maintained, public, open source, and high fidelity IOCs (malicious IPs, domains, URLs, file hashes) that can be streamed straight into Sentinel.

### 2.2 Threat Intelligence Platforms (TIP)

A **TIP** is a third party platform that collects, manages, and distributes threat intelligence, often aggregating indicators from many sources. Sentinel can import indicators from supported TIPs.

### 2.3 TAXII Servers

**TAXII (Trusted Automated eXchange of Intelligence Information)** is a standard protocol for sharing cyber threat intelligence. Organizations use TAXII servers to exchange IOCs automatically instead of manually importing CSV files.

```text
Threat Feed
        │
        ▼
TAXII Server
        │
        ▼
Microsoft Sentinel
```

### 2.4 Microsoft Graph Security Indicators API

The **Microsoft Graph Security Indicators API** lets applications programmatically upload threat indicators into Sentinel, enabling automated integration with custom security solutions or scripts.

> **Exam Tip:** Notice the pattern across all four methods: MDTI and TIP feeds are largely **pull** based (Sentinel or a solution imports them), while TAXII is **pull** based on a schedule, and API driven methods are **push** based (an external system sends data into Sentinel).

### SC-200 Exam Tips

* Four ways to bring threat intelligence into Sentinel: **MDTI**, **TIP**, **TAXII servers**, and the **Microsoft Graph Security Indicators API**.
* **MDTI** = Microsoft's own curated feed.
* **TIP** = generic term for third party intelligence platforms.
* **TAXII** = standard protocol, requires a TAXII server.
* **Graph Security Indicators API** = programmatic upload path used by custom applications.

## 3. Threat Intelligence Data Connectors and the ThreatIntelligenceIndicator Table

Microsoft Sentinel ships **five** Threat Intelligence data connectors:

1. Threat Intelligence, TAXII
2. Microsoft Defender Threat Intelligence
3. Premium Microsoft Defender Threat Intelligence
4. Threat Intelligence Platforms
5. Threat Intelligence Upload API (Preview)

> **Exam Tip:** Each connector has a different setup process, but **all five write their imported indicators into the same destination table**.

### The ThreatIntelligenceIndicator Table

The **ThreatIntelligenceIndicator** table is where Sentinel stores every imported threat indicator, no matter which connector brought it in. Analytics rules, hunting queries, and workbooks all read from this single table.

```text
MDTI        TAXII        TIP        Upload API
    │           │           │            │
    └───────────┴─────┬─────┴────────────┘
                       ▼
        ThreatIntelligenceIndicator Table
                       │
                       ▼
   Analytics Rules · Hunting Queries · Workbooks
```

### SC-200 Exam Tips

* Memorize the number: **five** Threat Intelligence connectors.
* Whichever connector is used, imported data always lands in **ThreatIntelligenceIndicator**.
* Sentinel features (analytics, hunting, workbooks) query this one table regardless of source.

## 5. Connect the Microsoft Defender Threat Intelligence Connector

### 5.1 What Is MDTI

**Microsoft Defender Threat Intelligence (MDTI)** is Microsoft's cloud based threat intelligence service, providing public, open source, and high fidelity IOCs. Connecting MDTI to Sentinel automatically imports these indicators for detection, investigation, hunting, and automation.

### 5.2 Prerequisite: Install the Threat Intelligence Solution

Before enabling the MDTI connector, install the **Threat Intelligence** solution from the **Content Hub**. This solution adds:

* Threat Intelligence connectors
* Analytics rule templates
* Hunting queries
* Workbooks
* Playbooks

that all work with threat intelligence data.

### 5.3 Connector Options

| Option | Notes |
|---|---|
| Microsoft Defender Threat Intelligence | Standard, no additional licensing noted |
| Premium Microsoft Defender Threat Intelligence | Paid connector. Requires **Workspace Read and Write permissions** and the **MDTI API Access SKU** |

### 5.4 Steps to Enable the Connector

```text
Azure portal or Defender portal
        │
        ▼
Microsoft Sentinel
        │
        ▼
Configuration → Data connectors
        │
        ▼
Search "Defender Threat Intelligence"
        │
        ▼
Open connector page
        │
        ▼
Select "Connect"
        │
        ▼
Status changes to "Connected"
```

### SC-200 Exam Tips

* Always **install the Threat Intelligence solution from the Content Hub first**, before trying to enable the MDTI connector.
* There are two connector flavors: standard **Microsoft Defender Threat Intelligence** and **Premium Microsoft Defender Threat Intelligence**.
* Premium requires **Workspace Read and Write permissions** plus the **MDTI API Access SKU** because it is a paid feature.
* After configuration, confirm the connector status reads **Connected**.
* Imported indicators still land in the **ThreatIntelligenceIndicator** table.

## 6. Connect the Threat Intelligence TAXII Connector

### 6.1 What Is TAXII

**Trusted Automated eXchange of Intelligence Information (TAXII)** is a standardized protocol for automatically exchanging cyber threat intelligence between organizations and security platforms. Sentinel supports both **TAXII 2.0** and **TAXII 2.1**. A **TAXII Server** is a host that serves threat intelligence feeds; think of it as an online repository of continuously updated threat intelligence.

Indicators retrieved through TAXII can include IP addresses, domains, URLs, and file hashes.

### 6.2 Configuration Values

| Required | Sometimes Required |
|---|---|
| Friendly Name | Username |
| API Root URL | Password |
| Collection ID | |

**Prerequisites:** Workspace Read and Write permissions, the TAXII Server URI, and the Collection ID.

**Polling Frequency** controls how often Sentinel checks the TAXII server for new indicators (the module's example used **Once an hour**).

### 6.3 What Happens After Connecting

```text
Microsoft Sentinel connects to TAXII Server
              │
              ▼
   TAXII Server returns indicators
              │
              ▼
   Sentinel imports the indicators
              │
              ▼
Stored in ThreatIntelligenceIndicator Table
              │
              ▼
Analytics Rules compare incoming logs
              │
              ▼
   Matching events → Alert → Incident
```

### SC-200 Exam Tips

* TAXII stands for **Trusted Automated eXchange of Intelligence Information**.
* Sentinel supports **TAXII 2.0** and **TAXII 2.1**.
* Required connector fields: **Friendly Name**, **API Root URL**, **Collection ID** (Username and Password only if the server needs them).
* **Polling Frequency** governs how often Sentinel pulls new data, this is a pull based connector.
* Imported indicators still flow into **ThreatIntelligenceIndicator**.

## 7. Connect the Threat Intelligence Upload API Connector

### 7.1 What Is the Upload API

The **Threat Intelligence Upload API** lets organizations **programmatically upload custom threat intelligence** into Sentinel without using a traditional data connector. It is built for organizations that already run a TIP, a custom threat intelligence application, or a security orchestration platform. The Upload API is installed as part of the **Microsoft Sentinel Threat Intelligence solution**.

### 7.2 What Is STIX

**Structured Threat Information eXpression (STIX)** is the industry standard format for representing cyber threat intelligence. STIX objects can represent IOCs, threat actors, malware, campaigns, attack patterns, and relationships between threats. The Upload API accepts STIX objects and imports them into Sentinel.

> **Exam Tip, STIX vs TAXII:** These two standards are companions but are not the same thing. **STIX is the data format** (what the threat intelligence looks like). **TAXII is a transport protocol** (one way to move that data around). The Upload API is a different transport path that also carries STIX formatted data, just without needing a TAXII server.

### 7.3 Why Use the Upload API

```text
   WITHOUT the Upload API                  WITH the Upload API

        Custom TIP                              Custom TIP
            │                                        │
            ▼                                        ▼
     Manual CSV Export                          Upload API
            │                                        │
            ▼                                        ▼
      Manual Import                          Microsoft Sentinel
```

### 7.4 Upload API vs TAXII Connector

| | TAXII Connector | Upload API |
|---|---|---|
| Direction | Sentinel **pulls** from a TAXII server | Application **pushes** STIX objects |
| Needs a TAXII server | Yes | No |
| Best for | A provider that already exposes a TAXII feed | Custom applications or TIPs without a TAXII server |

> **Exam Tip:** TAXII pulls, Upload API pushes.

### 7.5 Prerequisites

* Read and Write permissions on the Microsoft Sentinel workspace.
* Ability to register a Microsoft Entra application.
* The Microsoft Entra application must be assigned the **Microsoft Sentinel Contributor** role at the workspace level.

### 7.6 Configuration Steps

**Step 1, Register a Microsoft Entra Application**
Create an application registration in Microsoft Entra ID and record its **Application (Client) ID**. This app authenticates to Sentinel when uploading STIX objects, applications (not users) authenticate through Microsoft Entra identities.

**Step 2, Generate a Client Secret**
Create and securely store a **Client Secret**, this functions like the application's password and is required during OAuth authentication.

**Step 3, Assign the Microsoft Sentinel Contributor Role**
This role lets an identity manage Sentinel resources, for the Upload API it grants permission to ingest threat intelligence. Without it, the Upload API cannot write STIX objects to Sentinel.

```text
Log Analytics workspaces
        │
        ▼
Access control (IAM)
        │
        ▼
Add → Add role assignment
        │
        ▼
Select role: Microsoft Sentinel Contributor
        │
        ▼
Next
        │
        ▼
Members → User, group, or service principal
        │
        ▼
Select the registered Microsoft Entra application
        │
        ▼
Review + assign
```

**Step 4, Configure the TIP or Custom Application**
Configure the TIP or custom application with the **Application (Client) ID**, a **Microsoft Entra OAuth 2.0 Access Token**, and the **Microsoft Sentinel Workspace ID**, then submit STIX objects to the Upload API. Uploaded objects should appear in Sentinel within a few minutes.

| Term | Meaning |
|---|---|
| OAuth 2.0 Access Token | Temporary token issued by Microsoft Entra ID after successful authentication, proves the app is authorized to upload |
| Workspace ID | Uniquely identifies the target Sentinel (Log Analytics) workspace |

### 7.8 Real World SOC Scenario, Condensed

A company builds its own TIP that aggregates internal malware analysis with external feeds and exports the results as STIX objects. The SOC registers a Microsoft Entra application, creates a Client Secret, assigns the Microsoft Sentinel Contributor role, and configures the TIP with the Client ID, OAuth token, and Workspace ID. The TIP then pushes STIX objects through the Upload API, Sentinel stores them in ThreatIntelligenceIndicator, and when a firewall log later matches an uploaded malicious IP, an analytics rule fires an alert and opens an incident for investigation.

### Key Terms to Remember

| Term | Definition |
|---|---|
| STIX | Standard format for representing cyber threat intelligence |
| Upload API | Pushes STIX objects directly into Sentinel |
| Microsoft Entra Application | Identity used by the application, not a user |
| Client Secret | Application credential, acts like a password |
| OAuth 2.0 Access Token | Authentication token proving the app can call the API |
| Microsoft Sentinel Contributor | Role required to upload threat intelligence |
| ThreatIntelligenceIndicator | Table that stores uploaded and imported indicators |

### SC-200 Exam Tips

* The Upload API is for **programmatic push** of STIX objects, no TAXII server required.
* It ships as part of the **Microsoft Sentinel Threat Intelligence solution**.
* Setup order to memorize: **register Entra app → create client secret → assign Sentinel Contributor role → configure app with Client ID, OAuth token, Workspace ID**.
* **TAXII pulls, Upload API pushes.**
* STIX is the **format**, TAXII and the Upload API are two different **transport mechanisms** for that format.

## 8. View Threat Indicators with KQL

### 8.1 Where Indicators Live

Indicators imported from MDTI, TAXII, the Upload API, and TIPs are all stored in the **ThreatIntelligenceIndicator** table. Analytics Rules, Workbooks, and Hunting Queries all query this table.

### 8.2 Basic Query

To view every imported indicator, open **Microsoft Sentinel → Logs (General section)** and run:

```kql
ThreatIntelligenceIndicator
```

> **Exam Tip:** Typing a table name by itself in KQL returns every row and column from that table. In real investigations, analysts usually add filters, for example `| where ConfidenceScore > 70` or `| take 50`, but the exam mainly expects you to know the table name and that this bare query returns all indicators.

### 8.3 Important Update: New STIX Tables

Microsoft is moving Threat Intelligence storage to two new tables that support STIX indicator and object schemas:

| Table | Purpose |
|---|---|
| **ThreatIntelIndicators** | New table for STIX indicators |
| **ThreatIntelObjects** | New table for STIX objects |

Timeline from the source material:

* **April 3, 2025**, both new tables entered public preview. Sentinel began ingesting all threat intelligence into them.
* Ingestion into the legacy **ThreatIntelligenceIndicator** table continued in parallel until **July 31, 2025**.

> **Exam Tip:** During the migration window, data existed in both the old and new tables. Any custom queries, analytics rules, workbooks, or automation built against the legacy table needed to be updated to point at **ThreatIntelIndicators** and **ThreatIntelObjects** before the old table stopped receiving new data.

### SC-200 Exam Tips

* Legacy table name: **ThreatIntelligenceIndicator** (singular "Indicator").
* New table names: **ThreatIntelIndicators** and **ThreatIntelObjects** (note the shortened "ThreatIntel" prefix and the plural "Indicators").
* Know the key dates: **preview started April 3, 2025**, **legacy ingestion ended July 31, 2025**.
* A bare table name in KQL, for example `ThreatIntelligenceIndicator`, returns the full table.

## 9. SC-200 Last Minute Revision

### 9.1 Facts to Memorize

* Threat intelligence is made of **IOCs**: IP addresses, domains, URLs, file hashes, email addresses.
* There are **five** Threat Intelligence data connectors in Sentinel.
* Every connector, regardless of type, writes to **ThreatIntelligenceIndicator** (legacy) or the new **ThreatIntelIndicators / ThreatIntelObjects** tables.
* **Playbooks** require **Azure Logic Apps**.
* **Premium MDTI** needs the **MDTI API Access SKU** plus Workspace Read and Write permissions.
* The Upload API needs an **Entra application**, a **Client Secret**, and the **Microsoft Sentinel Contributor** role.
* New STIX tables went to preview on **April 3, 2025**; the legacy table stopped receiving data on **July 31, 2025**.

### 9.2 Frequently Confused Concepts

| Easily Confused | How to Tell Them Apart |
|---|---|
| Analytics Rules vs Hunting Queries | Analytics Rules run automatically and can create incidents. Hunting Queries are run manually by an analyst against historical data. |
| STIX vs TAXII | STIX is the **data format**. TAXII is a **transport protocol** used to move STIX data. |
| TAXII Connector vs Upload API | TAXII **pulls** from a server on a schedule. Upload API **pushes** data from an application, no server needed. |
| MDTI vs TIP | MDTI is Microsoft's own built in feed. TIP is a generic term for any third party intelligence platform. |
| ThreatIntelligenceIndicator vs ThreatIntelIndicators | The first is the **legacy** table (singular Indicator). The second plus ThreatIntelObjects are the **new** STIX schema tables. |
| Alert vs Incident | An alert is a single detection. An incident is a case that groups one or more related alerts for investigation. |

### 9.3 Connector Comparison Table

| Connector | Direction | Needs TAXII Server | Needs Entra App | Extra Requirement |
|---|---|---|---|---|
| Microsoft Defender Threat Intelligence | Pull, built in | No | No | Content Hub solution installed |
| Premium Microsoft Defender Threat Intelligence | Pull, built in | No | No | MDTI API Access SKU, Read/Write permissions |
| Threat Intelligence, TAXII | Pull, scheduled | Yes | No | Friendly Name, API Root URL, Collection ID |
| Threat Intelligence Platforms | Varies by TIP | Varies | Varies | Vendor specific setup |
| Threat Intelligence Upload API (Preview) | Push | No | Yes | Client Secret, Sentinel Contributor role, OAuth token, Workspace ID |

### 9.4 Important KQL Syntax

```kql
// Return every imported threat indicator
ThreatIntelligenceIndicator
```

```kql
// Practical variant analysts commonly use
ThreatIntelligenceIndicator
| take 50
```

> **Exam Tip:** For SC-200 you mainly need to recognize the correct table name and know that a table name alone is valid KQL that returns everything in it.
