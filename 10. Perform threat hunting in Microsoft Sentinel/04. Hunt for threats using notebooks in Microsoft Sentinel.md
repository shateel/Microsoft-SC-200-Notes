## 1. Accessing Microsoft Sentinel Data With External Tools

### 1.1 Core Concept

Microsoft Sentinel stores its data in an **Azure Log Analytics workspace**, a data store built for fast **Kusto Query Language (KQL)** queries. Analysts normally query this data through the Azure portal or the Microsoft Defender portal, but the same data is reachable **programmatically** through standard APIs.

This matters for:

* SOC analysts automating repetitive investigation steps
* Security engineers building custom applications
* Automation developers integrating Sentinel with third party platforms
* Analysts running Python based threat hunting or machine learning analysis

### 1.2 Why Go Beyond the Portal

The Sentinel portal covers threat hunting, incident investigation, alert analysis, and dashboard visualization well, but analysts sometimes need more flexibility, for example:

* Automating investigations and scheduled scripts
* Building custom dashboards
* Integrating with third party security platforms
* Running advanced Python analysis or machine learning models

### 1.3 How External Tools Reach Sentinel Data

An external tool (a Python script, PowerShell script, custom application, or notebook) sends a request to the **Log Analytics API** instead of opening the portal manually. The API executes the KQL query and returns results. Both the Azure portal and the Microsoft Defender portal use this same underlying API, so external tools are simply calling the same door directly.

```text
External Tool
(Python Script, PowerShell Script, Custom App, Notebook)
        │
        ▼
Log Analytics API
        │
        ▼
Log Analytics Workspace
        │
        ▼
KQL Query Executes
        │
        ▼
Results Returned
```

### 1.4 SC 200 Exam Tips

> * Microsoft Sentinel stores its security data in a **Log Analytics workspace**.
> * The Azure portal, Microsoft Defender portal, and external tools all reach that data through the same **Log Analytics API**.
> * Notebooks, Kqlmagic, and msticpy are all examples of external tools that use this API.

### 1.5 Quick Memorization

| Term | Meaning |
|---|---|
| Log Analytics Workspace | Stores Microsoft Sentinel log data |
| Log Analytics API | Lets external tools query the workspace programmatically |

## 2. What Is a Notebook

### 2.1 Definition

A **notebook** is an interactive investigation document that mixes explanatory text, Python code, KQL queries, charts, investigation notes, and code output in one place. Unlike a normal Python script that runs top to bottom in one go, a notebook is executed **one section (called a cell) at a time**, so an analyst can review each result before deciding the next step.

Think of a notebook as a **digital investigation workbook**.

### 2.2 Why SOC Analysts Use Notebooks

Without a notebook, a single investigation can be scattered across many tools:

```text
Microsoft Sentinel + Excel + Python Scripts + Word Document
+ Threat Intelligence Website + PowerPoint
```

This is inefficient and hard to reproduce later. A notebook keeps everything in one document:

```text
Notebook
        │
        ├── Query Microsoft Sentinel
        ├── Analyze Results
        ├── Add Threat Intelligence
        ├── Draw Charts
        ├── Write Investigation Notes
        └── Save Everything Together
```

**Example without a notebook:** open Sentinel, run KQL, copy results into Excel, open VirusTotal, check the IP, copy findings into Word, take screenshots, then email the report. Many separate manual steps.

**Example with a notebook:** run KQL, get results, check IP reputation, draw a timeline, map login locations, analyze processes, and save the investigation, all inside one interactive document.

> **Exam takeaway:** the value of a notebook is that it removes the need to jump between separate tools during an investigation, and it produces a single reusable record of the work.

### 2.3 What a Notebook Can Contain

| Content Type | Used For |
|---|---|
| Text | Investigation notes, hypotheses, conclusions, documentation |
| Python code | Processing data, calling APIs, calculations, automating steps |
| KQL queries | Querying Sentinel directly, commonly through **Kqlmagic** |
| Visualizations | Timelines, maps, charts, and graphs that reveal patterns raw log rows would hide |

Microsoft Sentinel ships notebooks created by Microsoft security analysts, some ready to use for specific scenarios and others as customizable samples. More notebooks can be imported from the Microsoft Sentinel community on GitHub, so an analyst does not always need to build one from nothing.

### 2.4 The Two Components of Every Notebook

| Component | Role |
|---|---|
| **Browser based interface** | The editor the analyst interacts with: writing code, entering KQL, running commands, and viewing charts and results |
| **Kernel** | The engine that actually reads and runs the Python code, returns output, and handles errors |

> Without the kernel, a notebook is only a text document. It cannot execute anything.

### 2.5 The Kernel Runs on an Azure Virtual Machine

The Microsoft Sentinel notebook kernel runs on an **Azure Virtual Machine (VM)**. Organizations can pick more powerful VM sizes for heavier workloads such as complex machine learning.

```text
Notebook
(Needs CPU, RAM, and Python)
        │
        ▼
Azure Virtual Machine
        │
        ▼
Python Executes
        │
        ▼
Results Returned
```

### 2.6 Common Python Libraries

Sentinel notebooks commonly rely on:

* **pandas**: data processing and analysis
* **matplotlib** and **bokeh**: visualizations and graphics
* **msticpy**: security investigation and threat hunting functions

These support statistics, numerical computing, and machine learning as well as charting.

### 2.7 SC 200 Exam Tips

> * A notebook is an **interactive investigation environment**, not just a saved script.
> * It combines Python code, KQL queries, investigation notes, visualizations, and results.
> * Every notebook has exactly two components: the **browser based interface** and the **kernel**.
> * The kernel runs on an **Azure Virtual Machine**.
> * Notebooks can be imported ready made, used as customizable samples, or pulled from the Sentinel GitHub community.

### 2.8 Quick Memorization

| Term | Meaning |
|---|---|
| Notebook | Interactive investigation workspace, executed cell by cell |
| Interface | Where you write and view code and results |
| Kernel | Executes the Python code |
| Azure VM | Hardware that runs the kernel |
| pandas | Data analysis library |
| matplotlib / bokeh | Visualization libraries |

## 3. Kqlmagic

### 3.1 What It Is

**Kqlmagic** is a Python library that simplifies running KQL queries from Python environments such as Jupyter notebooks. It wraps the underlying communication so an analyst does not need to manually authenticate to Azure, build REST API requests, handle responses, or parse the returned JSON. The analyst can focus on writing KQL instead of writing API code.

### 3.2 Workflow

```text
Jupyter Notebook
        │
        ▼
Kqlmagic
        │
        ▼
Log Analytics API
        │
        ▼
Microsoft Sentinel
        │
        ▼
KQL Results
```

### 3.3 SC 200 Exam Tips

> * **Kqlmagic** exists purely to make running KQL from Python easy; it does not enrich, analyze, or visualize data on its own.
> * Kqlmagic and msticpy are both commonly used together inside Jupyter notebooks for threat hunting.

## 4. msticpy

### 4.1 What It Is

**msticpy** (Microsoft Threat Intelligence Python Security Tools) is a Python library built specifically for **security investigations and threat hunting**. Many of its components began as real Jupyter notebook code used in actual investigations. Unlike Kqlmagic, which focuses only on running KQL, msticpy offers a broader set of capabilities for end to end investigations: gathering data from multiple sources, enriching indicators with threat intelligence, analyzing relationships, and visualizing attack patterns.

### 4.2 Core Capabilities

| Stage | What Happens |
|---|---|
| **1. Acquire and Enrich** | Retrieve data from Microsoft Sentinel, Microsoft Defender XDR, Microsoft Defender for Endpoint, and Microsoft Security Graph; enrich it with additional context |
| **2. Analyze** | Identify suspicious logons, correlate security events, investigate user activity, examine process execution |
| **3. Visualize** | Show relationships between entities, attack timelines, geographic information, and investigation paths |

```text
Microsoft Sentinel
Microsoft Defender XDR
Microsoft Defender for Endpoint
Microsoft Security Graph
        │
        ▼
msticpy
        │
        ├── Acquire Data
        ├── Enrich Data
        ├── Analyze Data
        └── Visualize Data
```

### 4.3 Predefined Queries and Functions

A key advantage of msticpy is that it ships **predefined queries and functions** for Microsoft security services, so analysts do not need to write every KQL query from scratch. Example: **list_logons_by_account** retrieves logon events for a specified account, making investigations faster and more consistent.

### 4.4 SC 200 Exam Tips

> * msticpy is a **Python security investigation toolkit**, broader in scope than Kqlmagic.
> * Remember the three stage workflow: **Acquire and Enrich, Analyze, Visualize**.
> * msticpy includes predefined investigation functions such as **list_logons_by_account**.
> * msticpy can pull data from Sentinel, Defender XDR, Defender for Endpoint, and Microsoft Security Graph.

### 4.5 Quick Memorization

| Term | Meaning |
|---|---|
| msticpy | Python toolkit for investigations |
| Acquire, Enrich, Analyze, Visualize | msticpy's core workflow, in order |
| list_logons_by_account | Predefined msticpy function for logon investigation |

## 5. Kqlmagic vs msticpy (Quick Comparison)

This comparison is a frequent source of confusion on the exam. Keep it simple:

| Aspect | Kqlmagic | msticpy |
|---|---|---|
| Primary purpose | Run KQL queries easily from Python | Full investigation toolkit |
| Scope | Query execution only | Acquire, enrich, analyze, visualize |
| Typical exam clue | "Run KQL from Python quickly" | "Enrich with threat intelligence" or "visualize attack patterns" |
| Relationship | Often used alongside msticpy | Broader capability set, commonly paired with Kqlmagic or a Query Provider |

> **Exam tip:** if a question emphasizes simply *executing* a KQL query from Python, think Kqlmagic. If it emphasizes *investigating*, *enriching with threat intelligence*, or *visualizing*, think msticpy.

## 6. Creating a Notebook: Environment Setup

### 6.1 Why Sentinel Needs Azure Machine Learning

A common point of confusion: **why can't Microsoft Sentinel run notebooks directly?** Because notebooks execute Python code, and Python code needs CPU, memory, storage, and installed libraries. Microsoft Sentinel is a SIEM and SOAR platform, not a Python execution environment, so it relies on an **Azure Machine Learning (Azure ML) Workspace** to provide that environment.

Creating a notebook is **not just opening a file**. It requires:

1. Creating an Azure Machine Learning workspace
2. Creating a compute instance (a virtual machine)
3. Opening a notebook template
4. Authenticating to Azure
5. Initializing the notebook environment
6. Running Python code

### 6.2 Overall Architecture

```text
SOC Analyst
        │
        ▼
Microsoft Sentinel
        │
        ▼
Azure Machine Learning Workspace
        │
        ▼
Compute Instance (Azure VM)
        │
        ▼
Jupyter Notebook
        │
        ▼
Python Executes
```

### 6.3 What Is an Azure Machine Learning Workspace

An **Azure Machine Learning Workspace** is a central service that manages machine learning resources: notebooks, compute instances, models, datasets, and experiments. For Sentinel, its main role is narrower: it provides notebook storage, notebook execution, compute management, and the Python environment. Azure ML supports much more advanced machine learning than SC 200 requires; for this exam, treat it as the platform that hosts and runs Sentinel notebooks.

> **Do not confuse the two "workspaces":** the **Log Analytics workspace** stores Sentinel's log data. The **Azure Machine Learning workspace** hosts the compute and environment that *runs* notebooks. They are separate Azure resources with separate purposes.

### 6.4 Creating the Azure Machine Learning Workspace

1. Open **Notebooks** from the **Threat Management** section of Microsoft Sentinel.
2. Choose to configure Azure Machine Learning.
3. Create a new Azure ML Workspace.
4. Select the Azure subscription.
5. Create or choose a resource group.
6. Give the workspace a unique name.
7. Choose the Azure region.
8. Leave the default Storage Account, Key Vault, and Application Insights settings.
9. Leave Container Registry as **None**.
10. Review and create the workspace.

Deployment (via **Review + Create**, then **Create**) takes several minutes. Once it completes, you return to Microsoft Sentinel to continue configuring notebooks.

### 6.5 Resources Automatically Associated With the Workspace

| Resource | Purpose |
|---|---|
| **Storage Account** | Stores notebook files, datasets, and related artifacts. Without it, a notebook could not be saved. |
| **Key Vault** | Securely stores secrets, passwords, API keys, and connection strings, so credentials never need to sit directly in notebook code. |
| **Application Insights** | Monitors notebook performance, errors, usage, and diagnostics to help administrators troubleshoot issues. |
| **Container Registry** | Stores custom container images for machine learning workloads. Not required for a basic Sentinel notebook setup, so it can stay **None**. |

### 6.6 What Is a Compute Instance

After opening the notebook, you create a **Compute Instance**: simply an **Azure Virtual Machine dedicated to running notebook code**. Without it, the notebook cannot execute anything.

```text
Notebook
(Needs CPU, RAM, Python)
        │
        ▼
Compute Instance (Azure VM)
```

### 6.7 SC 200 Exam Tips

> * Microsoft Sentinel notebooks require an **Azure Machine Learning Workspace**; Sentinel cannot run Python itself.
> * A **Compute Instance** is the Azure VM that runs notebook code; the **Kernel** is what actually executes the Python on that VM.
> * When the ML Workspace is created, it automatically provisions a Storage Account, Key Vault, and Application Insights; Container Registry can remain **None** for a basic Sentinel notebook setup.
> * Use the **Getting Started Guide for Microsoft Sentinel ML Notebooks** template to begin.
> * You must **authenticate** before querying Sentinel data from a notebook.
> * Initialization creates a **msticpyconfig.yaml** configuration file.
> * Confirm the **Python 3.10 - PyTorch and TensorFlow** kernel is selected before running code.
> * In hands on labs, do **not** run the **Multiple Microsoft Sentinel workspaces** code cell; it is expected to fail in a single workspace lab.

### 6.8 Quick Memorization

| Term | Meaning |
|---|---|
| Azure ML Workspace | Hosts the notebook's compute, storage, and environment |
| Notebook | The investigation document itself |
| Compute Instance | The Azure VM |
| Kernel | The engine on that VM that runs Python |
| Storage Account | Stores notebook files |
| Key Vault | Stores secrets and API keys |
| Application Insights | Monitors notebook performance |
| Authenticate | Grants the notebook access to Azure resources |
| msticpyconfig.yaml | Configuration file created during initialization; typically holds workspace and provider connection settings |

## 7. Exploring Notebook Code

### 7.1 Purpose

Notebook code retrieves, processes, enriches, analyzes, and visualizes security data using Python, KQL, and **msticpy**. Unlike a plain KQL query that only displays results inside Sentinel, notebook code can execute the query, store results in Python variables, manipulate the data, enrich it with threat intelligence, and generate visualizations.

### 7.2 Creating and Executing a KQL Query in a Notebook

The process:

1. Create a variable (for example **test_query**) and store a KQL query inside it as text.
2. Execute the query using **qry_prov.exec_query()**.
3. Store the returned results in a DataFrame (for example **test_df**).
4. Display the first rows using the DataFrame's **head()** function.

**Step 1: Store the query as a Python variable**

```python
test_query = """
SigninLogs
| where TimeGenerated > ago(7d)
| take 10
"""
```

`test_query` is just a string of text at this point; it contains the KQL query but has not run yet.

**Step 2: Execute the query**

```python
test_df = qry_prov.exec_query(test_query)
```

`exec_query()` tells the Query Provider: "execute this KQL query against Microsoft Sentinel."

### 7.3 What Is qry_prov (Query Provider)

Think of **qry_prov** as the **Query Provider**: the bridge between the notebook and Microsoft Sentinel.

```text
Notebook
        │
        ▼
Query Provider (qry_prov)
        │
        ▼
Log Analytics Workspace
        │
        ▼
Execute KQL
        │
        ▼
Return Results
```

### 7.4 Complete Code Example

```python
# Define our query
test_query = """
SigninLogs
| where TimeGenerated > ago(7d)
| take 10
"""

# Pass that query to our QueryProvider
test_df = qry_prov.exec_query(test_query)

# Check that we have some data
if isinstance(test_df, pd.DataFrame) and not test_df.empty:
    # .head() returns the first 5 rows of our results DataFrame
    display(test_df.head())

# If there is no data, load some sample data to use instead
else:
    md("You don't appear to have any SigninLogs, so we will load sample data for you to use.")
    if not Path("nbdemo/data/aad_logons.pkl").exists():
        Path("nbdemo/data/").mkdir(parents=True, exist_ok=True)
        urlretrieve(
            "https://github.com/Azure/Azure-Sentinel-Notebooks/blob/master/nbdemo/data/aad_logons.pkl?raw=true",
            "nbdemo/data/aad_logons.pkl"
        )
        urlretrieve(
            "https://raw.githubusercontent.com/Azure/Azure-Sentinel-Notebooks/master/nbdemo/data/queries.yaml",
            "nbdemo/data/queries.yaml"
        )
    qry_prov = QueryProvider(
        "LocalData",
        data_paths=["nbdemo/data/"],
        query_paths=["nbdemo/data/"]
    )
    logons_df = qry_prov.Azure.list_all_signins_geo()
    display(logons_df.head())
```

**What this code does, step by step:**

1. Defines a KQL query that retrieves 10 sign in events from the last 7 days.
2. Executes the query using the Query Provider.
3. Checks whether any data was returned.
4. If data exists, displays the first five rows.
5. If no `SigninLogs` data exists, it displays a message, downloads sample sign in data (`aad_logons.pkl`) and sample query definitions (`queries.yaml`), creates a **LocalData QueryProvider**, loads the sample data, and displays the first five rows of that sample dataset instead.

> **Exam tip:** the fallback logic matters conceptually even if you never memorize the exact code: notebooks can gracefully switch to a **LocalData** source when live Sentinel data is not available, which is useful for training labs and demos.

### 7.5 Threat Intelligence Enrichment Functions

The source material's exam tips reference a threat intelligence enrichment example that pairs with msticpy. Remember these three functions and how they chain together:

| Function | Role |
|---|---|
| **lookup_ioc()** | Queries a threat intelligence provider (the example uses **VirusTotal**) for a given indicator of compromise (IOC), such as an IP address or file hash |
| **result_to_df()** | Converts the threat intelligence response into a pandas DataFrame so it can be filtered, joined, or displayed like any other query result |
| **head()** | Displays the first rows of any DataFrame, whether it came from a KQL query or a threat intelligence lookup |

```text
Indicator of Compromise (IOC)
        │
        ▼
lookup_ioc()  →  Threat Intelligence Provider (e.g. VirusTotal)
        │
        ▼
result_to_df()
        │
        ▼
Pandas DataFrame  →  Visualization
```

### 7.6 SC 200 Exam Tips

> * **test_query** stores a KQL query as a Python string; it does nothing until executed.
> * **qry_prov.exec_query()** executes the KQL query against the Log Analytics workspace.
> * Results land in a **pandas DataFrame** (for example `test_df`).
> * **head()** shows the first **five rows** of a DataFrame by default.
> * **lookup_ioc()** checks an indicator of compromise against a threat intelligence provider; the module's example uses **VirusTotal**.
> * **result_to_df()** converts a threat intelligence response into a pandas DataFrame.
> * Visualizations are built from DataFrames, which is why converting results and enrichment data into DataFrames matters before charting.

### 7.7 Quick Memorization

| Term | Meaning |
|---|---|
| Query Provider (qry_prov) | Executes KQL queries against the workspace |
| exec_query() | Runs the KQL query |
| DataFrame (test_df) | Stores query results |
| head() | Shows the first 5 rows |
| lookup_ioc() | Checks an IOC against threat intelligence |
| result_to_df() | Converts threat intelligence results into a DataFrame |
| Visualization | Converts log or enrichment data into charts for faster analysis |

## 8. SC 200 Last Minute Revision

### 8.1 One Page Cheat Sheet

* Sentinel data lives in a **Log Analytics workspace**; external tools reach it through the **Log Analytics API**.
* A **notebook** is an interactive, cell by cell investigation document combining text, Python, KQL, and visualizations.
* Every notebook needs a **browser based interface** (where you work) plus a **kernel** (what executes the code).
* The kernel runs on a **Compute Instance**, which is an Azure Virtual Machine.
* Notebooks require an **Azure Machine Learning Workspace** because Sentinel itself cannot execute Python.
* **Kqlmagic** = run KQL from Python easily. **msticpy** = full acquire, enrich, analyze, visualize toolkit.
* **qry_prov.exec_query(query)** runs a KQL string and returns a **pandas DataFrame**.
* **lookup_ioc()** plus **result_to_df()** is the pattern for threat intelligence enrichment (for example, against VirusTotal).
* **msticpyconfig.yaml** is generated during initialization and holds connection and provider configuration.

### 8.2 Frequently Confused Concepts

| Concept A | Concept B | The Difference |
|---|---|---|
| Log Analytics workspace | Azure Machine Learning workspace | The first **stores** Sentinel's log data; the second **hosts the compute** that runs notebook code |
| Compute Instance | Kernel | The Compute Instance is the **Azure VM itself**; the Kernel is the **engine on that VM** that runs Python |
| Kqlmagic | msticpy | Kqlmagic only **runs** KQL queries; msticpy is a **broader toolkit** for acquiring, enriching, analyzing, and visualizing |
| qry_prov | exec_query() | `qry_prov` is the **Query Provider object**; `exec_query()` is the **method** you call on it to run a query |
| test_query | test_df | `test_query` holds the **KQL text**; `test_df` holds the **returned results** as a DataFrame |
| lookup_ioc() | result_to_df() | `lookup_ioc()` **queries** a threat intelligence provider; `result_to_df()` **converts** that response into a usable DataFrame |

### 8.3 Key KQL Syntax Seen in This Module

```kql
SigninLogs
| where TimeGenerated > ago(7d)
| take 10
```

```kql
SigninLogs
| where UserPrincipalName == "john.doe@contoso.com"
```

> Remember the basic KQL pattern: start with a **table name**, then filter and shape results using pipe (`|`) separated operators such as `where`, `take`, `project`, and `summarize`. `ago(7d)` means seven days before now.

### 8.6 Where Notebooks Fit Among Sentinel's Hunting Tools

Notebooks are one of several ways to hunt inside Microsoft Sentinel. For exam purposes, understand the general distinction: built in **hunting queries** and **bookmarks** in the Sentinel portal are best for quick, guided KQL based hunting inside the UI, while **notebooks** are best when an investigation needs custom Python logic, external data enrichment (such as threat intelligence lookups), advanced visualizations, or a reusable, shareable record of the entire investigation. Choose a notebook when the scenario emphasizes automation, enrichment, or heavier data analysis rather than a single quick query.

> **Final reminder before the exam:** if a scenario question mentions Python, Jupyter, enrichment with an external threat intelligence source, or building a reusable investigation workflow, think **notebooks with msticpy**. If it only mentions running a KQL query from an external script quickly, think **Kqlmagic** or the **Log Analytics API** directly.
